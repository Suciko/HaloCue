# 定向卡片讨论（card-assistance/1.0）

`messages` / `messages:enqueue` / `agent-runs/:id:redirect` 接受可选 `card_assistance` 对象；旧请求省略此字段时行为不变。数据写入既有消息与输入快照 JSON，无数据库结构迁移。旧记录读作无定向约束。

- kind: `character_card` 或 `world_card`。
- target_id: 当前作品的已保存卡片 ID，不使用名称猜目标。
- base_revision_id: 人物卡修订或世界观集合修订。发起与整理候选时均校验；旧资料不会被悄悄覆盖。
- allowed_fields: 非空字段白名单。人物只允许职责、声音、知情边界、红线与关系；世界观只允许定义、别名、参与人物及设定关联。
- 稳定身份、来源类型、来源引用、采用状态、导入元数据不允许模型变更。
- 已保存卡片的未保存表单通过 `card_assistance.draft` 传递，在对话输入区可展开查看；新建卡片仍通过可见消息传递。草稿只作讨论材料，不能视作已确认事实。候选只取模型返回的允许字段；其余字段来自基准正式修订。
- `knowledge:propose` 根据指定 assistant preview 前的用户消息恢复约束，重查基准。不能用请求中的另一个目标或模型返回名称换目标。
- `conversation-knowledge-proposal/1.2` 新增可选 `card_assistance`；字段差异、影响摘要与人工部分采纳继续使用原契约。
- 归档、跨作品、过期目标拒绝。新建未保存卡片仍走普通讨论，界面不声称存在稳定字段锁。

前端在当前标签页 sessionStorage 保留最近一次带入助手的卡片草稿。返回且基准一致时恢复；正式资料已有新修订时展示新版本，旧草稿只供查看，不自动合并。

返回编辑后，可以直接再次点击“带草稿去讨论”更新尚未发送的自动生成说明。只有文本仍与本次生成值完全一致时才会替换；手动修改过的或其他对话草稿不会被覆盖。

服务能力通过 `/capabilities` 的 `card_assistance/1.0` 声明。前端发现旧后端时禁用定向入口并提示重启，已有定向会话也不能静默降级为不受约束的普通消息。普通讨论和手动编辑仍可使用。

运行中转向在取消旧运行前验证新请求的卡片约束，并将其完整传给新运行；过期约束不能取消原运行，也不能降级成无定向约束的讨论。
