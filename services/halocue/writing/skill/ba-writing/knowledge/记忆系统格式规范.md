# 记忆系统格式规范（两级架构）

> **定位**：定义 BA 写作的记忆系统格式与生命周期。本文件是 skill 侧的**格式契约**，项目侧的实际记忆文件存放在项目目录的 `memory/` 下。
>
> **两级架构**：
> - **动态记忆**（项目 `memory/*.md`）：写作过程中各环节的实时反馈与状态，随写随记。
> - **永久记忆**（项目 `memory/永久记忆.md`）：从动态记忆晋升的高频条目，跨章节稳定生效。

---

## 一、文件结构（项目目录下）

```
<作品目录>/memory/
├── 伏笔总表.md          # 🌱🔄✅ 三区伏笔追踪（剧情状态）
├── 角色状态总表.md      # 角色当前位置/情绪/关系（剧情状态）
├── 时间线.md            # 故事时间线（剧情状态）
├── 写作反馈.md          # 作者对写作的反馈（方法论记忆，可晋升）
└── 永久记忆.md          # 高频晋升条目（跨章稳定生效）
```

**两类记忆区分：**
- **剧情状态记忆**（伏笔/角色状态/时间线）：记录"故事发展到哪了"，每章 memory-keeper 更新。
- **方法论记忆**（写作反馈/永久记忆）：记录"作者要我怎么写"，作者反馈时追加，高频晋升。

---

## 二、方法论记忆条目格式

每条记忆包含以下字段：

```markdown
### {序号}. {类型}：{一句话摘要}

- **环节:** {章纲|提示词|正文|去AI味}
- **类型:** {正面案例|反面案例|规则}
- **原文:** {作者反馈原文摘要，保留关键说法不转写}
- **结论:** {提炼为可操作指引，不写空话}
- **场景:** {什么情况下这条适用，不写"写作时"这种泛词}
- **来源:** {触发记录的 agent}
- **日期:** {YYYY-MM-DD}
- **use_count:** {引用次数}
- **last_used:** {YYYY-MM-DD}
```

---

## 三、条目生命周期

```
写入 写作反馈.md → 被 agent 引用（use_count++）→ use_count >= 4
→ 晋升到 永久记忆.md（保留全部字段 + [晋升 YYYY-MM-DD] 标记）
→ 后续持续引用 → 保留
→ 连续 3 次 sweep 未引用 → 标记待移除 → 作者确认后删除
```

### 3.1 晋升条件（写作反馈 → 永久记忆）

| 条件 | 说明 |
|------|------|
| use_count >= 4 | 已被不同环节引用 4 次以上 |
| 结论可复用 | 是通用规则而非一次性场景 |
| 无冲突 | 与已有永久记忆不矛盾 |

### 3.2 降级条件（永久记忆 → 移除）

| 条件 | 说明 |
|------|------|
| 连续 3 次 sweep 未更新 last_used | 3 个写作周期无引用 |
| 作者确认 | 移除前询问作者 |

### 3.3 使用追踪规则

- agent 引用某条记忆并应用到产出后，递增 `use_count` 并更新 `last_used`
- 同一环节多次引用同一条只计 1 次
- memory-keeper sweep 时检查 last_used，跨周期未更新则累加 skip 计数

---

## 四、与永久知识的关系

- **skill `knowledge/`**：BA 通用方法论（规则 spec / 反AI附录 / ACG译文语体判别 / 老师双模式）。**跨项目、不随写作变化**。
- **项目 `memory/永久记忆.md`**：本部小说积累的写作偏好。**只属于这部小说**。

> 当永久记忆里的某条规律被验证适用于**任何 BA 二创**（不只这部），才考虑反向贡献回 skill 的 spec——但这需要作者明确判断，不自动晋升。
