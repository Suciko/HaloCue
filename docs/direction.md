# 演出与镜头语言

这份文档回答一个问题：**怎么让生成出来的东西看起来像有人导过，而不是一堆立绘杵着。**

数据来自 131 个人手工程、18089 行对白的统计，加上视觉小说演出的通用共识。
每条都标了出处，凭经验的地方也说清楚了。

---

## 一、最重要的一件事：AA 会自己插停顿

搞清楚这个，节奏问题解决一半。134 组工程/存档配对实测：

| 这一行的状态 | 编译器自动插入 | 命中率 |
|---|---|---|
| 有气泡（emoticon） | `#wait;2500` | 4552/4643 = 98% |
| 没气泡，但有走位 / 进出场 / 动作 | `#wait;1500` | 1179/1331 = 89% |
| 都没有 | 不插 | — |

而且你手写的 `#wait` 是**覆盖**这个默认值，不是加在后面（119/119 验证）。

推论：

- **挂一个气泡 = 附赠 2.5 秒停顿。** 一段里挂五个气泡，等于强行插了 12 秒卡顿。
  这才是"气泡要克制"的真正原因，跟好不好看无关。
- 自动标注不生成普通对白 `#wait`。`#wait` 留给“这一节点没有文字，只需要停一拍”的
  人工节点，不用于普通对白。

## 二、镜头：背景不变，画面里的人要变

AA 里"切镜头"的机制很简单：**一行的立绘名单换了，上一行有、这一行没有的人
会被编译器自动隐藏**（`#N;hide`，1752/1756 验证）。所以换名单就是剪辑，
不需要进出场动画。

区分两个概念：

| | 手段 | 读起来像 |
|---|---|---|
| **切镜头** | 改 `characters` 数组成员 | 镜头切走了，人还在这个场景里 |
| **进出场** | `appear` = 登场/退场 | 人物走进/走出了这个房间 |

本工具默认采用“一次正常登场”规则：一场戏的**第一个立绘人物**直接就位
（`appear=0`，即使前面已有旁白也不淡入）；后续角色第一次进入画面而没有显式
`@enter` 时使用 `appear=3`；已经登场过的角色再次进镜使用 `appear=0`，不重复
播放渐入。明确 `@enter` 才使用作者指定的入场方式，明确 `@exit` 才播放退场/
渐去。场景结尾不自动添加退场信号，单纯镜头切换也不应被写成进出场。

`@bg` 或 `@place` 表示硬换场。换场后的第一镜会先清空上一地点的立绘名单，
避免上一场的桃井之类角色一直残留到河堤、宿舍等新地点。

搞混的话，一个人只是暂时不在画面里，观众会以为他离场了。

### 真实分布（131 个人手工程）

```
同屏 0 人（纯旁白）  23.4%
同屏 1 人            38.0%   ← 最常见
同屏 2 人            24.7%
同屏 3 人            12.1%
同屏 4 人             1.3%
同屏 5 人             0.6%   ← 几乎不用
```

**一屏塞五个人基本是错的。**默认是单人或双人，三人已经算群戏。

### 镜头长度

```
1 行  25.5%
2 行以内 42.9%
3 行以内 55.2%
4 行以内 63.7%
6 行以内 76.2%
中位数约 3 行，平均 6.1 行
总计 2963 次切镜头
```

作为对照：本工具早期版本生成的第二章是 **342 行只切 2 次**，
等于全程一个静止镜头。人手做的同一体量是 **262 行切 57 次**。差 35 倍。

### 呼吸式节奏

人手工程读出来的规律是**攒—切—再攒**：

```
桃井说    镜头[桃井]                单人起手
绿说      镜头[桃井、绿]             对话锁双人，一锁八行不动
柚子说    镜头[柚子]           ✂ 新面孔第一次开口，硬切单人让观众看清是谁
桃井说    镜头[桃井、柚子]
绿说      镜头[桃井、柚子、绿]        攒到三人
爱丽丝说  镜头[爱丽丝]          ✂ 又一个新面孔，又切回单人
凯伊说    镜头[桃井、爱丽丝、凯伊]
桃井说    镜头[桃井、凯伊]           爱丽丝下
绿说      镜头[绿、凯伊]            桃井下
桃井说    镜头[桃井]           ✂ 切回单人
```

不是简单的 LRU——纯"最近三个说话者"对不上这个序列。真正起作用的信号更像是
**对话簇的边界**：一组人稳定交谈时锁住镜头，话题转向另一组时硬切。

### 通用共识（来自视觉小说创作社区）

- **切 vs 摇**：直接硬切比平移更"刺"，适合争吵和沉重的沉默；带平移的切换更流畅，
  适合斗嘴和轻松来回。（[ingthing](https://ingthing.dev/behind-the-lens-1-vn-camerawork/)）
- **双人镜头 vs 特写**：情绪转折推特写让观众看清表情，回到并肩状态用双人镜头。
- **对立站位**：起冲突的两人放在画面两端，用空间表达分歧。（[VNDev Wiki](https://vndev.wiki/Scene_direction)）
- **别让画面长时间不动**：读者是在为你的作品花时间，静止太久就流失了。

## 三、各维度的用法与配额

| 维度 | 字段 | 配额建议 | 依据 |
|---|---|---|---|
| 表情 | `faceId` | 每句重新判断 | 语义变化就换，避免少数编号连续霸占 |
| 气泡 | `emoticon` | 十行最多 2–3 个 | 每个附赠 2.5 秒停顿 |
| 动作 | `action` | 台词明写了肢体动作才加 | 人手工程里很稀疏 |
| 立绘效果 | `shapeOverride` | 特写一场戏 1–2 次 | 稀少才有力 |
| 背景效果 | `bgEffect` | 一场戏 0–2 次 | 比表情重得多 |
| 背景抖动 | `#bgshake` | 一整章 2–3 次 | 只用于物理冲击 |
| 音效 | `sound` | 跟着可听见的物理事件走 | 可从紧邻语境推断脚步、递物、按钮等 |
| 过渡 | `transition` | 只在换背景那行 | 1000/1500/2000 三档占绝大多数 |
| 地点卡 | `placeText` | 一场戏开头一次 | 人手工程共 78 次 |

### 表情

`00`–`06` 是蔚蓝档案的通用七表情，几乎每个角色都有：

```
00 默认   01 平常   02 回应   03 微笑   04 困窘   05 认真   06 低落
```

`07` 以上是各角色自己的追加差分，语义因人而异，看素材库。

每次角色开口都重新判断表情。语气、态度或反应有变化就选语义最贴切的已登记
差分；只有同一句拆开的连续气口或情绪确实不变时才保持。语义正确优先于机械轮换。
已验证但没有语义标签的裸编号仍可人工使用，但不会交给模型猜。

### 表情符号

任意相邻两句不连续使用气泡，同一符号短时间不重复，“脸红”使用更长冷却：

- **沉默（dot/…）**：犹豫、思考、尴尬停顿、无语或不知道怎么回答。
- **悲伤（Sad）**：无语、心情差、失望、沮丧。
- **冷汗（Sweat）**：无语、尴尬、无奈、被弄得没办法。
- **音符（Music）**：活泼、轻快、兴致很高地说话。
- **灵光一闪（Bulb）**：只表示突然想到办法或恍然大悟，不能代替一般的活泼。

### 立绘效果（三种位标记，可以组合）

- **通讯** —— 通讯画面效果。
- **黑屏剪影** —— 只显示角色剪影。
- **特写** —— 镜头推近，表现人物与老师/摄像机的距离变近。

它们可以叠加，例如 `通讯+特写`、`黑屏剪影+特写`。

### 背景效果里最好用的一个

**集中线**（`BG_FocusLine`）：人手工程里 55 次，**跨 38 个不同背景**——
说明它跟场景无关，是纯演出手段。全部用在爆发性单句上，比如
「——你们两个都给我闭嘴！！」。它只允许画面中有一个立绘，并必须同时把该人物
设为特写；多人镜头中的集中线会被程序自动取消。集中线本身没有音效，不自动补音效。

其余按语义配：红滤镜=危机 / 烟尘=废墟战场 / 枪战=交火 / 雨雪雾=天气底色 /
爱心闪光=暧昧温暖 / 闪白闪电=瞬间冲击。

### 音效

除了文本明写的声音，也可从紧邻语境可靠推断可听见的动作：人物到达或走近配一次
脚步，递纸配纸张声，按按钮配按键声，跑出配奔跑声。连续动作只在开始处配一次。
情绪、背景效果和命令特效本身都不是音效，不能凭空附加声音。

## 四、常见错误

| 做法 | 后果 |
|---|---|
| 不看语义只机械轮换表情 | 立绘在抽搐 |
| 同一表情连续霸占多句 | 人物像没有反应 |
| 连续五行挂气泡 | 每行自动停 2.5 秒，整段变幻灯片 |
| 五个人从头站到尾 | 就是"很呆"的根源，且违背 99.4% 的真实用法 |
| 一段戏三次特写 | 特写不再是特写 |
| 心理描写配抖动 | 抖动是物理的 |
| 「她愣住了」配打字音效 | 音效跟着声音，不跟着情绪 |
| 把切镜头做成进出场 | 观众以为人离开了房间 |
| 到处加 wait | 默认值本来就有，加了反而乱 |
| 多人镜头挂集中线 | 漫画爆点失去明确主体；程序会取消 |

## 五、给 LLM 写提示词时要交代的

完整提示词在 `prompt.py`。设计要点：

1. **先讲清楚 AA 会自动做什么**（自动 wait），否则模型会重复劳动、拖垮节奏。
2. **给具体数字而不是形容词**。"克制使用"没用，"十行最多 2–3 个"才有用。
3. **给真实分布**。告诉它同屏 5 人只占 0.6%，比说"不要太多人"有效。
4. **示范里大部分行是空的**。模型天然倾向于每个字段都填满，要用例子压住。
5. **写反面例子**。正面例子教它做什么，反面例子教它别做什么。
6. **资源表按本章演员表裁剪**。每个角色只看得到自己真实拥有的表情编号。
7. **回来的标注再过一遍白名单**。模型再怎么被提示也可能编，程序兜底丢弃。
