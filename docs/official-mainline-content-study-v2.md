# 官方主线内容与演出因果研究 v2

本报告只读取 `05-官方演出语料库/records` 中的官方解析记录、官方中文文本和
`raw.script_kr`。没有读取 AA 工程、旧 AAP、模型结果或人工生成工程，也没有把
官方命令流输入任何盲测模型。本轮没有调用模型，只做离线内容研究。

## 研究样本

本轮补看了六段跨卷主线连续剧情。它们不是同一事件链的变体，而是不同叙事尺度和
不同空间组织方式：

| 主线 1-1-8 | `scenario_0:3756-4029` | 阿拜多斯会议、荒唐提案升级、便利屋与拉面店相遇 | 274 / 222 / 51 |

## 连续内容阅读记录

### 1. 主线 1-1-1：系统连接不是普通“开场对白”

在 `2460-2471`，画面连续清空并等待 1500-3000ms，先出现“连线密码核准”的
屏幕文字，再由旁白欢迎老师进入「希迪姆的箱子」。这段没有立绘对白，却完成了
“系统连接已经成功”的事实建立。这里的等待不是人物发呆，也不能编译成对白节点
的附加 Wait。

`2494-2542` 是未知人物的连续独白。多次 `#all;hide` 和 500-2000ms 等待把它
分成“承认失误 -> 请求老师 -> 解释选择和责任 -> 留下未完成请求”的心理段落。文本
没有说出角色身份，镜头也没有强行给一个立绘；匿名旁白和清镜共同保持了信息悬念。

`2544-2563` 才切入琳叫醒老师并说明当前情况。琳的 `01 -> 99 -> 03` 变化与
`greeting`、停顿对应的是“正式说明 -> 察觉对方混乱 -> 责任重大”，不是按每句
轮换编号。`2564-2567` 的 `d + wait + all;hide` 是“跟上去”的无对白过渡，
不是琳真实退场的证据。

`2583-2628` 是典型的多人追责会议：

- 优香先用 `em=反应`、随后 `em=?`、`hophop`、`m3 + 怒筋` 把抱怨升级为质问；
- 琳在 `2590` 用 `m5` 让原有画面中的人物发生横向让位，随后继续保持琳为信息轴；
- 琳宣布学生会长失踪后，`2605-2607` 才出现优香 `?! + shake`、千夏 `!`、莲华
  的单独反应，说明同一刺激可以在同一清镜边界后分配给不同承受者；
- `2625-2628` 的优香从问候到否认、冒火、`hophop + m3`，同时琳 `al`、优香
  `m3`、莲华 `dr`，表达的是“琳把话题拉回正事 -> 优香被点名反驳 -> 其他人离镜”，
  不是简单的三人同步换脸。

`2638-2654` 的通讯说明了“画外信息 -> 现场承受者”的镜头逻辑。桃香在通讯位说
明外围地区正在成为战场，琳先沉默，通话结束后才用 `hide -> m3 -> stiff + 怒筋`
表现压住火气。这里的 `stiff` 是听到坏消息后的身体反应，不应由“汇报”这个标签
自动生成，也不应在后端被认为重复而删除。

`2657-2660` 琳发现现场有人可以利用：`em=闪亮` 后直接把力量分配给在场学生，
这是“新决定”的承载。她没有把所有人拉回同一关系镜头，而是在随后重组小组。内容
因果先于镜头名单。

### 2. 主线 1-1-8：喜剧升级依靠反应接力和真实位置变化

`3767-3788` 的会议从“学校欠债”进入“锗手链发财”。茜香从认真汇报到发现传单、
坚持发财，官方使用 `m2 + !`、`hophop`、`em=闪亮`；听者绫音、星野和白子不是
每句都跟着换脸，而是在茜香的荒谬逻辑被揭穿时分别出现 `?`、`stiff`、`...`。

`3793` 是一个真正有内容的无对白拍：茜香保持 `face=01` 和 `em=反应`，等待
1500ms 后才问“大家怎么了吗”。停顿让观众先读到群体表情，再读茜香没有察觉的
反差。若把这段压成“对白 -> 下一句对白”，笑点的因果就消失。

`3832-3857` 白子提出抢银行后，先是单人计划说明，再用 `m1`、`dl` 和换装显现
把面罩拿出来。`3840-3845` 的 `m1 -> dl -> 新立绘 ar -> m3` 是物件/形象展示
的连续动作，不是普通表情变化；它必须让位于真实的镜内状态更新。

`3898-3906` 是“犹豫 -> 结论 -> 翻桌”的完整喜剧峰值：绫音先停顿，随后单人
`CLOSEUP + 怒筋`，下一条才是 `#all;hide + bgshake` 的翻桌声，之后切回其他人
的反应。重效果没有提前放在“最”字上，也没有让集中线持续覆盖余波。

`3920-3957` 拉面店段展示了另一种节奏：亚瑠、睦月、佳代子和遥香先后从门外
出现，穷困误会由店员承受，店员再把“没钱不是罪”转成安抚。`m1/m3/m4` 是人物
在同一关系组中换位和靠近；`d/dr` 与 `wait` 让离开的角色完成视觉收束。这个段落
不应该被压成“每个新 speaker 都在同一槽位替换”。

### 3. 主线 1-3-9：寻找、记忆和天气危机交替使用静默与硬切

`32204-32223` 先表达“什么都没找到”，梦使用 `em=세로선`、`stiff`、随后
`falldownR`，星野以 `em=한숨` 收住。这里官方明确区分了低落竖线、叹气和摔倒；
不能把 `세로선`、`한숨` 或 `스팀` 合并成一个 upset 标签。

`32229-32244` 从“浪费时间”转到“手册掉了”。星野通过 `m1` 进入新的承受位置，
梦先 `?! + shake` 找手册，再用两个无对白节点 `m3/greeting` 表现捡起和松气。动作
结果先落地，台词才解释“差点弄丢”。

`32262-32320` 是关系信息揭示：星野质问梦如何成为会长，梦回答“这是我自己的意愿”。
官方用 `all;hide`、1500-2500ms、`m3`、`em=...` 让话题从玩笑转到责任，再由
`em=闪亮` 展示学生会长手册。星野对手册的嫌弃没有立刻变成新特写，而是保持同一
关系镜头直到“那种事不会发生”后才产生情绪断裂。

`32349-32372` 先有 2000ms 风暴前空白，再由 `bgshake`、`?! + shake`、奔跑动作
把沙尘暴变成空间危机。这里的 `bgshake` 是真实天气冲击，不能用人物 `shake` 代替；
同样，人物 `hophop` 只表达急促行动，不代表已经完成走位。

`32489-32512` 星野递出入会申请，梦先询问、再 `closeup + ?! + shake`，随后连续
`closeup` 把惊喜、拥抱和拍照决定留在同一情绪峰值中。峰值之后，`32515-32529`
才重建到拍照的关系构图；这是“单人峰值 -> 关系镜头”的硬切回收。

`32642-32711` 的储物柜发现是典型“静默发现 -> 物件操作 -> 关系揭示”：白子先
无对白移动到柜子，野乃美阻止，开锁工具露出后才切回其他人的 `?! + shake`，打开
柜子后发现星野旧装备，再让星野以 `em=!` 显现。这里的 `a/al/ar` 只是镜头显现
证据；真正的入场/退场需要文本和连续画面额外证明。

### 4. 主线 2-1-5：操作反馈必须形成“输入 -> 结果 -> 反应”

`105139-105165` 的目标是让爱丽丝伪装成游戏开发部成员。绿先担心，爱丽丝按字面
解释“没问题”，绿立即用 `?! + shake`、`m3`、`hophop` 纠正。这里动作来自对话
语义和社交压力，不是因为句尾问号本身。

`105176-105194` 爱丽丝四处张望、发现游戏资料，先用两个 `m2/m1` 实际移动，再
由绿以 `?!` 反应。对象被看见后，才进入“要不要玩游戏”的决定；`em=闪亮 + hophop`
是绿接受机会的情绪峰值。

`105197-105217` 是操作链的完整范例：准备完成 -> 爱丽丝单人 `closeup` 开始游戏
-> 屏幕文字说明 -> 按 B -> 新手教学 -> 爆炸音和 `bgshake`。这里的屏幕文字和
无对白 `wait` 是游戏界面反馈，不能被后端强行改成角色 Wait，也不能因为没有对白
就删除。

`105230-105291` 反复失败时，爱丽丝的 `shake + 难过`、短暂 `...`、重新启动、
再次 `closeup + !`、两小时/一小时旁白和最后的 `stiff` 构成逐阶段升级。连续相同
操作配不同等待（1500、2500 等）不是重复；时间跳跃本身就是叙事信息。

`105307-105326` 游戏评价从三人闪亮提问转成爱丽丝无法回答，随后 `...`、搜索中、
情绪无法翻译，最后用 `closeup` 和 `（滑落）` 让哭泣结果落地。不是每句都需要
emo/act，但当“无法说明 -> 眼泪”是可见的新状态时，必须有独立载体。

### 5. 主线 2-2-5：游戏蒙太奇可以由人手补，但普通对话仍有清晰因果

`46257-46295` 先用多个 200ms/1000ms 无对白操作节点表现爱丽丝在校园中进行
“勇者修行”，再让路人以 `stiff` 反应。`46298-46319` 通过 `zmc` 视角移动、
清镜、三人重新显现和讲解，把“发现工程师部”从空间事件变成新镜头，而不是把三名
角色塞进旧构图。

`46374-46389` 宁瑠突然抓走爱丽丝，官方用单人 `closeup`、`?!/stiff` 和随后
`all;hide` 处理喜剧冲击；`46431-46441` 则连续使用 200/700/1200/1500ms 的
特写节拍演示游戏对战。不同等待时长是输入节奏，不应被“相同 closeup”去重。

`46544-46587` 朱音在游戏过程中出现，先用画外对白打断，再以 `closeup + ?!` 让
宁瑠承受“被发现”的结果。这里没有把朱音用 enter 伪装成镜头切换；她是新的拍摄
关系和结果承受者。

`46648-46666` 的校园日常蒙太奇几乎全是无对白人物表情、动作、`wait` 和显隐变化。
它不能直接作为“每句对白都应有静默拍”的模板，但说明无对白节点可以承载一组连续的
日常观察、欢迎和被关注反应。

### 6. 主线 3-2-4：场景功能改变时，镜头和服装状态一起重建

`110658-110668` 先以雨天早晨的四人群像建立空间，再让梓在画外梦话；听者花子用
爱心回应，其他人保持在场。`110675-110686` 雷声出现后，花子 `!`、小春和日步美
同步 `?! + shake`，再由日步美 `hophop + m2` 触发抢衣服行动。同步反应有共同
刺激，因此可以在同一无对白拍合并；动作结果后才切离人物。

`110691-110713` 梓在床上连续 `m2 -> m4 -> m3 -> m2 -> m1 -> dl`，这些是
逐步醒来、观察、起身和离镜的身体/位置阶段，不是重复指令。随后 `zmc` 和四人
泳装显现重建成泳装派对构图，服装变化是场景状态变化，不应被普通 `camera_hold`
继承覆盖。

`110730-110754` 从“没有替换衣服”进入小春对内衣的强烈抗议，官方先给听者 `?!`、
再用单人 `closeup + !` 收束小春的爆点。`110761-110776` 停电、洗衣机卡住、
回溯四十分钟前和泳装派对的因果由旁白、黑场和 `zmc` 连接；这不是一场戏里连续
加表情可以替代的事件链。

`110789-110830` 关系话题从玩笑转为“加入补课部后变得像家一样”，梓在
`closeup + 闪亮` 承受认可，日步美随后拥抱。镜头没有因为说话人变化机械切换，而是
在关系意义改变时才把焦点交给承受者。

`110857-110905` 又从闲聊回到“梓熬夜巡逻、埋地雷”的严肃信息。先是 `...`、
`?`、多人无对白停顿，之后梓单人说明；电力恢复和雨停才用群体反应收束。这里的
沉默不是空白，而是大家在听到“我可能背叛你们”后无法马上回答。

## 主线 3-4-18 对照：严肃回忆的节奏不能套日常群像

在 `124860-125041`，过去的阿里乌斯成员多次以旁白、`#all;hide`、短促音效和
等待承受虐待与绝望。`124991-125012` 美香提出“和解”，先切单人 `closeup + 闪亮`，
沙织随后用 `closeup + ...` 和 2500ms 停顿回答“荒唐无稽”。

`125078-125129` 的和解提案逐步从积极闪亮转到不理解、悔恨和否认；`125142-125150`
用 700/500/300/1000/1500ms 连续留白把心理防线压到最后。`125175-125195` 的
黑屏剪影和迟到的单人显现，表达的是无法直接面对幸福，不是普通“特写资源”。

这段证明：主线模式不能只写“单人/双人推进信息”，还要允许画外旁白、黑屏、长留白、
切回旧关系和心理阶段结束后的新构图。

## 跨主线稳定的“内容因果 -> 演出选择”

以下规律在上述多个不同主线样本中反复出现，足以进入通用导演提示词，但仍不应变成
固定配方：

1. **先识别刺激和承受者。** 信息、物件、声音、失误、回忆或突发天气先发生；
   镜头可以拍承受者而不是说话者，也可以先拍画外空间。
2. **先完成结果，再解释结果。** 发现、捡起、按键、爆炸、开门、停电、衣服变湿等
   事件通常由无对白动作/音效/等待落地，下一句才解释。
3. **静默节点承载需要在下一句前独立读到的反应或新信息。** 典型是发现、观察、
   犹豫、听到坏消息后的无言、操作反馈、时间跳跃、群体同步反应和情绪余波。反应
   可以由人物关系和上下文强烈暗示，不要求原文先写成括号动作；但它不能增加新的
   剧情事实。没有独立可读价值时，不要为了“像官方”生成 Wait。
4. **反应是阶段链，不是标签。** 同一刺激可经历注意 -> 疑惑 -> 确认 -> 释然，
   或正常 -> 违和 -> 尴尬 -> 爆点 -> 余波；每一阶段可由 face、emo、act、镜头或
   静默承载，选择最自然的一个或少数组合。
5. **动作类型取决于身体事实。** `stiff` 是压住的僵硬/轻颤，`shake` 是失控/强烈
   慌乱，`jump` 是一次跃升，`hophop` 是持续外放；`bgshake` 是物理冲击。不能
   把这些资源合并为“强烈情绪”。
6. **镜头表达关系和信息，不表达 speaker 轮次。** 同一互动轴可保持构图；承受者、
   关系轴、揭示或峰值改变时，允许硬切到单人，再切回关系镜头。硬切后新构图可保留
   一个锚点，但不能把连续镜内换位伪装成静态换人。
7. **显现和入场是两件事。** `a/al/ar`、`#all;hide` 后重新建立构图，只能证明
   观众在这一镜看到角色；只有正文或连续画面证明走入/离开物理空间时，才是 enter/exit。
8. **等待时长是内容信号。** 100-500ms 常承接输入或切换，800-1500ms 常承接
   观察/反应，2000ms 以上常承接情绪留白、黑场或时间跳跃；这是解释线索，不是
   后端配额或硬阈值。连续相同动作使用不同等待时长时，不得去重。
9. **角色和状态要跨节点持续。** move、显现、隐藏、服装变化、物件操作和镜头重建
   都要更新物理存在、当前可见名单、槽位和表情阶段；否则下一句会出现瞬移或错误承接。

## 可以进入提示词的内容原则

建议只加入一个权威段落，名称为 `CONTENT_CAUSAL_DIRECTING`，放在导演原则和输出
协议之间：

```text
先读“上文刺激 -> 承受者 -> 结果/阶段 -> 下一拍需要让观众看到什么”。
镜头不由 speaker 轮次决定；可拍说话者、听者、画外空间或物件结果。
当观众需要在下一句前独立读到一个反应或新信息时，才创建无对白 beat；它可以表达发现、
操作结果、听者停顿、群体反应、时间跳跃或情绪余波。允许根据关系因果主动补原文未逐字写出
的停顿、视线或轻微身体反应，但不能补新的剧情事实。台词节点不要额外 Wait。
先选择最自然的可见载体（face / emo / act / fx / move / camera / wait），不要为填密度
堆资源；但也不能因“克制”隐藏正文已经证明的阶段变化。把同一刺激按阶段承接，直到结果被
回应或转移，再结束状态。连续等待、动作、显现和镜头变化只在字段和语义都可证明相同时去重。
```

这段原则能覆盖六段主线共同的因果，而不把“某句话必须使用某个表情+动作”写成模板。

## 面对没有官方节奏的新文本

最终系统面对的是未知文本，所以生成时不应询问“官方在类似位置放了几个 Wait”，而应
只做三层判断：

1. **剧情事实层**：输入明确发生了什么。物件、进出场、操作结果、时间跳跃和关系事实
   只能来自这一层，AI 不得补写。
2. **强因果演出层**：正文没有逐字写动作，但人物受到刺激后，观众自然需要看见的停顿、
   视线、轻微身体反应、听者反打或峰值后的余波。AI 可以主动创作这一层，因为它只把
   已有潜台词变得可见，没有改写剧情。
3. **纯装饰层**：既不改变可读信息，也不是关系因果所需的气泡、动作、切镜或等待。
   不禁止偶尔使用，但不能按官方密度、事件类型或固定配额补齐。

因此，官方研究的产物是“何时应该让反应落地、什么载体适合什么身体状态、怎样维持连续性”，
不是一张可复制的节点表。未知文本可以比官方样本更克制，也可以在因果密集处更积极；节奏由
当前场景的刺激密度、关系压力和信息交接决定。

## 不应升级为硬限制的内容

- 特写次数、气泡次数、静默节点比例和等待时长没有统一配额。
- `?`、`!`、省略号不能直接映射为同名 emo 或某个 act。
- 主线不总是单人/双人；多人群像、旁白、屏幕文字、黑屏、视频和环境效果都可能是
  更正确的承载。
- `#all;hide`、`d/dl/dr`、`a/al/ar` 不能单独证明人物叙事退场或真实入场。
- 同一表情、动作、closeup 或 wait 不能只因连续出现就删除；必须比较刺激、阶段、
  目标和持续时间。
- “发现者一定单人”“说话人一定同框”“有动作就必须有音效”都不是通用规则。

## 对当前 0.9x 提示词的直接检查结论

现有 `prompt.py` 已经覆盖了很多协议和资源定义，但主线研究提示出三个需要保持的
方向：

1. `scene_function` 不应只在 G1 生成事件标签；G2 必须在每个目标前读取上一有效
   `last_performance_node`，并把对象操作、画外刺激和结果承接作为同一条因果链。
2. 不能把“主线策略”压缩成“单人/双人 + 重效果稀少”。主线 1-1-1、2-1-5、3-2-4
   都证明主线可以有屏幕文字、操作蒙太奇、群像、旁白、天气、长等待和静默反馈。
3. 输出检查应只保留硬性协议检查，以及一条内容链检查：
   `stimulus -> owner -> carrier -> next-state`。不要再增加固定 face/emo/act 密度
   或每个事件都必须有 silent beat 的检查项。

## 研究边界

这些结论来自官方解析记录和文本内容，能够说明命令与语义的对应关系，但不能替代
逐帧视频观察。仍需用视频或最新人工标注确认：黑屏/淡入淡出的实际时长、`zmc` 的
真实镜头运动、`#all;hide` 是否合并为一个视觉拍、以及无对白蒙太奇中人物是否真的
发生镜内位移。它们可作为事后对照和提示词研究资料，不能作为盲测生成输入。
