# HaloCue 1.0 首次创作教学与可选引导方案

- kind: proposal
- scope: HaloCue 1.0；client、writing、production
- status: implementing；优先首次教学，日常陪跑需主动开启；维护者 2026-10-20 指定聚光遮罩和小指针，当前实现及实操见[聚光教学交接](handoffs/2026-10-20-1.0-first-use-spotlight.md)；G2–G4 未实现
- source: 维护者 2026-10-19 对话；现有实现与约束见第 9 节
- observed_at: 2026-10-19
- owner: 1.0 client/backend；G1 [Issue 87](https://github.com/Suciko/HaloCue/issues/87)，分支 `codex/1.0-guided-authoring-g1-20261019`

HC 的当前优先级是帮助首次使用的作者学会创作。维护者明确选择“直接带着做自己的作品”：教学随真实操作推进，首次建立作品、进入正文并保存第一段后结束；学会后不再默认显示引导。全流程陪跑仅作为主动开启的可选能力，不能替代首次教学。

同日接续修正：聚光跟随面板内部缩放；阅读模式下先指向真实编辑入口，再接回手写/保存。复现记录、Web Control 实操及最终 11 项首次教学测试见[后续交接](handoffs/2026-10-20-1.0-first-use-followup.md)。

完整 AI 与异常接续已补验：人物缺项/选择、准备等待、失败重试、失效候选、教学作品回收与恢复；补齐空白场景的对话起草工具，仍由明确应用建立正式正文。实现、32 项相关浏览器及 77 项后端检查、Web Control 实操和待执行的真人首次试用见[最新 AI/恢复交接](handoffs/2026-10-20-1.0-first-use-ai-recovery.md)。

2026-10-22 显示验收纠正：主验收采用 1920×1080 内容视口、16:9、浏览器 100% 缩放，另查 1600×900；小窗口作为适配补测。新增浅/深色 1920×1080 全流程，明确检查视口、浏览器 zoom/scale 和 CSS zoom。5 组定向测试与原尺寸 Web Control 证据见[正常比例交接](handoffs/2026-10-22-1.0-first-use-normal-scale.md)，本轮没有改产品布局。

初版把重点放在持续陪跑，维护者随后指出主要需要首次使用教学。以下是最新约束，优先于后文早期全流程设想：

- 真实空白工作区提供可跳过的教学入口；有作品或既有导览记录的作者不自动进入教学。
- 直接使用作者自己的作品，不自动创建样例、不要求先完成练习工程。
- 每次只解释当前要做的一件事，定位真实控件；完成检测读取场景、候选及正式正文修订，不用点击“下一步”伪装学会。
- 支持手写，无模型也能完成。AI 路线沿用既有构思回复、下一步入口与原位候选审查，采纳必须由作者明确操作。
- 完成或跳过按浏览器学习记录退出，之后建立新作品也不重播；暂停需从帮助/设置主动继续，重看可手动触发。当前记录不跨设备同步。
- 首版只证明“自己的作品到第一段保存”的教学闭环，不宣称章检查、冻结、AA 制作教学已经完成。后续教学覆盖范围依据首次体验反馈再决定，G2–G4 仍是待审设想。
- 原 G1 陪跑保留为可选入口，默认自由创作，普通作者不显示模式工具栏。

实现与测试收据见[首次教学交接](handoffs/2026-10-19-1.0-first-use-task.md)。原 [G1 交接](handoffs/2026-10-19-1.0-guided-authoring-g1.md) 保留为纠正前的历史实现记录。

## 1. 已认可方向与设计边界

维护者指出 1.0 功能复杂，需要强引导，并提出由 AI 判断阶段推进时机，主动提供半强引导。随后明确重点是首次使用软件、直接做自己的作品。以下全流程路线与控件设想仍供后续审阅，实际交付以第 0 节及最新交接为准。

- 新手可选择“带我完成”，系统主动提示下一项具体任务；有经验的作者可以自由创作、暂缓或关闭引导。
- AI 判断创作是否足以尝试下一步；保存、采纳、检查、冻结和编译是否成功，以服务端实际状态为准。
- 自动展示引导、展开相关区域与定位入口，沿用既有命令与导航；正式修改仍沿用候选审查和人工决定。
- 直接发送“帮我写开场”等明确请求时，Agent 按现有对话工具链执行，不要求作者再按一次生成按钮。
- “可以继续”与“本阶段完成”分别表达。作者可以先试写再完善构思，也可以写完一章后继续写，不必先完成全作资料表或所有章的检查。

现有产品方向、正式修订、冻结发布及 AA 安装规则继续生效。引导状态不成为正文、资料、审查或制作结果的另一套事实来源。

## 2. 当前基础与缺口

以下依据当前源码基线 `f215b05ae1ae146d9d2c20b60566c590e1b074bb`；本轮未运行产品或真实模型。

| 已有基础 | 本轮核对位置 | 对新方案的意义 |
| --- | --- | --- |
| 首次界面导览，有聚焦提示、下一步和跳过 | `services/halocue/writing/web/app.js` 的 `onboardingSteps`、`startOnboardingTour` | 可复用定位表现；现有内容主要说明界面区域，不等于任务完成检测 |
| Agent 可返回 `next_step`，值为 organize/review/structure/draft 或 null | `discussion_response.py`、`discussion-next-step-1.0.schema.json` | 已有一个小型下一步入口，不需要从零另建聊天助手 |
| 只有最新回复显示入口，并核对候选、人物准备、场景和当前运行 | `app.js` 的 `conversationGuidanceMarkup` | 保留单一入口和实际状态复核；需扩展到正文、定稿和制作 |
| 构思线程与场景对话可建立有范围校验的来源关联 | `discussion_continuation.py` | 跳到正文后继续使用之前的要求；保持来源可返回 |
| 模型、规则、人物资料、上下文有场景 readiness | `scene_readiness.py` | 能说明具体缺项；不能把 AI 不可用扩大成手写也不可用 |
| 章检查与冻结版本关联，AA 有素材、逐卡审查、编译门 | `writing/docs/authoring-workspace.md`、`production/ui/index.html` | 新引导消费既有状态与操作，不另造检查通过或编译成功标记 |

缺口主要是跨阶段统一的目标与状态投影、自然停顿处的主动接力、引导暂停及恢复，以及跨写作/制作的上下文承接。现有 `workflow_state` 主要是场景、已写场景和待处理候选数量，尚不足以表示整条路线是否就绪。

## 3. 从作者目标选择路线

首次开始时展示“从想法开始”“改编已有原文”“制作现成剧本”“继续上次作品”。已有内容与明确要求能确定路线时直接沿用，不重复提问；起步选择可以修改。

| 路线 | 主要引导 | 不能额外强制的步骤 |
| --- | --- | --- |
| 从想法开始 | 构思 → 可执行的写作范围 → 试写/手写 → 修改采纳 → 检查定稿 → AA 制作 | 为短场景先填写完整世界观和长篇总纲 |
| 改编已有原文 | 保存原文 → 确认改编计划 → 分段生成/审查 → 采纳 → 后续写作与制作 | 丢弃来源、重复要求从空白构思；首版仍走现有改编工作台 |
| 制作现成剧本 | 导入并审查 → 处理实际交付前置条件 → 素材对应 → 演出审阅 → 编译 | 无关的创意讨论；也不能绕过导入与发布边界 |
| 继续作品 | 恢复上次目标和位置，按当前版本计算下一步 | 重新介绍已掌握的操作，或默认继续已删除/过期的目标 |

长篇以“本章/本场/所选范围”为推进单位。完成局部写作可以推荐继续下一章或检查本章，不宣称整部作品完成。篇幅和题材分别处理；“先试写”不把整部作品自动定为短篇。

## 4. 引导强度与自动操作

### 4.1 三种使用方式

| 使用方式 | 默认表现 | 自动程度 |
| --- | --- | --- |
| 首次创作教学 | 空白工作区首次提供，可跳过；使用自己的作品，完成后退出 | 真实操作完成后更新当前教学；定位或跨页由作者点击 |
| 可选创作陪跑 | 作者从设置主动开启，解释当前下一步，可暂停或关闭 | 自动更新建议；跨页面由作者点击进入 |
| 自由创作 | 日常默认，不显示教学或模式工具栏 | 已有回复小按钮、真实错误和原有门禁照常显示 |

“带我完成”默认只自动展示和就近展开。跨写作/制作等页面的自动切换由作者另行开启“完成后自动带到下一步”，默认关闭；它仅授权导航，不授权生成、采纳、冻结或安装。任一模式可暂停，暂停后仍能正常使用 HC。

### 4.2 一条提示必须能落到操作

默认呈现为一句判断、一个主操作和一个次要退路。例如：

> 人物和这场戏的看点已明确，可以先试写开场看看效果。
>
> **试写开场**　继续讨论

主操作说明实际动作：打开写作、生成候选、审查候选或检查本章，不使用含义不明的“继续”。提示位于当前回复、正文审查位置或制作当前步骤附近。同一目标只保留一个主引导；不在对话、顶栏和侧栏重复铺设下一步卡片。

需要解释时展开“为什么建议这一步”；首次操作教学使用短说明与目标高亮，允许 Escape/跳过。不做全屏常驻教程，也不在每次打开时重播。减少动画、键盘操作与明暗主题均保留等价信息。

### 4.3 自动行为的范围

| 行为 | 规则 |
| --- | --- |
| 计算可执行动作、更新提示、展示下一项任务 | 自动，读取当前实际状态 |
| 在当前任务中展开工具、定位目标或第一处改动 | 仅在输入结束且目标仍有效时；不覆盖当前操作 |
| 跨页面导航 | 默认需点击；主动开启自动带路后，在无草稿、无输入/拖拽/弹窗且作用对象未变时可自动导航 |
| 生成正文或运行需要模型的检查 | 沿用作者当前明确请求，或点击含义明确的动作；开启带路本身不授权连续付费生成 |
| 采纳正文/设定、确认检查变化、冻结发布、安装 AA | 沿用现有明确决定；自动导航选项不能代替这些决定 |
| 修复问题 | 可自动定位和说明；涉及正式内容或制作草稿修改时走原命令、审查及撤销规则 |

输入法组合、选区编辑、未保存草稿、资源挑选、已有弹窗、拖拽或后台任务运行期间，只更新非打断状态，不滚动、不抢焦点、不切页。条件恢复后重新验证建议，不补执行排队的旧导航。

## 5. 短篇首条路线的触发条件

| 阶段与触发点 | 实际状态依据 | 引导与结果 |
| --- | --- | --- |
| 构思回复完成 | AI 认为人物/场面/看点足以试写；服务验证写作范围与前置条件 | 推荐试写，缺少决定下一步的关键信息时只问必要问题；不按聊天轮数判定完成 |
| 尚无可写场景 | 现有范围/结构状态与实际可用命令 | 引导建立最小写作范围；结构候选存在时直接定位审查；不预设已有场景或已确认全作方向 |
| 正文候选生成完成 | 当前目标候选、基准版本与实际改动位置 | 自动展示原位审查并定位第一处改动；逐项采用、退回或继续修改 |
| 正文采用或手写保存成功 | 已落盘的正式修订、所选范围与作者目标 | 可继续本段；只有作者表示收尾、已选“完成本章”任务等可靠意图时，才建议检查；保存本身不等于写完 |
| 本章检查结束 | 现有检查结果、对应正文/资料版本、阻塞项与待决定变化 | 有问题先定位可处理项；结果有效且目标准备交付时推荐确认定稿；结果过期则建议重查 |
| 作者确认冻结成功 | 实际不可变 ScriptRelease 及范围 | 提示进入 AA 制作，沿用冻结内容；不把聊天中“可以了”擅自当冻结指令 |
| AA 任务建立/素材选择完成 | 实际 production run、映射、缺项和素材请求 | 显示已对应与需要作者处理的项目；自动预填不等于已审，保持原有映射选择与冲突处理 |
| 逐卡审阅推进 | 真实卡片审查状态、素材/语义门禁 | 可定位下一张未审卡，或当前阻塞；不能自动标记已审 |
| 编译成功或失败 | 实际 build/job 状态与当前输入版本 | 成功后展示产物和安装预检入口；失败则定位具体问题；不宣称已安装或已验证 AA 原生播放 |

同一目标的选择优先级为：作者最新明确任务 → 该动作的真实阻塞/失败恢复 → 当前待决定结果 → 下一项推进建议。其他章节的候选不能无条件阻断当前手写或跳转。

## 6. 判断与状态的技术候选

### 6.1 系统准备动作，AI 在范围内建议

服务端先按实际目标投影可执行动作及前置条件；AI 只从该范围提出建议并附一句理由，允许不建议。UI 执行前再验证对象与版本。AI 不自行发明动作、场景 ID、按钮命令、检查通过状态或完成进度。

先复用 `next_step` 的既有结构和验证，实施时按切片补充版本化的引导合同，覆盖目标范围、来源版本、可执行动作、阻塞原因和解释。具体字段与 endpoint 在对应实施 Issue 中确定；本文不新增或宣称已有 API。

### 6.2 三类信息分别保存

- **正式进度**：直接读取正文修订、候选决定、有效检查、发布、制作与编译结果，不另存可手工勾选的“已完成”副本。
- **AI 推进建议**：带来源线程/运行、作用对象和输入版本。正文、资料或目标改变后重新验证；依赖变化即失效，不因缓存而保留旧结论。
- **个人引导偏好**：模式、暂停状态、已看过的操作说明，以及按作品/范围记录的“暂不做这一步”。它们不进入正文历史，也不修改冻结内容。提示身份不依赖最新回复 ID，避免每轮聊天重复出现。

“继续讨论”使同一范围的该推进建议休眠；作者明确要求进入下一步、切换目标，或相关成果发生实质变化后才重新考虑。刷新、重启和重复轮询不解除休眠；缺乏足以推进的证据时不强行补一条建议。

跨页恢复沿用各页面既有的草稿机制，分别保护正文未保存输入、对话输入、选区/光标与尚未提交的素材选择。没有可靠保存/恢复路径的编辑状态禁止自动离页；手动离页继续使用现有保存、留在原处或丢弃的选择。只有目标存在且来源版本一致时才恢复原选区；版本已变时保留草稿并明确提示冲突，不把旧偏移套到新正文。目标被删除时回到仍有效的上级位置并说明原因，由作者重新选目标。AA 恢复绑定原制作任务和草稿版本，不能把旧卡片的已审状态套到新草稿上。

### 6.3 成本与失败恢复

利用正常 Agent 回复提供创作推进判断；保存、采纳、检查和编译事件触发本地状态投影，不在每次输入、点击或轮询时额外调用模型。没有新 AI 回复时，仅给有事实依据的就绪动作，不能补造创作判断。

模型断网、取消或超时时，现有人工导航、手写、保存及制作入口继续可用；恢复入口说明重试对象。建议与任务都绑定当前作品、范围和版本，迟到结果不能切换到另一个作品或覆盖新草稿。预填请求不覆盖已有输入，不伪造已发送状态。

写作页面与 AA 页面共用目标引用，通过现有交付链关联冻结版本和制作任务。建议持有必要标识，不复制工程内容，也不另建一套制作状态。跨服务新增投影或持久字段时先定义兼容合同和迁移，再实现消费者。

| G2 正文到定稿 | 作者准备收尾 → 有效章检查 → 处理问题/变化 → 明确确认冻结；编辑后旧结果失效 | 复用现有 chapter review 与发布门；保存不被当作完成，检查不被推荐动作自动批准 |
| G3 定稿到 AA 编译 | 精确冻结版本 → 素材待办 → 下一张未审卡 → 检查/编译 → 成功产物或失败修复 | writing/production 共用目标投影；逐卡确认、编译和安装原有边界不变 |
| G4 长篇与改编 | 局部完成后继续下一章；原文改编工作台无重复起步；中途切换路线仍能继续 | 在 G1–G3 机制上接入现有范围和导入结果，保留原文来源与跨章状态 |

G0 是当前第一项教学交付，G1 首版已实现但降为可选。后续完整路线必须另行验证，不能把第一段保存或 G1 完成称为“想法到 AA 编译”全流程已交付。当前纠正在同一 Issue 87 / PR 88 内继续；后续切片各自建立 Issue。既有 PR 86 是依赖基线，不承载本轮引导实现。

现有单体 `app.js` 只接入呈现和事件，判断逻辑优先放入可独立验证的模块，复用服务状态与导航命令。只调整引导需要的相关代码，不借此重做整个 1.0 UI 或 1.1 编辑器。

## 8. 验收方式

首作任务使用独立合成工程：一句想法 → 试写与部分采纳 → 手动修改 → 检查并处理问题 → 明确冻结 → AA 素材确认 → 逐卡审阅 → 编译。记录是否需要旁人指路、在哪停住、误点/回退、从建议到动作的步骤，以及误判或重复提醒次数。邀请首次接触 HC 的作者走一遍，再调整文案和强度；模型质量与用户理解必须单独验证，模拟 Provider 只能证明状态和操作链路。

实施时用有意义的状态与交互测试覆盖：

1. AI 说“完成”但系统未采纳/未保存，仍显示真实状态；AI 不建议时没有强行下一步。
2. 各路线、当前作用范围与不同章的候选分别处理；手写不被模型配置阻断。
3. 直接对话请求能执行既有工具；导航不偷偷生成，自动带路不批准正式修改。
4. “继续讨论”、暂停、关闭、刷新和重启之后不重复催同一任务。
5. 输入法、未保存输入、当前选区和弹窗不被引导抢走；跨页返回保留各自草稿与位置；版本变化/目标删除明确降级，旧审查不转移到新制作草稿；延迟结果不跨作品生效。
6. 正文/资料改变后建议和检查结果正确失效；原位采纳、部分采纳、撤销与保存结果一致。
7. 冻结和制作目标对应准确版本；未审卡、缺素材、失败编译均有可执行恢复入口。
8. 断网或无模型时普通操作仍可用；实际工具与任务结果可追溯。
9. 1600×900、1280×720，明暗主题、键盘、减少动画；提示不遮住操作点，不新增横向溢出。

纯方案阶段检查路径、引用、状态与规则一致性，不运行产品全量测试，不把静态阅读描述成实机或模型验收。
