# Architecture decisions

ADRs record decisions that affect more than one module, release, or contributor.
Use four-digit sequential names such as `0001-canonical-project-model.md`.

Product intent lives in `docs/product-direction-1.x.md`; ADRs should record the
architecture, ownership, contract, or governance decision that makes that
intent durable. Long-term memory and Skill promotion rules are recorded in
ADR-0006.

An ADR should state the decision, context, alternatives considered, consequences,
and migration/rollback implications. Reopen an ADR when the decision changes;
do not silently contradict it in a feature document.
