# ADR-0009: Electron window for the 1.0 integrated preview

Status: accepted by the maintainer on 2026-10-03; implemented in issue #54.
Owners: client, backend, release. Applies to the 1.0 repository only.

Beta 3 used a Python/WebView2 window. The maintainer requested a real Electron package, native window controls integrated into the existing top bar, better first-launch feedback and the original blue/white/cyan icon.

The Electron host under `apps/desktop-client/electron` owns one frozen backend process and one BrowserWindow. The renderer remains the existing writing/AA application. The backend, updater and MCP worker retain their root-level layout and canonical user-data paths. There is no new story model, wire contract or content migration. Electron preferences are a separate `electron` directory inside the existing user data. Native Windows titleBarOverlay controls share the existing 56 px header; drag regions exclude interactive elements. Renderer privileges remain sandboxed and context-isolated, with no Node or general IPC API.

The window opens a local boot page while the service starts. Local timings distinguish window visibility from workbench readiness. Feedback delivery is asynchronous after boot, so an offline remote cannot hold the editor. Preferred loopback ports persist between launches to preserve origin-scoped appearance settings; an occupied port falls back to an available one. Only the child-owned shutdown receipt is used to stop the backend.

The maintainer additionally required night-mode continuity on 2026-10-04. The host keeps an allowlisted appearance cache, applies it to the boot page and native caption before first paint, and restores only missing renderer appearance keys before the existing theme script. Manual choices remain authoritative; system mode follows current OS appearance. This cache contains no project data or credentials.

The public source exporter includes only this host's reviewed files. The packaged asar is compared entry-for-entry with staged audited source. Official Electron/Chromium license files remain in the portable folder. The completed bundle still passes the existing source/content/notices audits, with exact official Windows runtime binary names added to the executable allowlist.

References: [Electron security](https://www.electronjs.org/docs/latest/tutorial/security), [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window), [Packager options](https://electron.github.io/packager/main/interfaces/Options.html). The sibling 1.1 repository's UI plans and future Tauri work are unaffected.
