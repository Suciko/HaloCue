## 原因与改动

| Before | After | Why |
| --- | --- | --- |
| 嵌入层读取 24 项，原生层读取 36 项；嵌入层反复替换列表，点击与分页失效 | 原生工作台统一负责列表、搜索、选中、预览和分页；嵌入层只组织用途与分类控制 | 两套加载器竞争同一 DOM，既能覆盖事件，也能让显示数量和后端结果不一致 |
| 背景列表被旧 grid-area 放到窄列，外层弹窗和内层列表同时滚动 | 分类、目录、预览各有明确区域；目录／预览独立滚动，弹窗留出上下边距 | 桌面布局继承的网格区域不能直接套在嵌套工作台上 |
| 右上角操作进入 Electron 标题栏区域；详情标题被来源标签盖住 | 顶部操作位于标题栏下方且不参与拖动；详情标题与来源标签分行布局 | 原弹窗纵向尺寸过大，详情标签又采用绝对定位 |
| 只有手动加载更多；CG 最多读 120 项 | 目录和 CG 选择均按 36 项分页，滚动继续加载并保留手动按钮 | 素材规模超过单页时必须可达，不能截断成固定上限 |
| 简体“亚子”无法找到“亞子”；日奈的区域译名无法对应 | 读取随包完整人物参考的确定性别名；原版骨骼的唯一英文别名可辅助匹配 | 别名只补充搜索，不生成 AA Identifier，也不修改 manifest 展示名 |
| 中文背景标注与 AA 资源键大小写不同，原生搜索丢失语义资料 | 标注按大小写无关的键关联；实际 AA 键和哈希保持原值 | 检索、分类、预览、当前场景应使用同一份关联结果 |
| 场景标题被拿来充当已选背景的名称 | 草稿只返回已使用背景的只读元数据，映射、时间线、检查器显示实际素材名 | “风纪委员会办公室”是场景描述，不是选择了哪张素材的证据 |
| 明确的说话人与地点也要从零逐个绑定 | 原生新任务启用确定性预填；唯一角色／明确无冲突场景才自动对应，继续待核对 | 自动化降低重复操作，同时保留模糊地点、服装歧义和已有手动选择 |
| 插入演出要求写工具命令；插入后工具栏还指向旧卡片 | 中文演出类型、参数提示与素材选择；插入后选中新卡片 | 用户应操作演出对象，不能在不了解内部键时猜命令 |
| CG 预览把段落名显示成说话人，夜间 CG 标签与信息区使用浅底白字 | 预览保留说话人；CG 信息使用宿主主题变量 | CG 是画面呈现方式，台词身份和文字可读性仍需保持 |
| 夜间素材类型／背景用途／分类的选中态被通用按钮主题覆盖 | 选中态使用主题强调色，CG 选择行也保持选中状态 | 筛选条件应一眼可见，不能只依靠点过哪个按钮的记忆 |
| 安装器将大小写不同的原版背景标注误判为自定义素材 | 来源声明按大小写关联；只有一致的 `official_base` 才允许引用原版字节，未知／冲突／资源包仍要求实际素材 | 手动安装验收复现了这个问题，检索端修正也必须贯穿交付端 |

分类侧栏不再展示来自另一检索范围的数量。当前目录的已读取数量和总数由原生生产服务返回。

## 内部浏览器手动验收

使用 Codex 内部浏览器，1600×900（16:9），独立用户状态与测试任务。游戏资料仅在本机读取，未提交游戏图片、研究数据库或用户工程到仓库。上传和安装均使用合成素材／隔离测试目标。

| 操作 | 实际结果 |
| --- | --- |
| 粘贴源稿、读取预检、确认场景、选择仅格式化、创建任务 | 可进入四步工作流；原稿保留 |
| 新任务只写“亚子、日奈”和明确 Angel 24 场景标题 | 两个说话人自动对应；背景自动对应；通用“开场”仍提示补背景 |
| 简体亚子搜索、日奈搜索、老师身份 | 可选择真实 AA 资源；老师使用独立身份预设；可手动覆盖自动结果 |
| 深色与浅色背景工作台 | 真实缩略图和详情显示；标题／来源不重叠；弹窗在视口内，顶部操作可点击 |
| 背景分类、搜索、滚动、选择 | 室内范围检索正常；36→72 项滚动加载；选中条目显示详情；已选背景名称真实 |
| 顶部导入／返回任务 | 实际打开导入对话框／回到任务，未误触背后的列表 |
| 损坏 PNG 与背景／插图 PNG、WAV、合成骨骼 ZIP | 损坏图片校验失败且不可登记；四类正常合成素材校验并登记为本任务素材，插图可按中文标签检索并预览 |
| 多场景背景选择、台词与表情保存、刷新 | 两场景分别保存办公室与夜间教室；台词和 `00` 表情保存；刷新后绑定保持 |
| 逐卡预览、自动翻卡与暂停 | 背景和台词跟随卡片，翻卡能推进并暂停；CG 台词保留角色名 |
| 插入／移动演出、检查问题、定位并修复 | 新卡片选中，能前后移动；无效停顿参数被诊断，改为 800 毫秒后解除阻断 |
| CG 范围、选图、预览 | 范围内标记 CG，使用合成背景并隐藏立绘；深色 CG 文本可读 |
| 审查、编译、安装预检、重命名安装 | 10 张卡片完成审查，编译成功；隔离目标安装成功，`.aap`、工程素材、存档镜像均落盘 |
| 未配置模型时请求 CG 制作意见 | 显示“获取 AI 制作意见前，请先配置演出模型”，没有假结果或修改草稿 |

## 可重复自动化

以下 E 盘位置是本次测试临时目录，不是其他电脑运行本项目的前提。`python` 指本地构建虚拟环境 Python 3.13；Playwright 使用 Chromium。

```text
python -X utf8 -m pytest services/halocue/production/tests -q --basetemp E:/HC-AA-production-final-all
python -X utf8 -m pytest services/halocue/integrated/tests/test_aa_material_workbench_browser.py -q --basetemp E:/HC-AA-material-final-theme
python -X utf8 -m pytest services/halocue/integrated/tests/test_production_navigation.py::test_aa_source_focus_keeps_workbench_at_window_bottom -q --basetemp E:/HC-AA-host-scroll-final

```

结果：制作模块 508 项；素材工作台 6 项；宿主滚动 6 项；安装相关 39 项；预览／选择／标注／信息组织 45 项均通过。45 项属于制作模块的重复定向检查，不计作额外独立覆盖。

素材工作台 6 项覆盖 1280×720、1600×900、1920×1080 × 浅色／深色，实际点击与滚动，检查目录分页、后页搜索、预览、顶部命中、边界、简体角色、快速切换类别、类型选中态、插入新卡选中、CG 分页、详情标题不重叠及 CG 文字对比度 ≥ 4.5。安装新增 4 个来源用例先复现失败再修复：原版标注大小写、资源包、冲突来源、未知来源。

新增 Python 文件全量 Ruff check 和 format check 通过；涉及已有大型文件的致命错误规则通过；两个 JS 文件 `node --check` 与 `git diff --check` 通过。未把已有大型文件整体重排版，也未宣称整个仓库 lint 全绿。

## 验收边界

- 本次未启动原生 AA 播放器，不能据此宣称骨骼动画、音效播放、节奏与真实 AA 版本已全部验收。合成 ZIP 只验证校验／登记／交付链路，不代表游戏骨骼能播放。
- 未在隔离状态配置真实模型。本地／模拟 provider 测试验证协议与失败路径，不等于真实 AI 输出质量、额度或外部 Agent 登录验收。
- 顶部按钮已在内部浏览器验证实际点击与 DOM 命中、位置；本次未生成并人工点击新的 Electron 窗口。
- 无法逐一人工核对全部游戏素材；目录分页、检索、选择与预览链路用真实本地资料及合成多页数据覆盖。
- 新任务自动匹配是 opt-in 的局部预填；旧任务和已有手动绑定不自动重写，卡片仍待作者审查。
- 自动化清单覆盖这次改动及相邻链路，不代表全仓库 CI、合并前全套测试或跨电脑安装包已经通过。
