## 1. 总判断

软件需要从“按内部模块分页面”转向“围绕一部作品完成工作”。不是删掉功能，也不是给所有页面涂同一种颜色。

推荐定位：**以作品为中心的创作与制作工作台，AI 是能够查看上下文、提出修改并接受审查的助手。** 不把聊天记录当成作品本身，不让用户为了写一句话先学习内部 Agent、记忆、任务和发布协议。

四条底线：
1. 不使用 AI，也能新建作品、写正文、整理设定和导入文件。
2. AI 修改与作者手写有清晰来源，候选、正式稿和本次制作用稿不混淆。
3. 用户离开一个页面不应失去文字、阅读位置或当前作品；跨作品不能串上下文。
4. 没有配置模型、AA 环境或原作语料时，只有依赖该能力的操作受影响，不能把整个软件变成错误页面。

## 4. 推荐的信息架构

```text
全局入口
├─ 作品                     最近作品 / 新建 / 导入 / 继续上次位置
├─ 创作（当前作品）
│  ├─ 构思                  聊天 + 可检查的方向/决定
│  ├─ 大纲                  章节与场景的内容，而非另一个设置表
│  ├─ 正文                  文稿优先，目录与助手可展开
│  └─ 设定与资料            本作品的知识，不是全局共享真相
├─ 制作（当前作品）          本次制作用稿 → 素材映射 → 演出/审查 → 交付
└─ 素材                     可跨作品复用的媒体资源

固定辅助入口：活动（运行/待处理/失败/历史）、设置、帮助
反馈放入帮助，不再占主工作区一级入口。
```

- “作品”是起点与归属，不是又一个繁杂 dashboard。默认最近作品/继续创作，提供新建空白作品和导入已有稿。
- “构思/大纲/正文/设定与资料”是同一作品内部视图，不是强制线性通关。作者可以先写正文，之后补设定。
- 制作必须沿用作品归属，并清楚标明当前使用哪份锁定稿。不因切到制作就让用户误以为换了一套项目。
- 独立导入只用于制作的老用户仍有路径，标明“独立制作项目”；不要强迫他们先与 AI 聊一遍。
- 素材页的全局性质必须可见；“本作品已用”和“全部素材”是筛选/使用关系，不是复制两份库。
- 夜间首版只调整呈现与导航映射，旧 section/view 路由、书签、历史记录和持久 ID 继续有效。
- 用单一导航配置驱动桌面、窄屏、面包屑、选中态和旧路由别名，不能各处单独硬编码。

## 5. 各模块应该怎样存在

### 5.1 构思和写作：同一个创作工作面，不是两个助手产品

共同能力：统一输入面板、运行/停止状态、待审修改、范围说明和错误恢复。
不同布局：构思时讨论是主要内容；正文时文稿是主要内容。统一不等于把两者强行做成同样宽的三栏。

- 助手作用域始终可看见：整部作品 / 当前章节 / 当前场景 / 选中文段。
- 切换作用域先留住未发送要求，不静默把旧要求带给另一个作品。
- 讨论、大纲建议、正文改动都能查看新增/删除/修改与理由；采用后建立正式修订。
- 手工正文保存走现有直接保存规则，不要求作者审核自己刚写的每一句。
- “没填完人物卡”不应禁止打开正文或讨论；生成依赖缺失时显示具体缺项和就地补充入口，不凭空虚构资料来消除 Gate。
- 入口优先明确动作，如“继续写作”“导入文稿”“查看修改”；不恢复此前删掉的常驻模板提示按钮。
- 没有待审项时不占据一个空的待办栏。正在运行时保留停止和当前范围。
- 保存状态统一为未保存/保存中/已保存/保存失败；不让制作任务页也笼统显示“正文已保存”。

推荐主流程：
1. **已有剧本**：导入 → 预览识别结果 → 选择放入当前作品或新作品 → 编辑/讨论 → 审查 AI 修改。原文只读保留，格式失败有定位，不能假装无损。
2. **已有大纲**：导入或录入大纲 → 选择章节/场景 → 助手读取已确认依据、讨论缺失细节 → 生成候选 → 审查。
3. **人机交替**：手写/粘贴 → 明确保存 → 请求补充或选段修改 → 在原文位置查看差异 → 采纳/拒绝。
4. **纯手工作者**：空白作品 → 建章/场景 → 直接写作和保存 → 整理资料；不必配置模型。
5. **仅制作已有稿**：导入制作来源 → 确认有歧义的分场 → 仅转换格式或主动选择 AI 演出 → 审查/交付。

### 5.2 资料库：必须保留，但改成“本作品的设定与资料”

它回答“这个故事中什么成立、依据是什么”，不是“有哪些图片”。建议首层收为四组：

| 首层 | 内容 | 次级/高级入口 |
|---|---|---|
| 人物 | 身份、职责、说话方式、关系 | 别名、知情边界、原作出处、版本历史 |
| 世界与规则 | 地点、组织、世界设定和规则 | 类型、限制、适用范围 |
| 剧情记录 | 已发生事实、时间线、伏笔、场末状态 | 关系视图、记忆记录/来源/归档 |
| 参考文件 | 导入原文、创作资料、原作来源 | 解析状态、引用片段、索引和原作检索 |

注意：这是视图分组，不把 WorkCanon、记忆、世界规则、原始文档合并成一张数据表，不改变各自来源和权威级别。

- 总览显示最近使用、待确认、缺失关联等有意义内容；空态直接给创建/导入入口。
- 人物第一屏只显示必要信息，高级字段折叠；“新建自定义人物”必须真的是自定义来源。
- 原作资料、本作设定和 AI 提议来源分明。用户明确确认前，不把参考片段当成正式剧情事实。
- 关系图是已有资料的另一种查看方式，放在相关页的视图切换中，不要求用户单独维护第二套事实。
- “长期记忆”改为可解释的剧情记录/助手参考详情，保留来源修订和回收能力；不让作者学习数据库概念。
- 待审资料并入统一“待审修改”，同时在对应资料页有数量入口；不是迁移后找不到。
- 场景缺人物资料时，在当前工作面侧栏选已有卡或创建最小草稿，完成后返回原场景，保留未发送文字。
- 原作检索不可用只影响该来源，不把全库染成警告状态。

### 5.3 素材库：保留独立资源中心，但建立“找得到、看得见、用得上”的闭环

它回答“演出用哪张图、哪个声音、哪个角色资源”。核心实体与资料卡不同。

三层必须分清：
1. 素材本体：文件/资源 key、预览能力、类型、来源、技术有效性。
2. 作品使用关系：在哪部作品、哪个角色/场景使用。
3. 制作快照：本次制作引用或复制了哪个版本，有无复制回执、缺失资源。

第一晚优先：
- 浏览/搜索/类型筛选 → 预览 → “用于当前场景/制作项目”，无目标时明确选择目标。
- 当前分类决定上传默认类型，只展示该类型字段。角色 Identifier 等技术键默认自动生成或高级展开，但不能破坏 AA 兼容键规则。
- 分类明确称“角色素材/立绘”，避免和资料中的人物卡混淆。
- 统一素材卡、搜索、选中、详情、空态、缺失和不支持预览的状态；Spine 未渲染时如实显示“仅包信息/暂无渲染预览”。
- 现有支持的背景、CG、WAV 音效、Spine ZIP 做完整，不用加空标签伪装已支持 BGM、配音或视频。
- 标签、识别和批量处理是辅助能力；AI 识别可选，用户不应为普通导入被强制消耗额度。
- 对素材的合法来源/许可及使用位置留入口。删除被引用素材前说明影响；首晚不做自动清库或物理去重。

后续：全库索引/缩略图缓存与制作执行服务逐步解耦；至少能显示已确认的本地索引及其过期/离线状态。不得把旧缓存伪装为在线可用素材，也不在首晚另起一套资源数据库。

### 5.4 任务：系统必须有，主导航不必常驻一整页

改为“活动中心”：
- 入口显示真实运行中数量；无活动时安静，失败/待处理时有明确提示。
- 列表只讲清楚：在做什么、属于哪个作品/场景、真实状态、结果在哪里、下一步能做什么。
- 支持的操作才显示：查看结果、重试、取消；不支持恢复的阶段不要展示假的暂停/继续。
- 没有可计算总量时用阶段状态，不伪造百分比。
- 错误先给用户可操作解释，错误码/日志/用量在详情；重试可能重新调用模型时应说明。
- 待审修改与后台运行相互链接，但不是同一种状态：运行成功不代表已经采纳。
- 作品 runs、Agent runs、production jobs 首晚通过只读适配聚合视图，保留各自状态机和事件来源；不直接合并持久化表。
- 老任务页保留为活动历史深链接，入口降级，不删除记录。

### 5.5 制作与交付：消除另一套软件的感觉

- 外框、作品归属、主题、控件、状态和错误方式统一；生产渲染/兼容服务保持原边界。
- 当前输出明确标注“AA”，不是把未实现的 MP4/MMT 导出按钮摆出来。主导航可叫“制作”，具体交付格式按真实能力显示。
- 从写作进入时带入作品与已锁定的制作用稿；不要求重新起工程名、重新找同一篇正文。
- UI 可把“发布”解释为“准备制作用稿/锁定本次版本”，底层仍是 immutable ScriptRelease。写作后续修改不悄悄修改制作输入。
- 将缺场景正文、缺资料、记忆未处理、素材缺失、过期审查集中成可定位清单，避免只给一个消失的 toast。
- 读取/确定性预检可以自动做；有歧义的分场、模型调用、正式写入和交付仍要明确决定。不能把三个按钮简单合成一个不可解释的黑箱。
- 回到写作后有修改，制作显示“有新稿可用，当前仍使用版本 X”；更新必须显式选择并显示受影响范围。
- 首晚优化外框、空态、来源和错误恢复；完整制作预览与演出大改另列验收，不重做 AA 编译器。

### 5.6 设置、帮助与缓存

- 设置按外观/模型连接/本地制作环境/数据与备份/关于组织，不把环境依赖撒在每个空页面。
- 模型选择放在助手附近，详细密钥/服务配置在设置。不要用“顶尖”“高智商”等营销文案代替连接状态与能力。
- 明确区分 AI 提示词前缀缓存、参考文档索引缓存、素材预览缓存、用户未保存草稿恢复。
- 前缀稳定性优化已经存在，先回归不退化。正文保存后下一轮必须引用新修订；不能为了命中率读取旧稿。
- 服务商未报告的用量显示未知，不能显示为零命中；不把真实命中率或成本改善当作未经测量的交付成果。
- 全局全文搜索、全应用跨进程草稿恢复属于后续纵向功能，不为赶时间做一个只搜当前页的假全局搜索。

## 6. 统一视觉与交互的具体要求

统一的是规则，不是所有内容的宽度：
- 唯一的品牌/导航/面包屑/作品切换外框，所有页面共享图标与语义选中态。
- 主题 token 统一背景、层级表面、边框、正文/次要文字、强调/危险/警告色；少用与状态无关的彩色框。
- 标题、字段说明、按钮、菜单、弹窗、空态、错误、加载状态统一；去除不必要的英文大写标签和版本开发说明。
- 正文/长讨论保留适合阅读的最大宽度与留白；素材网格/制作预览可以更宽，不把主文稿拉满屏。
- 共享三个布局模板：文稿+助手、目录+列表+详情、制作预览+编辑。工具和辅助栏按任务出现。
- 每个工作区明确滚动容器；滚动条贴所属面板右缘，不出现在居中文稿边上。
- 窄窗口空间不足时转为单面板/抽屉，不把三栏硬缩成三条窄缝；自动折叠与用户偏好分开记录。
- 正文/对话/素材搜索在返回后恢复原位置；切换作品不错误恢复另一作品内容。
- 高频按钮有可理解的文字，图标补充而非谜语；边缘收起按钮保留 hover/focus/touch 可访问性。
- 成功状态安静，阻塞状态具体；不能用到处出现的“不会自动修改”长说明替代真实的权限和审查设计。

技术上先收敛外框/基础组件样式所有权，不通过再追加一份万能覆盖 CSS 完成。制作有 Shadow DOM 边界，应用 token 需明确透传；不能只给外层 body 换色后宣称制作已统一。

## 7. 实施路线与整晚时间盒

以下为约 8 小时的安排，不是保证 8 小时内做完全部愿景。回归发现数据/状态风险时优先收尾，不拿安全和验收换页面数量。

| 时间盒 | 切片 | 当晚完成标准 | 依赖/风险 |
|---|---|---|---|
| 0:00–0:45 | 基线与保护 | 记录当前脏树/逐文件快照；隔离完整服务和合成数据；冻结导航/权限/保存/审查最小回归清单 | 不能直接从 HEAD 建工作树而漏掉全部既有未提交功能；不 reset/clean |
| 0:45–2:00 | 全局外框与设计基础 | 六个旧工作面共用品牌、导航、主题和基本控件；补制作服务失败页的可恢复动作 | 优先复用，不重写整个框架 |
| 2:00–3:30 | 创作信息架构与状态 | 创作内的构思/大纲/正文/资料有明确归属；旧 URL 可用；修复跨模块右栏状态；手写与导入入口不用先聊 AI | 保存/未发送文字/作用域是验收重点 |
| 3:30–4:45 | 资料的首层整理 | 四组入口映射已有 11 类；修正自定义来源；空态可直接建资料；原作警告局部化 | 只调整视图，不合并领域数据；复杂编辑改造可顺延 |
| 4:45–5:45 | 素材基本闭环 | 类型跟随、字段渐进、预览状态、明确应用目标；去除全屏说明堆叠 | 依赖可用的制作/资源接口；真实大库性能另测 |
| 5:45–6:30 | 活动与制作衔接 | 运行计数正确、活动入口和结果定位；制作用稿来源明确；失败有返回/诊断入口 | 聚合仅使用已有状态，不造新后台调度器 |
| 6:30–8:00 | 全流程回归与整理 | 关键路径/尺寸/主题回归；修优先阻塞；截图和差异记录；已完成/未完成如实清单 | 这段预算不可全部挪去加功能 |

### 首晚真正的必交付
1. 看起来、操作起来是同一款软件，而非只统一构思和写作。
2. 用户能理解“作品 → 创作 → 本次制作用稿 → 制作/交付”；素材和资料不混淆。
3. 已确认的来源默认值、任务计数、跨页面状态问题有回归保护。
4. 默认导航更少，但所有旧功能/历史入口仍可找到，不靠删数据实现简洁。
5. 用户手稿、权限、候选、Gate 和制作输入快照不退化。

### 当晚不得伪装完成的内容
- 整个八千行 app.js 和全部 CSS 一次重写，或者临时换 React/Vue。
- 新视频/MMT 渲染器、真正无缝制作预览、原生 AA 全链路验收。
- 全素材资源解耦、全库物理去重/删除、跨作品知识自动共享。
- 全应用自动保存到正式稿、自动采纳 AI、自动跳过记忆/发布检查。
- 未经授权的真实模型费用测试、后台自动重试、安装或发布。

若时间不足：保留已验证切片，素材深层编辑、活动跨服务高级聚合、关系图新布局进入第二轮；不交付一个所有页面都改了但没有完整路径可用的版本。

## 8. 工程分解与迁移约束

| 工作包 | 主要位置 | 不应顺手改的内容 |
|---|---|---|
| 导航/作品归属 | writing/web/app.js 的 HC_SECTIONS/router/renderChrome，index.html、shell.js、writing-workbench.js | 不重编场景 ID，不改历史路由含义 |
| 外框/组件规则 | tokens.css、shell.css、theme.css、redesign.css、authoring-ui.css；production-theme/production-embed.css | 不盲删旧 CSS 或以 !important 全覆盖掩盖规则冲突 |
| 构思/正文/助手 | agent-workspace.js/css、app.js scene/work renderer、change-review.js/css | 不合并讨论线程、不绕过 Proposal 接受逻辑 |
| 设定与资料 | renderReferencesNavigation/renderReferences/decorateLibrary、资料相关 tests | 不把不同来源/修订的资料自动视作同一个事实 |
| 素材 | app.js asset catalog/upload、production resource_catalog/custom assets、production embed selector | 不改真实媒体内容、不重建第二素材库 |
| 活动 | renderMobileTasks、现有 user status/agent run/production job 适配 | 不改变任务幂等性、重试费用与晚到结果处理 |
| 制作交付 | production-embed.js/css、production/ui、integrated gateway 与现有 release contract | 不改冻结发布、审查快照、素材复制回执和 AA 编译协议 |

- 先建立真正共享的薄组件/样式边界，再迁移页面；每个切片都有能运行的旧路由兼容入口。
- 同一个组件只有一个最终 renderer；清理重定义必须先确认调用者，按切片替换，不能凭名称删除旧实现。
- 新增局部视图状态使用稳定作品/场景/线程 ID 作为键；不要把内容本身或全局 DOM 缓存当领域真相。
- 有线格式或发布 Gate 变化才需要合同/迁移/ADR；纯标签分组不用凭空引入数据库迁移。
- 当前无专门关联的重整 Issue/PR。本计划待用户确认后再拆成聚焦 Issue/提交，不把历史脏树打包成一个“UI 优化”提交。

## 9. 验收矩阵

功能路径至少包括：
1. 无模型：新建空白作品 → 建章/场景 → 手写保存 → 重开仍有稿。
2. 旧稿导入：预览 → 选归属 → 保留原文 → 形成可编辑内容；取消不产生正式稿。
3. 已有大纲：定位场景 → 讨论 → 候选 → 查看增删改 → 部分采纳/拒绝。
4. 人机混写：未保存手稿 + 未发送要求 → 模块切换/保存失败/重试 → 不丢、不串作品。
5. 设定：新建自定义人物默认自定义来源；原作导入保持原作来源；待核对不偷渡正式上下文。
6. 资料空库不要求先配置 AI；原作语料离线不影响本作资料编辑。
7. 素材：角色分类上传默认角色类型；取消无写入；不支持的预览诚实提示；应用到明确场景/制作项目。
8. 活动：运行/待审/失败/完成数准确；从记录定位结果；重试/取消不重复写入、不拉回已离开的页面。
9. 跨模块：构思待办 → 资料 → 任务 → 正文，仍恢复正确场景与助手，不出现不相干的 STEP 面板。
10. 写作定稿 → 制作来源；写作后续修改不改变旧制作输入；资源/审查失败可回到具体问题。
11. 制作服务关闭时：构思/手写仍可用；素材/制作显示具体恢复入口，不用原始 503 页面充当体验。
12. 权限选项、选段修改、待审差异、中文输入法 Enter、停止、快捷保存、未保存导航确认全部回归。

界面组合：1440×900、1280×800、1024×768、820×520、390×844；亮/暗主题；键盘、触摸尺寸、焦点恢复；长标题、长稿、多章、多任务、空状态和错误状态。

验收不等于截图变漂亮：
- 页面不横向溢出；按钮不裁切，滚动归属正确。
- 用户能说出当前位置、当前操作影响什么、下一步点哪里。
- 纯导航、打开面板、预览说明不调用模型。
- 形式上的按钮隐藏不能改变后台权限/发布条件。
- 测试数据与真实库隔离；付费调用、真实安装/发布另经用户明确授权。

## 10. 回退与交付

1. 实施前记录脏树文件与原始内容，保持本轮修改集合可辨识；不清理其他人的工作。
2. 每个切片通过对应回归再继续；失败只回退本切片，不全仓 reset。
3. 旧 URL、资源 ID、作品数据、历史修订保留；本轮不做破坏性迁移。
4. UI 改造完成不等于“稳定版发布”。真实 AA/大量素材/真实模型只做过什么就报告什么。
5. 交付清单写明：改了什么、没改什么、测试命令与结果、截图、剩余问题、未验证依赖、下一步。

## 11. 需要单独评审的产品决定

以下建议不能混在视觉提交里悄悄生效：
- 是否把逐场记忆维护从发布硬门槛调整为可选/分级要求。
- 是否新增章节范围的制作用稿，而不是全作发布；涉及范围与跨章依赖。
- 素材索引与制作服务的持久化解耦，以及已有数据迁移。
- 更完整的本地草稿自动恢复与跨窗口冲突解决。
- 从当前 AA 交付扩展到视频/MMT 的正式产品范围。

首晚应避免这些决策阻塞外框统一和已确认缺陷修复，但也不能在界面上假装它们已经解决。
