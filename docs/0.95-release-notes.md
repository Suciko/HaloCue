# HaloCue 0.95 更新日志

0.95 的重点不是更换桌面外壳，而是把新的 AI 演出判断、资源语义数据和后端字段链路整理成一套可以稳定使用的流程。

## 新增与改进

### AI 演出流程

现在的生成流程是：预读剧本 -> G1 场景规划 -> G2 逐节点导演 -> 编译 AAP。AI 会结合上文刺激、人物关系和情绪阶段，自主判断：

- 谁在承受当前刺激；
- 是否需要换脸、表情符号、动作、音效或气泡；
- 什么时候保持关系镜头，什么时候使用反应特写或硬切；
- 站位和人物状态如何延续；
- 只有在下一句之前必须看见反应时，才加入短的无对白节点。

这套流程不再用固定的 `Wait`、`face`、`emo` 或 `act` 数量要求 AI，也不会为了凑指令数量强行加戏。长段默剧不再作为模型必须完成的硬指标。

### 角色表情的细致标注

早期版本没有完整的角色表情语义库，主要依赖 Spine 骨骼内附带的少量标注。这些标注有时过于粗略，甚至会把资源含义解释错，模型就可能生成不存在或不适合当前角色的表情名称。

0.95 加入了经过逐角色、逐装束、逐表情复核的详细标注，并在请求中提供当前角色真实拥有的表情白名单和语义。这样可以减少类似 `[Emo:沉稳剖析]` 这种自然语言情绪被误当成资源名的问题；编译前仍会检查角色、装束和表情是否真实存在。

### 人物名称与装束识别

0.95 内置了一份从 ba-writing 人物卡的角色名和别名中精简提取的人物别名索引，并随程序提供繁简转换能力。中文常用名、繁体名、其他地区译名与 AA 使用的角色标识可以在本地对应起来，不需要用户手工改写 AA 的人物清单。

搜索普通人物名时，会同时列出该人物的普通形态和已安装装束，方便用户自行选择；自动匹配则优先尊重剧本中是否明确写出装束。比如“乃爱”或“诺亚”默认匹配普通的 `노아`，只有明确写出“诺亚（睡衣）”时才会选择睡衣装束。生成到 AA 后，对白框仍显示简体中文常用名“诺亚”，不会显示韩文资源标识。

程序只读取当前用户 AA 中已经安装的人物及其资源对应关系，并在 HaloCue 本地完成别名匹配，不会修改或写回用户的 AA `manifest`。只修改人物显示名的官方资源仍按官方人物处理；只有无法对应已知角色标识和骨骼的新增人物，才归入该用户本机的自定义人物。

这些数据库中不存在、但已经安装在当前 AA 的自定义骨骼会自动出现在素材库，并标记为“AA 本机自定义”。用户可以直接调用素材库现有的 AI 表情标注功能；标注结果只保存到该用户的本机数据库，不会上传到公共数据库，也不会改写 AA `manifest`。如果用户以后删除该资源，素材库中的本机映射会随之移除。

### 背景分类与搜索

背景部分也不再只依赖资源文件名或零散字段。我们补充了细致的人工标注，覆盖地点、主分类、中文子分类、室内外、时间、天气、季节、氛围、阵营、复用范围、标签和中文搜索词。搜索会检查完整标注记录，已标注的分类、近义词和描述都可以参与检索。

### 标注数据库

0.95 可以同时读取主标注数据库和一个或多个只读叠加数据库。主库优先，叠加库用于补充表情、背景和其他标注事实，不会覆盖或写回原数据库。

## 相对旧版修复的问题

- 修复了早期只依赖 Spine 内部少量标注、导致表情语义不准和资源名误用的问题；现在使用细致的角色、装束和表情标注，并保留真实资源白名单校验。
- 修复了 AI 已经返回 `emo`、`act`、`fx`、`camera`、`move`、`reveal` 等演出字段，但在后续 compact、策略处理或 AAP 编译中无法追踪的问题；现在可以定位字段在哪一层保留、替换或被拒绝。
- 修复了模型明确选择表情、动作或镜头后，后端为了追求“简单”而静默压掉有效演出的情况。只有协议、资源、生命周期、几何和人数等硬约束可以导致字段被处理。
- 修复了跨节点的镜头、站位和人物生命周期状态不连续时，后续节点无法正确继承的问题。
- 修复了标注数据库叠加配置依赖开发机绝对路径的问题；现在使用相对路径，主库优先，叠加库保持只读。
- 修复了同一套流程在不同入口使用不同版本标记的问题；0.95 的提示词、后端和资源数据使用同一个版本标识。
- 公开发布包不再包含开发环境中登记的私有自定义人物及其关联信息，其他用户只会看到随正式版本提供和自己本机安装的人物。
- 修复了繁简体和不同地区译名难以对应 AA 人物的问题；别名匹配只在 HaloCue 本地进行，最终对白框使用简体中文常用名，不会修改用户的 AA `manifest`。
- 修复了普通人物名称可能被本地服装变体优先占用的问题；搜索普通名仍会列出普通形态和可用装束，但自动匹配默认选择普通形态，只有剧本明确写出装束时才选择对应变体。
- 修复了用户自行加入 AA、但公共数据库中不存在的人物骨骼只能在人物列表中出现、无法进入素材库打标的问题；现在这类资源会归入本机自定义素材，并可单独完成 AI 表情标注。

## 发布方式说明

桌面 EXE、WebView2 窗口、内置 Python 和第三方运行库沿用 0.945 已经完成的发布方式，不是 0.95 才新增的功能。0.95 只是把本轮新的提示词、后端、资源标注数据库和修复后的字段链路放进同一套既有桌面发布结构。人物别名索引和 OpenCC 繁简转换组件也随 EXE 一同打包，普通用户无需另行安装或下载。

发布包必须完整解压，入口是根目录的 `HaloCue.exe`，不能只复制 EXE 或删除 `_internal`。Windows 10/11 通常已经有 Microsoft Edge WebView2 Runtime；如果系统缺少，启动时会提示安装。AzureArchive、游戏资源包和模型接口仍由使用者自行提供。

## 不包含的内容

发布包不包含 AzureArchive 本体、游戏图片、立绘、背景图、CG、音频、AssetBundle、`.skel`、`.atlas` 或用户剧本工程。随包数据库只保存资源名称和文字/结构化标注，不是游戏资源本体。Spine WebGL 运行时用于网页预览，并附带其许可证。

## 已知限制

- 当前主要面向线性剧本，完整分支选项还没有全部接入。
- 不同 Spine 版本的兼容范围仍需按实际资源确认。
- 长段连续默剧不是 AI 的默认质量门，复杂连续动作仍可能需要人工导演复核。
- 编译成功或字段完整不代表演出观感已经达到官方质量，生成后仍应检查镜头、站位、表情、动作和节奏。
- 目前没有可复现的官方相似度百分比计算器，因此不提供虚构的相似度数字。
