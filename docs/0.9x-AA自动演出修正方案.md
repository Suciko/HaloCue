# 0.9x AA 自动演出系统：修正与落地方案（v1）

状态：设计评审完成，已合并独立方案中可用部分并修正实现缺口。本文档只描述方案，不直接改代码；实施时按第 11 节顺序落地。

---

## 1. 范围与目标

输入：只有台词、说话人、场景和演员资源信息的剧本。
输出：AzureArchive 可编译、可播放、空间连续、角色身份正确、接近《蔚蓝档案》官方活动剧情演出质量的 AAP 工程。

当前只做 0.9x 后端，1.0 后续再同步。

事实来源：

- `aa/aa_assets.db`：完整标注事实来源（结构化查询抽样，不整库进提示词）。
- `aa/aa_resources.json`：程序兼容与运行时资源索引。

不可违背约束（沿用用户已明确的要求）：

1. 不设置硬字符预算。
2. 后端不擅自改小模型最大输出 token；按用户与模型配置使用。
3. 不设固定动作数、气泡数、特写数、镜头数、Wait 数、无对白节点数或固定镜头长度配额。
4. 每镜最多三名可见人物，绝不允许四人同镜；单人和双人默认，三人只用于确实成立的共同反应或稳定三方互动。
5. Wait 只允许出现在无对话框节点。
6. 无对话框节点必须有可读目的。
7. 普通镜头切换不等于真实入场/退场；`enter/exit` 只用于确实进入或离开叙事空间。
8. 硬切是官方常用语法，不压制；禁止的是逐句机械反打和视觉上的原位换图层。
9. 单人通常中央构图；双人和三人必须结合立绘真实宽度与几何标注防重叠。
10. 关系距离只判断当前画面中真正互动的人。
11. 表情、动作、气泡、镜头共同服务当前演出目的，可以组合多层承载爆点。
12. 爱丽丝日常状态不得使用凯伊人格红眼/黑化/身份污染差分；所有角色特殊身份差分必须硬过滤。
13. 写作 Agent 推理强度固定 `high`，不使用更高档位。

本方案采用的设计结论（由现有盲测、用户反馈与代码核对共同得出）：

1. **峰值不是单人特写的同义词**：第一阶段必须区分 `solo_emphasis / relationship_peak / group_reaction`。只有明确规划为 `solo_emphasis`、且 G1 有台词语义证据时，后端才确定性落实单人构图；关系峰值和共同反应不得机械收成单人。
2. **`semantic_modular` 角色候选池**：合并官方验证的 legacy face id（如 06/07 类），但必须先通过人格硬过滤；实施前用 DB 抽样确认这些 face 有可用的语义/官方使用证据。
3. **场景事件规划分阶段启用**：实现与盲测阶段显式开启；达到第 12 节验收标准后再将 `scene_event_planning=True` 设为生产默认。保留 `--no-scene-plan` 作为显式降级路径；这不是字符预算，也不改变模型最大输出 token。

## 3. 总体架构

两阶段 + 确定性后端 + 三层质量门 + 局部返修。**不新增常驻第三 AI critic。**

```text
剧本 + cast + aa_resources.json + aa_assets.db
   │
   ▼
[0] 解析/预审（确定性）
   parse_lines / split_strong_dialogue_items / assign_annotation_ids / build_scene_map
   usage_chain 提供场景边界、active_modes、已确认 bg/se/bgm
   │
   ▼
[1] 第一阶段：场景事件规划（每场景 1 次，high）
   plan_scene_events()
   → Plan IR v2（见第 5.1 节）
   │
   ▼
[G1] 计划层质量门（确定性，失败只返修该 event）
   │
   ▼
[2] 第二阶段：分块执行（high，走正式 annotate.py 管线）
   assemble_chunk_context()
   → 模型输出 lines + direction + beats（Execution IR）
   → validate_chunk_response() 协议校验
   → 后端安全内核：
       资源白名单 / 身份硬过滤 / 最多三人 / 说话者可见
       / 计划授权的构图修正 / heavy fx 语义复核 / move+reveal+enter 归一
   │
   ▼
[G2] 执行 IR 层质量门（每 chunk commit 前跑）
   通过 → 写 checkpoint
    失败 → 对失败 source_ids 做一次局部返修（不重发整 chunk）
    返修仍失败 → 标记 needs_review；可继续生成草稿，但不得标记 PASS 或自动安装
   │
   ▼
[3] 渲染 annotated.txt
   insert_annotation_beats + _beat_item（空 face 保留，由编译器按顺序继承；carrier 已经 G2 验证）
   render_annotated_items
   │
   ▼
[4] script2aap.build() 生成内存中的真实 ScriptData
    │
    ▼
[G3] 检查 flat ScriptData + provenance；失败则返修 IR、重放状态并重新 build
    │
    ▼
[5] wrap_project()；剥离私有 trace 后写 AAP / 安装工程
```

返修边界：

- G1 失败：只重发该 event 的台词区间 + 错误码 + 原计划错误点。
- G2 失败：把失败 `source_ids` 做成合成 chunk（±3~5 行上下文），用原 schema 重新生成这些行和这些锚点的 beats；未失败行冻结不动。
- G3 失败：按 provenance 返修触发行/beat/plan event；从所属场景的安全状态点向后重放，禁止只替换前文而沿用被污染的后续 memory。
- 每 chunk 最多返修 1 次，防止成本失控。
- `critical/high` 在一次返修后仍未解决：只允许输出带红色报告的草稿，不得自动安装；`warning/info` 才允许带诊断继续。

## 4. 职责矩阵

| 决策 | 第一阶段 AI | 第二阶段 AI | 确定性后端 | 局部返修 AI | 人工 |
|---|---|---|---|---|---|
| 场景类型与混合模式 | 从 usage_chain 继承；缺失时推断 | 只读 | 校验枚举并注入 active_modes | 否 | 可覆盖 |
| 事件链与互动轴 | 唯一生成者 | 只读兑现 | 否 | G1 失败时 | 否 |
| `scene_presence`（是否仍在叙事空间） | 只给真实 arrival/exit 证据 | 用 enter/exit 申请变更 | 状态机最终裁决 | 分类错误时 | 否 |
| `shot_visibility`（镜头可见名单） | 只规划 shot_group | 决定 visible_characters | 校验 ≤3、说话者可见、名单与 positions 一致 | 是 | 否 |
| hard cut / hold / reframe | 只标互动轴是否改变 | 先写 shot_operation | 映射 shot_transition；校验 cut 完整重建 | 是 | 否 |
| reveal / enter / exit / move | 只标“需要” | 填具体 beat | 按 scene_presence 校验；方向按目标槽位；reframe 需要让位时已有角色出 move | 是 | 否 |
| 具体槽位和缩放 | 否 | AI 导演模式可给 | AI 辅助/稳定模式由 Stage 计算；全模式校验重叠 | 是 | 否 |
| 峰值类型与效果释放 | 区分 solo/relationship/group，给 peak/release 与表演意图 | 选择具体构图、资源与释放点 | 只对已验证的 `solo_emphasis` 落实单人；重效果需计划授权并校验生命周期 | 是 | 否 |
| face 语义 / face id / 身份过滤 | 只输出 face_arc 语义阶段 | 从 shortlist 选 `[Emo:语义]` | 解析 face id；人格硬过滤 | 阶段无变化时 | 可 |
| 动作 / 气泡 / 声音 | 只写叙事意图 | 从白名单选具体资源 | 合法性校验；禁止配额与冷却删除 | 是 | 否 |
| 无对话框 beat 与 Wait | silent phase + carrier_requirement | 输出 beat 与 wait_ms | 按顺序继承 face；校验是否兑现可读载体；Wait 只允许在 beat | 是 | 否 |
| 背景与转场 | 否 | 从候选选 bg/trans | 资源校验；trans 只随 bg 变化 | 否 | 否 |
| 编译后空间连续性 | 否 | 否 | G3 确定性复核 | G3 发现时 | 否 |

三种模式只改“谁填哪部分 IR 字段”，不改渲染器和安全内核：

- `AI 导演`（原 pure_ai）：AI 填完整镜头与槽位；后端校验结构/几何/身份，只落实经过验证且不涉及艺术分歧的修正。
- `AI 辅助`：AI 填焦点/关系/演出意图；后端 Stage 填槽位。
- `稳定后端`：AI 主要填 face/emo/act 语义；后端承担镜头与站位。

字段规则（Schema 级，不是提示词建议）：

- `shot_groups` 是事件内先后被拍摄的互动小组，不是逐句镜头；同组、同焦点、同景别且没有新语义变化的连续声明应合并。
- 删除/废弃实验期的逐句 `shot_steps`。质量门只检查重复声明和无语义变化，不拿 shot 总数与台词总数做比例配额。
- `peak_type` 必须是 `solo_emphasis / relationship_peak / group_reaction` 之一。`release_i + release_position` 可指向后续行、下一事件或 `scene_end`；重效果必须有可确定收束的生命周期。
- `performance_intents[].carriers` 默认是可替代实现集合，第二阶段为指定人物兑现其中至少一种即可；只有物件操作、真实入退场或声画组合缺少任一层都会改变事件事实时，才加 `require_all: true` 并逐项硬验。相邻台词之间的 `上一句 after` 与 `下一句 before` 是同一时间边界，质量门必须等价识别。
- 每个 silent beat 必须有结构化 `carrier_requirement`。`require_observable_change` 按 phase 决定；允许有明确目的的 decision pause 继承姿态并仅使用 Wait，但普通反应拍不能只有空等待。
- `face_arcs.stages[]` 用 `anchor_i + position` 定位，只写语义状态与变化原因，不写 face id、不写具体资源。
- 连续强句：每个 event 若含连续强句，peaks 必须给出“一个 peak + 一个 release”的明确划分。默认 peak 在真正完成升级的那句；若 peak 在前句，`why` 必须说明后句是余波/解释/回落。**不把“峰值一定在后句”当硬规则。**

## 6. 镜头与人物状态机

在 `memory.direction` 增加 `scene_presence`（每个角色的叙事空间三态），与 `shot_visible_characters` 分离。场景开头不能把所有未建立角色直接视为 `absent`；没有到场/离场证据时保持 `unknown`。

| 状态 | 字段 | 变更来源 |
|---|---|---|
| `scene_presence` | `memory.direction.scene_presence: {角色: unknown\|present\|absent}` | 场景边界置 unknown；明确 arrival/enter 置 present；明确 exit 置 absent；首次镜头建立不改变为“刚刚到场” |
| `shot_visibility` | `memory.direction.shot_visible_characters` | visible_characters / camera_cut / camera_hold / reveal / enter / exit |
| `composition` | positions + focus_character + focus_kind + relation_distance + shot_group | direction.positions 等 |
| `transition` | shot_operation（语义）→ shot_transition（渲染） | director_policy 映射 |
| `performance_state` | last_faces + continuity + recent_* | _merge_director_rows |

转移规则：

| 转移 | 条件 | 状态变化与后端动作 |
|---|---|---|
| hold | 同互动轴、同 group、焦点/景别没变 | 只更新 performance；丢弃重复 camera/face |
| reframe | 同 group 内扩/缩、焦点承接 | 必须完整 positions；Stage 计算让位；已有角色出 `@move`；新人 `reveal/enter` |
| cut | 互动轴、完整拍摄小组、焦点承受者或戏剧拍点改变 | `@camera_cut` 清旧构图并重建完整名单+槽位；共同保留者必须有槽位或景别变化 |
| reveal | 角色为 present，或为 unknown 且正文没有真实到场证据；第一次进入当前连续镜头 | 只加 shot_visibility；unknown 同时确立为 present，但不得播放“刚进入房间”的叙事含义；方向 = 槽位 1/2→left，4/5→right，3→fade |
| enter | 角色为 absent，或 unknown 但正文有明确真实到场证据 | scene_presence 置 present，shot_visibility 同加；方向同 reveal |
| exit | 角色为 present 且正文有真实离开空间证据 | scene_presence 置 absent，并从 shot_visibility 移除；只离开镜头不用 exit |
| move | 可见角色真实位置变化或为新人让位 | 只改 positions；必须形成动画，不瞬间换层 |

关键场景处理：

- **合法硬切 vs 原位换图层**：源码层查 `shot_operation/cut_motivation/shot_group`，编译层比较可见名单、槽位、景别、说话者、高亮、face/emo/act/fx 与出现方式。`[A,B]→[A,C]` 且共同保留者完全不变时默认报 high；只有计划明确声明 `anchor_match_cut`、给出互动轴变化的语义理由，并且编译结果存在可读的焦点或表演变化时才允许。
- **`[A,B]→[A,C]`** 只允许三种路径：
  1. 收成 A 单人 → C 以 reveal/enter 加入，A 用 move 让位；
  2. C 真实入场 → enter；
   3. 完整互动轴改变 → cut；通常重建槽位/景别。若刻意保持 A 为视觉锚点，必须满足上面的窄 `anchor_match_cut` 例外，不能靠随意移动 A 来规避检查。
- **单人扩双人、双人扩三人**：默认 reframe；后端用 `Stage.plan` 生成 positions；现有角色 move，新人 reveal/enter。
- **三人收双人**：被移出者仍在叙事空间时只离开当前镜（普通切镜），不 exit。
- **已在房间但第一次进入当前连续镜头**：没有真实到场证据时使用 reveal 或 cut/reframe，不使用 enter。
- **离镜很久后重新被拍到**：cut/reframe 完整重建；不依赖 AA 的自动渐入。
- **共同反应后切单人承接**：group_reaction beat 后 `impact_insert/switch_group + cut` 到最重要回应者单人。
- **真实入场与镜头显现**：以三态 `scene_presence` 加正文证据共同判定；enter 对象已在场 → 后端降级为 reveal/cut 并告警；absent 角色 reveal → 有到场证据时改 enter，否则返修；unknown 角色默认 reveal/cut 建立，不擅自推断真实入场。

## 7. 表情系统方案

### 7.1 语义 token → 后端 face id

保留，并补三个缺陷：

1. **候选生成要计划感知**：`target_face_shortlists` 增加 `scene_event_plan` 参数；用当前事件 `face_arcs`、`peaks`、`performance_intents` 生成检索信号，而不是只用本句关键词。silent 候选继续用 `silent_reaction_shortlists`，并覆盖更多 phase。
2. **候选池补官方验证脸**：`annotate.py::annotation_constraints` 对官方 `semantic_modular` 角色，候选集合从 `semantic_face_allowlist`（仅 `spine_semantic`）扩大为经过视觉组件语义和身份范围验证的 `spine_semantic ∪ aa_verified`。`aap_observed` 只表示“曾被使用”，不能单独证明语义正确；只有同时具备眼/眉/嘴组件标签、装束/骨骼范围和非特殊身份结论时才可进入候选。`_allowed_face_records` 增加 `semantic="mixed"` 模式。实施前用 SQL 抽样确认 06/07 等 face 的 `sources/expression_class/persona` 状态，确认可用再放开。
3. **token 冲突去重**：`_semantic_token` 生成的两个不同 face 不得共用同一 token；冲突时只保留评分最高者，或在 token 后加短后缀（如 `[Emo:认真报告·2]`），保证 AI 选什么、后端解析什么。禁止 `token_map.setdefault` 静默吞候选。

### 7.2 阶段变化与可读差异

- `rank_face_candidates` 增加 `previous_face_record` 与 `stage_change` 软信号：
  - 计划声明阶段变化时，给与上一张脸 `eyes/brows/mouth` 组件签名不同的候选 +2~+3；
  - 与上一张脸相同或 `near_duplicate_of` 时不给变化奖励；
  - 同脸 hold 完全合法，不做强制轮换。
- 执行层检查：face_arc 声明阶段变化，但该锚点 face id 不变且 emo/act/fx/构图都没变 → `face_stage_no_readable_change`（warning，返修提示）。任何一层有变化即视为可读变化。
- 组件距离只做候选排序软分和返修提示，不做硬规则；`eye_effect/iris_color/face_shadow` 等特殊人格信号不进软分，只做硬过滤。

### 7.3 官方使用例与盲测隔离

- 离线表情标注允许读取该 face 在官方脚本中的完整上下文，用来形成眼/眉/嘴组件标签、人格范围和语用摘要；这是资产证据，不是运行时答案。
- 运行时排序使用 `official_usage_profile` 聚合统计，并可从训练集合检索 1-2 条去身份化、非同章节的短例子。严格盲测按章节/活动划分 holdout，禁止注入目标场景或同章节原句，而不是把所有官方例子一律删除。
- 评估 Agent 可以事后读官方资料；逐句答案只进评估报告，不写回生产提示词。

### 7.4 身份差分保证

分层防护，任一层都不依赖语义相似度：

1. `annotate._IDENTITY_FACE_BLOCKLIST`（爱丽丝 12/14-19）。
2. `face_label_backend.is_persona_face_blocked`（候选第一轮丢弃）。
3. `resolve_backend_label` 的 blocking flags（`persona_scope_blocked / special_visual_requires_special_class / candidate_conflicts_with_*`）。
4. `annotation_safety.filter_annotation_row` + `validate_chunk_response/_validate_beats` 运行时兜底。

### 8.2 安全约束 vs 经验建议

真正安全约束（后端兜底）：

- 不改台词；资源白名单；最多三人；有立绘说话者必须在自己的对白画面；Wait 只在无对白 beat；cut 必须完整镜头；cut 不与 enter/exit/reveal 同拍；无对白 beat 继承 face；关系距离只在双人；特殊身份差分硬过滤。

经验建议改为可推翻的软提示：

- 原“特写稀少”改为：
  > 特写的必要条件是：主体单一、本拍确为峰值或关键细节、上一拍未提前释放。判断依据是语义和镜头主体，不是数量。
- 原“连续强句峰值后置”改为：
  > 同属一条升级链的连续强句，峰值落在语义真正完成升级的那句；后句可能是余波、解释或回落，此时峰值在前句。对这类升级链标出 peak 和 release，不把所有相邻感叹句都强行套进模板。
- 原“保持镜头优先”改为：
  > 同一互动轴内保持或 reframe；互动轴、完整拍摄小组、焦点承受者或戏剧拍点改变时主动 cut。说话者改变本身不触发 cut，也不禁止 cut。
- 删除“同一 face 不重复输出”这类会被读成轮换的句子；同一情绪阶段允许自然 hold，阶段改变时要求 face 或其他表演层出现可读变化。
- 新增无对白默认处理表述：
  > 无对白反应拍默认继承上一拍 face；共同反应/听者反应/身体反应拍必须有 face 变化、动作、气泡、走位或镜头变化中的至少一种可读承载；“……”类无语拍优先考虑 `[沉默]` 气泡与无语/窘迫类 face。

### 9.1 修复责任边界（新增）

质量门的 `resolution` 只描述发现问题后的处理责任，不是新的演出规则：

| `resolution` | 后端可以做什么 | 后端不能做什么 |
|---|---|---|
| `deterministic` | 修复无歧义的协议/语法问题（例如把已注册动作 `<jump>` 纠正为 `{jump}`，删除无对白 `(00)` 占位） | 不替 AI 选择表情、动作、镜头审美 |
| `ai_repair` | 保留失败 source/beat 的精确范围，要求 AI 重新判断语义；未失败行冻结 | 不用固定短语或“镜头密度”猜测替换 |
| `block` | 阻止生成/安装，保留 provenance 供人工或 AI 修复 | 不通过删人、强行改槽位来掩盖三人以上、重叠或说话者缺失 |

特别是 `[A,B] -> [A,C]` 这类硬切/移动争议，后端只能检查空间连续性并报告 `ai_repair`；是否完整硬切、同镜移动还是显现，必须由 AI 根据事件计划和文本证据决定。这样可以增加安全约束而不牺牲泛化能力。

返修输出协议：合成 chunk 只含失败 source_ids 与 ±3~5 行上下文；模型只返回这些行的 lines/beats；未失败行不发送、不覆盖、不重写。G3 的 `critical/high` 返修仍失败时，不得自动安装正式工程。

### 9.4 G3 provenance 与真实编译产物

1. `_validate_beats` 首次接收 beat 时分配持久 `beat_id`。已有 beat 返修必须原样返回该 id；新增 beat 才由后端生成新 id。禁止使用会随插入/删除变化的 `anchor:position:ordinal` 作为身份。
2. `render_annotated_items` 改为同时返回文本和 trace；trace 覆盖每条生成的指令行与角色行，并记录 `source_id / beat_id / scene_id / plan_event_ids / chunk_id`。sidecar 必须保存 `annotated_source_sha256`，哈希不一致时拒绝沿用旧映射。
3. `Pending.origins` 收集被下一条 line 消费的 `@camera_cut/@move/@reveal/@enter/@wait/@fx...`；`scripts.append` 暂存 `_trace`。G3 完成后统一剥离 `_trace` 再 `wrap_project`，不污染 AAP。现有 `_explicitFxEnds/_sceneReset` 继续由 `performance_rules` 消费，不重复处理。
4. G3 issue 必须同时给 `script_index / source_id / beat_id / plan_event_ids / before_signature / after_signature / origins`，让返修落回 IR，而不是直接篡改最终 AAP JSON。

### 9.5 checkpoint v3 与状态重放

事实源不是 `memory`，而是按实际执行顺序保存的：

```text
chunk_outputs[chunk_id] =
  scene_id + target_ids + lines_by_id + beats_by_id
  + state_delta + memory_events + base_input_hash
```

- `memory` 只是可重建缓存。`base_input_hash` 对首次请求的固定 system、volatile、基础 user、schema、模型/提示词版本做 canonical hash；不包含重试错误文案。
- 重放从 `initial_memory` 开始；只在 `scene_id` 变化时调用 `complete_scene`。每个有效 chunk 严格按生产顺序执行 `apply_state_delta → _interleaved_director_events/_merge_director_rows → merge_memory_events`。
- G3 patch 只更新事实源。到达第一个输入 hash 不一致的 chunk 时停止使用其旧输出，将该 chunk 置 pending；重跑成功后继续向后重放。若后续输入重新收敛到相同 hash，可复用其旧输出，否则顺序重跑。
- 新 checkpoint 只在 rows、beats、chunk_outputs、重建 memory 和 hashes 全部一致时原子提交。失败保留旧 checkpoint；不得留下“完成 id 已更新但状态未更新”的半提交。

## 10. token 与成本方案

1. **static 不嵌 SOURCE_SCRIPT**：Agent 路径 `annotate.py:1426-1430` 用 `source_context_strategy="window"`。static 变为“规则 + cast + 候选资源”，同 cast/story_type 下可跨 chunk、跨剧本命中缓存。
2. **第一阶段只发一次、只发台词**：`build_scene_planner_request` 保持轻量，不带资源表。
3. **第二阶段用自适应检索短名单**：先返回少量高置信候选；语义歧义、候选近似或角色阶段变化明显时自动扩展。检索条数用于减少无关资源，不是艺术配额、字符预算，也不得把正确候选截掉。
4. **事件计划投影**：`relevant_scene_events / project_scene_event_plan` 只发当前 chunk 相关事件切片和前后事件摘要。
5. **返修只发失败切片**：不重发整 chunk；每 chunk 最多 1 次返修。
6. **不设硬字符预算、不降低最大输出 token**：`estimate_chunk_output_budget` 继续使用配置的 `annotation_max_tokens`；`grow_chunk_output_budget` 只在容量错误时向上增长到配置上限。
7. 56 句样本的观测预期约为 1 次计划、若干次自适应执行和必要的局部返修；调用数只用于遥测成本，不作为正确性验收或固定分块配额。
8. 可选 `--no-scene-plan`：跳过第一阶段，退回单阶段 + 完整 G2/G3 安全内核；这是显式成本开关，不是默认路径。

## 12. 盲测验收标准

生成 Agent 不得读取 V4、官方命令流或隐藏评估答案；评估 Agent 可事后读官方资料，但不得把逐句答案写回生产提示词。

1. **结构零错误**：三层质量门 pass；无默认脸空节点、无空 Wait、无多人特写、无 `[A,B]→[A,C]` 原位换人、无越界/重叠、说话者可见。
2. **计划不再逐句机械化**：连续同组、同焦点、同景别且无新语义变化的 shot 不重复声明；只有场景确实需要无对话框表演时才要求 performance beat，不设置数量配额。
3. **计划兑现**：`event_plan_fulfillment_errors` 返回空；每个 silent beat 都满足自身 carrier_requirement，允许已声明的有目的 pose hold。
4. **峰值规范**：solo/relationship/group 三类峰值与构图一致；强效果有语义证据和明确生命周期；连续强句有 peak/release 或 scene_end 收束，不能机械把所有强句收成单人特写。
5. **表情可读变化**：连续强句之间要么 face 有可读变化，要么 emo/act/构图承接；“……”有 `[沉默]`；无语语境出现无语/窘迫类脸。
6. **镜头过渡**：加人处能看到有动机的 `@move + @reveal/@enter` 或完整 hard cut；不存在无动机 `[A,B]→[A,C]` 原位换层；合法 `anchor_match_cut` 有计划理由和编译签名证据。
7. **成本**：重复全文输入占比下降；返修请求数 ≤ chunk 数；输出 token 未被后端私自定义截断。

## 13. 最大风险与降级

1. **确定性收单人可能过度干预**：只对通过 G1 的 `solo_emphasis` 要求单人构图；relationship/group peak 不适用。后端不把不确定的艺术判断伪装成安全规则。
2. **legacy face 合并可能引入误标**：先 DB 抽样；`aa_verified` 仍需语义字段和身份范围，`aap_observed` 必须再有视觉组件语义/官方证据才可使用；人格硬过滤优先于一切相似度。
3. **返修导致成本上升**：每 chunk 最多 1 次；返修只发失败切片；仍失败可继续生成带报告草稿，但 `critical/high` 不得自动安装。
4. **返修后仍“合法但平庸”**：以“计划兑现率”而不是数量配额衡量；兑现率高时至少保证 AI 规划的高价值拍点不丢失。
5. **极端降级路径**：
   - AI 导演反复几何错误 → 降级 AI 辅助；
   - AI 辅助仍不稳定 → 降级稳定后端；
   - critical/high G3 未解决 → 阻止正式安装并输出红字报告；可保留草稿供人工检查，但不得显示 PASS。
