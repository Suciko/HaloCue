# 0.9x 盲测迭代因果策略

> 持久化交接入口：继续任务时先读仓库根目录的 `AGENTS.md`，再按本文件的因果审查顺序检查真实输出。这里记录的是长期策略，不代表任何一轮已经完成。

## 目的

盲测处理的是模型未见过的新文本和新叙事方式。官方演出资料是目标和参照，不是可直接套用的事件链答案。相似官方片段只能帮助模型理解演出语法和因果关系，不能复制其节点顺序、镜头数量或角色安排。

## AI 应先回答的问题

对每个台词或无对白节点，优先记录以下因果链：

`上文刺激 -> 当前承受者/说话人 -> 情绪和身体反应 -> face/emo/act/bubble -> 构图与镜头时机 -> 下一节点继承的状态`

静默节点只有在对白无法独立展示的新信息存在时使用，例如入场被看见、发现物体、操作反馈、关系反应、情绪余波或短暂的决定停顿。静默节点不是数量配额，也不是为了满足协议而插入的空 Wait。

## 三层审查顺序

1. **文本因果**：当前反应是否由上文触发，结果承受者和余波承受者是否合理，跨 chunk 的物理存在、可见人物和位置是否连续。
2. **表演因果**：face、emo、act、bubble 是否表达语义和标点要求，阶段变化是否真的落地；多个不同表演意图不能整段塌缩成 face-only。
3. **镜头因果**：镜头是否表达互动关系、信息揭晓或情绪峰值；完整硬切可以在关系轴改变时出现，不得为了 hold 计划强行保留旧构图；无解释的瞬移和非完整 reframe 仍需拒绝。

## 后端边界

后端只处理协议解析、资源合法性、角色身份和装束、状态生命周期、槽位/几何安全、单镜最多三人、格式修复和可证明的重复指令去重。后端不得代替 AI 决定审美、节奏、表情阶段、镜头意图或静默节点数量，也不得静默删除 AI 明确返回的决定。

## 官方对照方法

生成完成后再对照官方命令流、视频解析和人工标注。逐段记录“官方展示了什么视觉/听觉新信息、模型是否用等价方式表达、差异属于顺序/承受者/表演资源/镜头关系/连续性哪一层”。不以官方节点数量或固定事件顺序作为通过条件。

## 退化诊断

- 原始 AI JSON 已缺少或误解因果：改提示词、场景计划或模型调用。
- 原始 AI JSON 正确但 compact/validate 后消失：改协议或校验。
- 原始 AI JSON 正确且通过，但最终 AAP 缺字段或状态断裂：改后端策略/编译器。
- 内部质量分上升但官方差距不缩小：不保留该改动，优先检查是否过度迎合硬限制。

## 运行闭环

每次得到新 AAP 后，必须同时完成三件事：

1. 读取真实 AAP、model-audit 和原始响应，确认字段和状态没有在链路中无原因消失。
2. 对照对应官方命令流、视频解析和最新人工标注，记录逐段差异，并给出可复核的评分或分层判断；内部 quality 分不能代替官方差异。
3. 如果分数下降、差异扩大或视觉上出现关系镜头/连续性退化，回到导致退化的层级修复，必要时只重试对应 request，然后重新编译和评估。三场景必须使用同一轮版本号，三段都评估后才保留改动。

除非存在明确且连续复现的外部阻塞，不在中间状态停下来等待用户选择；目标是持续迭代到拥有真实 AAP、完整审计链和可人工审查差异报告的版本。

每个版本必须保留原始请求、原始响应、协议展开、validate、策略应用、AAP trace 和 model-audit；三场景同一轮使用统一版本号，但各自独立 source_id、checkpoint 和结果目录。
