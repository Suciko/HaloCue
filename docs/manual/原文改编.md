# 把 TXT / DOCX 原文改编成场景

适用范围：包含“原文改编工作台”的集成写作界面或独立写作服务。
如果当前程序只显示兼容制作界面、没有下述按钮，不要按本页猜测操作；
这不是对旧版安装包入口的说明。新功能尚需随修复分支整体验收后再发布。

## 1. 保存原文，不调用模型

- 尚未建立作品时，点击“导入已有内容”。已有作品时，展开创作对话输入区的
  附件菜单，点击“导入小说 / AAP”。选择 TXT 或 DOCX 后进入改编工作台。
- 要接着处理以前的原文，在同一个导入窗口点击“继续原文改编”。
- 选择“连载中”或“已完结”，填写本次提供范围，点击“预览原文变化”。
  没有作品时，这一步会建立一个空白作品，但不会调用模型或生成正式正文。
- 核对章节与变化后，点击“确认保存原文”。原文件与来源记录会保留。
- 已有原文可以追加章节，或选择“更新选定旧章节”。更新按**原文显示顺序**
  对应文件里的章节，勾选顺序不改变对应关系；数量不一致会要求重新确认。

文件输入上限为 16 MB。能导入文件不等于整章一定装得进模型上下文：
长章节仍可能受所选模型的输入限制影响，当前尚未提供完整的 token 预算保证。
AAP 不走本流程，仍保留工程预览、附件及 Agent 转换流程。

## 2. 确认计划，再逐章生成

1. 在“计划”页选择本次章节；需要时填写“原名 = 目标名”的人物称呼映射。
2. 设置候选调用上限，点击“建立改编计划”，检查范围和规则后点击“确认计划”。
   建立和确认计划本身不会调用模型。
3. 在“候选”页核对当前模型。模拟模式只用于测试，不能当作真实改编质量。
   使用真实模型时，生成会发送选定原文章节并产生用量。
4. 点击某一章的“生成模拟候选”或“使用当前模型生成候选”，才会开始本轮生成。

界面中的调用数是**逻辑候选尝试次数**，不是完整 token 或费用账单。
失败的已尝试请求仍可能消耗额度；传输层重试也可能产生额外请求。
达到上限后，请重新评估范围再建立新计划，不要把重新建计划当作零成本重试。

## 3. 检查候选和目标场景

展开“原文依据与待确认内容”，检查引用、偏离说明和未决内容。
下方会明确标出“新建场景”或“替换已关联场景”及目标章节。

- 点击“采纳到此场景”后，才会建立普通场景正文修订。
- 冒号、空行等格式会按场景编辑器归一化；原候选和原文引用仍保留。
- 采纳后点击“查看正式场景”，继续手动编辑、审核和发布。
- 当前不支持在候选生成后任意改投另一个已有场景。目标或正文变化时，应
  重新查看并生成，不要通过重复点击绕过冲突。
- 旧版待采纳候选需要“确认目标并采纳旧候选”；旧版已采纳稿则选择章节后
  点击“确认把旧稿放入场景”。原稿保留，重复网络请求不会再建一份。

## 4. 停止、重试和重新打开

关闭窗口不等于停止任务。需要停止时，点击该章的“停止本轮”。
取消不会强行终止已经发出的远程请求，但晚到结果不会写入候选或正文。

重新打开工作台会读取已保存计划、运行状态和候选，不会自动重复生成。
可重试的失败会提供“重试固定输入”；配置、原文、目标变化或旧任务缺少目标时，
应确认当前条件后重新生成，而不是不断重试旧快照。发生网络读取失败时，
点击“刷新状态”核实结果，避免把未收到响应等同于未执行。

## 5. 正文采纳不等于发布完成

原文导入不会替你编造正式创作方向。点击“完善写作方向与发布条件”，
会回到创作对话并预填一段方向整理请求，**不会自动发送**。
在对话中讨论、整理并采纳故事方案后，再完成正常的场景审查、记忆维护决定、
连续性审查和发布审查，才能冻结并交给 AA 制作。

冻结、编译、安装和真实 AA 播放仍是后续步骤；看到候选或通过软件测试，
不代表作品已经通过真实模型质量或播放验收。
