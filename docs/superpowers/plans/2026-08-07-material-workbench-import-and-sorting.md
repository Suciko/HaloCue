# Material Workbench Import and Sorting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a unified material import dialog to the full-screen workbench and make growing historical libraries findable through reliable import-time sorting and source metadata.

**Architecture:** Preserve the current story-scoped registration model: all new materials are registered into the active story first, then appear in the aggregated workbench. Add server-owned registration timestamps to `asset_install`, aggregate them in the existing library response, keep sorting and selection in `library.js`, and isolate dialog orchestration in a new `library_import.js` that reuses `StoryAssets`, `StoryFilePicker`, and `HistoryDrawer` instead of duplicating their state machines.

**Tech Stack:** Python 3, SQLite, stdlib HTTP server, vanilla JavaScript, HTML/CSS, pytest, Node VM tests, Playwright.

## Global Constraints

- Support only `character`, `background`, and `sound`; custom BGM remains unavailable.
- New material timestamps are generated by the server as UTC ISO 8601 values; browser-supplied timestamps are ignored.
- Legacy records without a reliable timestamp remain empty and display as `导入时间未知`; migration time and filesystem mtime must not be presented as import time.
- Import, validation, registration, copying, and task recovery continue through the existing story-scoped APIs and opaque tokens.
- API responses must not expose `source_path`, `install_path`, `scope`, AA data paths, or host filesystem paths.
- Opening the workbench without an active story remains read-only; import, scan, and copy actions are disabled.
- Import completion refreshes both current-story assets and the workbench, preserves the selected sort mode, and selects/scrolls to the imported material.
- Preserve existing user edits in the dirty worktree; stage and commit only files named by each task.
- Keep CSP compliance: no inline event handlers, `eval`, or untrusted `innerHTML`.

---

- `js/library.js`: sort state, stable comparison, time/source rendering, imported-item selection.
- `js/library_import.js`: unified import dialog controller and adapters to existing import/history/picker controllers.
- `js/assets.js`: expose completion notifications and accept opaque picker selections without duplicating task logic.

- `css/layout.css`: workbench sort row, metadata line, import dialog, embedded history, responsive rules.
