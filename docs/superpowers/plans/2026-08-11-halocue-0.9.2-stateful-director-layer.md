# HaloCue 0.9.2 Stateful Director Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade HaloCue's annotation pipeline so an AI annotates unwritten AA direction from a stateful, official-style directing model while preserving source dialogue byte-for-byte and compiling only deterministic, validated annotations into a legal `.aap`.

**Architecture:** Add a small `director_state.py` domain module that owns the vocabulary, defaults, normalization, and diagnostics for scene type, scene function, focus, relationship distance, emotion phase, and continuity. Extend the existing annotation protocol and checkpoint memory with optional wire-compatible director metadata; after validation, apply that metadata to source items and translate only safe focus/lifecycle decisions into `@camera` and `@fx` directives. Keep prompts responsible for interpretation, keep Python responsible for resource/state/AA contracts, and keep official material offline and abstracted into rules rather than searchable dialogue.

**Tech Stack:** Python 3, existing `pytest` suite, JSON Schema-like provider schemas, existing `annotate.py` -> `annotation_agent.py` -> `script2aap.py` pipeline, AzureArchive `.aap` serializer.

## Global Constraints

- Input is a completed screenplay with no AA annotations; AI may add `(face)[emo]{act}<fx>`, `@...`, and necessary dialogue-free beats only.
- AI must never rewrite, delete, insert, or polish source dialogue; every annotated row remains tied to its source identity and text fingerprint.
- Official main/event/bond material is used only for offline-derived directing rules and self-authored regression fixtures; do not copy or emit official dialogue or full scenes.
- Face IDs are scoped by `character_id + outfit_key + spine_signature`; only `visual_confirmed` and `asset_semantic` evidence may drive automatic selection. `context_inferred` is research-only and must produce a review diagnostic.
- Existing AA syntax and `.aap` output remain compatible; new internal metadata must not enter dialogue text.
- Invalid or unprovable choices degrade to empty/default values plus a diagnostic; they must not silently change source order or text.
- Every task below uses TDD, runs its focused test before and after implementation, and ends with its own commit.

## File Map

- Create `director_state.py`: enums, bounded metadata shape, normalization, continuity transition helpers, and diagnostic codes.
- Modify `annotation_protocol.py`: add optional director metadata and beat reasons to complete and compact schemas; expand and validate to one canonical shape.
- Modify `annotation_memory.py`: persist scene type and director continuity, expose them in chunk context, and bump memory/checkpoint fingerprint versions.
- Modify `annotation_agent.py`: pass director context through chunk requests, save it in checkpoints, and merge validated per-line metadata without losing resume safety.
- Modify `prompt.py`: replace the “change face every line” rule with the nine scene functions, main/event/bond priorities, focus selection, emotional chains, and hold/start/escalate/end semantics.
- Modify `annotate.py`: apply validated director metadata, emit safe `@camera`/`@fx` lifecycle directives, retain review diagnostics, and make post-processing continuity-aware.
- Modify `camera.py`: accept explicit per-line visible/focus sets, listener/group/offscreen decisions, empty shots, and deterministic fallback to the existing automatic policy.
- Modify `script2aap.py`: parse one-shot `@camera` directives and use them to override the automatic shot list for exactly one compiled line.
- Modify `direction_rules.py`: preserve explicit continuity and delete only unsupported mechanical repetition; keep automatic supplements conservative.
- Modify `performance_rules.py`: give persistent closeups/communications explicit start, hold, and end semantics.
- Modify `asset_catalog.py` and `annotate.py` face constraint plumbing: expose evidence level and variant scope without promoting inferred semantics.
- Modify `webui.py` request option plumbing: accept `story_type` (`auto`, `main`, `event`, `bond`) and pass it to annotation; default remains `auto` for existing callers.
