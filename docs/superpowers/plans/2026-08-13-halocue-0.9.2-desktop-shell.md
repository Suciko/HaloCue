# HaloCue 0.9.2 Windows 桌面版实施计划

**目标：** 交付双击 `HaloCue.exe` 即显示独立窗口、无需系统 Python、不打开外部浏览器的一目录 Windows x64 便携包，并消除“全部标记已审”对浏览器原生确认框的依赖。

**架构：** 保留现有网页前端和回环 HTTP API。新增一个可测试的本地服务生命周期接口和 pywebview 桌面入口；冻结版将只读资源放在 PyInstaller 资源目录，将数据库、配置、日志和缓存放入 `%LOCALAPPDATA%\HaloCue`。审核批量确认改用现有模态框体系内的应用内对话框。

## 切片 1：应用内批量审核确认框

1. 添加行为测试：打开、取消、Esc、确定、重复确定、失败恢复和焦点返回。
2. 运行测试并确认旧 `window.confirm()` 实现失败。
3. 在 `ui.html` 中添加可访问的确认框，在 `js/app.js` 中拆分“请求确认”和“执行批准”，补充最小样式。
4. 运行相关 Node/pytest UI 测试和审核 API 测试。

## 切片 2：可控的本地服务生命周期

1. 添加公开接口测试：服务启动后可访问健康接口，`stop()` 后端口释放，关闭非自有服务不会发生。
2. 将 `webui.py` 的服务器创建、后台启动、前台运行和关闭收口到小型生命周期对象，保留原命令行行为。
3. 运行 HTTP、启动器和服务生命周期测试。

## 切片 3：桌面窗口入口

1. 添加桌面入口行为测试：就绪后创建窗口、传入正确 URL、不调用外部浏览器、窗口退出后关闭自有服务、WebView2 缺失时返回可读错误。
2. 新增 `desktop_app.py`，通过边界注入测试窗口运行器；发布环境使用 pywebview/Edge Chromium。
3. 让 `launcher.py` 的发布入口转入桌面模式，同时保留源码浏览器诊断入口。
4. 运行桌面入口和启动器测试。

## 切片 4：冻结资源和用户数据路径

1. 添加路径测试：源码模式不变；冻结模式将只读资源和可写用户状态分离；首次启动复制种子数据库；中文和空格路径可用。
2. 新增统一运行布局模块，并让 `launcher.py`、`aapaths.py`、`webui.py` 使用它。
3. 确保 `aa_config.json`、模型配置、数据库、日志、缩略图、上传文件和中间产物写入用户状态目录。
4. 运行路径、模型配置、设置、素材库和主要工作流回归。

## 切片 5：构建与实包验收

1. 添加构建清单测试，要求 EXE、HTML、JS、CSS、图标、数据库和说明存在，并拒绝私人配置、缓存、测试输出和素材扩展名。
2. 新增 PyInstaller spec 和 PowerShell/Python 构建入口；使用独立 `.venv-desktop-build` 安装固定打包依赖。
3. 构建 `HaloCue-0.9.2-windows-x64/` 和同名 ZIP。
4. 在无源码工作目录、中文空格路径和隔离用户数据目录下运行 `--check`、HTTP 冒烟和桌面启动检查。
5. 实际打开打包后的 WebView2 窗口，验证“全部标记已审”对话框的取消、Esc、焦点和单次提交行为。
6. 对最终目录执行密钥、私人配置、绝对开发路径和禁止素材扫描；记录 SHA-256。

## 完成门槛

- 相关测试和完整可运行测试集通过；
- `HaloCue.exe` 不需要系统 Python，不打开系统浏览器，不出现命令行窗口；
- 窗口关闭后自有端口释放；
- 批量审核确认不会取消误提交或重复提交；
- ZIP 可从中文空格路径解压运行；
- 最终内容扫描无密钥、私人配置、开发路径和禁止素材。
