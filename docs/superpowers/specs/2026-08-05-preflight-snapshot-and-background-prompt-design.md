# AI 初审快照与背景提示词入口设计

## 目标

1. 历史剧情重新打开时恢复最近一次 AI 初审判断，避免无意义地重复调用模型。
2. 原文变化后保留旧判断供参考，但不得把旧判断当成当前有效结果。
3. 官方背景最高匹配低于 90% 时，稳定显示网页端“生成生图提示词”入口。
4. 收紧背景卡片的视觉层级，让官方候选和自定义背景操作各自清晰但不过度占位。

## 初审快照

每个剧情历史记录保存一份最近成功完成的初审快照。快照包含：

- 完整、可公开给浏览器的初审结果；
- 原文指纹，包括文件大小、修改时间和内容 SHA-256；
- 初审完成时间；
- 是否已经由用户确认。

快照不保存 API 密钥、本机绝对路径或模型请求的内部诊断内容。写入沿用历史索引的原子替换机制。

## 保存与恢复

- 后台初审任务成功后，服务端立即保存快照。
- 用户确认初审后，服务端更新快照的确认状态。
- 从历史记录打开剧情时，当前剧情 API 一并返回快照及其新鲜度。
- 原文指纹一致时，前端直接恢复角色映射、场景规划、素材问题和确认状态，不自动重新调用 AI。
- 没有快照时，保持现有行为并启动初审。
- 原文指纹不一致时，前端显示旧结果和“原文已变化，请重新初审”，禁止直接使用旧结果进入生成步骤；用户点击“重新检查”后生成并保存新快照。

## 背景提示词入口

当背景未准确命中，且官方候选最高匹配度低于 90% 时，卡片显示紧凑的“自定义背景”折叠行。展开后依次提供：

1. `生成生图提示词`：主操作，固定存在；
2. `导入生成结果`：导入用户在外部工具生成的图片；
3. `从历史导入`：复用历史剧情背景；
4. `打开素材工作台`：进入完整素材管理流程。

点击“生成生图提示词”打开现有可编辑弹窗。提示词由场景名、原文证据、地点和演出理由生成，包含横向 16:9、无人、无文字、无水印等约束。弹窗提供“复制提示词”和“导入生成结果”，形成连续工作流。

后端必须为所有符合条件的背景返回 `generation_prompt`。前端同时根据背景需求字段生成保底提示词，避免旧快照或兼容数据导致按钮消失。匹配度达到 90% 时不显示整个自定义背景区。

## 界面层级

- 删除当前醒目的大框标题样式，改为带展开状态的紧凑操作行。
- 官方候选保持为主要内容；自定义背景操作使用较弱背景和清晰的主次按钮。
- 移动端按钮自动换行，文字不得溢出卡片。
- 不增加新的常驻面板，也不把自定义工作流与官方候选混成同一个按钮组。

## 错误处理

- 快照读取失败时忽略损坏数据并回退到重新初审，不阻止打开剧情。
- 快照写入失败时初审结果仍返回浏览器，但显示未保存状态并允许重试。
- 提示词复制失败时保留弹窗内容并显示可手动复制的提示。
- 导入失败沿用素材导入现有错误和重试流程。

## 测试

- 注册表单元测试覆盖快照原子保存、进程重启恢复、原文未变化和变化两种状态。
- HTTP 测试覆盖初审成功保存、确认状态更新以及当前剧情返回快照。
- 前端运行时测试覆盖历史剧情恢复时不调用 AI、过期快照禁止继续以及手动重新检查。
- UI 测试覆盖低于 90% 时四个操作完整出现、90% 时隐藏、缺少后端提示词字段时仍有保底按钮。
- Chromium 响应式测试验证折叠行、提示词弹窗和移动端无横向溢出。

## 非目标

- 不在网页内直接调用图像生成服务。
- 不保存模型密钥或原始模型请求。
- 不修改 AA 的 EXE、配置、资源包、工作区文件或时间戳。
