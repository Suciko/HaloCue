# HaloCue 0.9.2 Windows 桌面外壳与便携包设计

- 日期：2026-08-13
- 状态：用户已批准，待书面规格复核
- 目标平台：Windows 10/11 x64
- 交付形式：一目录便携包及对应 ZIP

## 1. 目标

将现有 HaloCue 0.9.2 PC 端从“启动本地服务后打开系统浏览器”改为独立 Windows 应用体验。用户双击 `HaloCue.exe` 后直接进入 HaloCue 窗口，不出现浏览器标签页，也不需要安装 Python。关闭最后一个 HaloCue 窗口后，由该进程启动的本地服务必须正常退出。

本次工作只更换桌面承载和发布方式，不重写已经完成的网页界面、剧本生成流程、审核逻辑或 Python 业务模块。

## 2. 技术选择

采用 `pywebview + Microsoft Edge WebView2 + PyInstaller one-directory`：

- `pywebview` 创建带 HaloCue 标题和图标的独立 Windows 窗口；
- WebView2 只作为窗口内部的渲染组件，不启动 Edge 浏览器应用；
- 现有 `ThreadingHTTPServer` 继续仅监听 `127.0.0.1`；
- PyInstaller 将 Python 运行时、Python 模块、前端静态资源和运行依赖打入一目录便携包。

不采用 Electron，因为它会额外引入 Node.js 和整套 Chromium，显著增加包体和构建链。不采用 WinUI/WPF 重写，因为这会重复实现现有前端并扩大 0.9.2 的回归面。

Windows 11 和仍受支持的常见 Windows 10 环境通常已有 WebView2。启动器必须显式检测 WebView2；缺失时显示中文错误说明，而不是静默失败、打开系统浏览器或显示 Python 堆栈。本次便携包不捆绑完整 WebView2 Fixed Version Runtime，以控制包体；发布说明列出 Microsoft WebView2 Runtime 为系统前提。

## 3. 架构与组件

### 3.1 桌面入口

新增桌面入口模块，负责：

1. 执行现有环境检查和 AA 安装/工作区发现；
2. 在后台线程中启动本地 HTTP 服务；
3. 等待健康检查成功后创建桌面窗口；
4. 将窗口导航到实际分配的回环地址；
5. 在窗口关闭时停止由当前进程拥有的服务并清理资源。

发布版入口直接导入并调用服务模块，不再通过 `sys.executable webui.py` 启动子进程。源码开发模式保留浏览器入口和 `--no-browser` 诊断参数，但普通用户入口不得调用 `webbrowser.open()`。

### 3.2 服务生命周期

服务绑定 `127.0.0.1`，优先使用既有端口策略。桌面窗口只能在健康检查成功后显示正式页面；启动超时或端口异常时显示可读错误并退出。

桌面外壳记录服务所有权：只有当前进程创建的服务才会在窗口关闭时被它停止，避免误停其他 HaloCue 实例或占用相同端口的其他程序。服务关闭使用 `shutdown()` 和线程回收，不依赖强制终止 Python 进程。

### 3.3 窗口行为

- 默认创建一个主窗口，标题使用 `HaloCue 0.9.2`；
- 设置合理的最小尺寸，初始尺寸适配常见 1080p 桌面；
- 使用 HaloCue 原创图标；
- 不显示命令行黑窗口；
- 页面内部链接、文件选择和下载行为在 WebView2 中完成或交给明确的 Windows 系统对话框；
- 页面加载失败时显示应用内错误页，不回退到外部浏览器。

## 4. “全部标记已审”确认框专项设计

当前 `approveAll()` 使用 `window.confirm()`。该原生 JavaScript 对话框在嵌入式 WebView、不同浏览器实现以及窗口焦点切换时存在行为差异，因此桌面版不再依赖它。

“全部标记已审”改用 HaloCue 页面内的受控确认框：

- 点击按钮只打开确认框，不立即调用 `/api/review/approve`；
- 确认框明确显示操作对象是“当前草稿的全部卡片”；
- “取消”、`Esc`、关闭按钮和点击允许关闭的遮罩都只关闭确认框，不发送请求；
- “确定”后立即锁定确定按钮和原工具栏按钮，显示处理中状态；
- 同一次确认最多发送一个批准请求，连续点击、双击和按两次 Enter 都不得重复提交；
- 请求成功后关闭确认框、刷新草稿并恢复按钮状态；
- 请求失败时保留可读错误，允许用户关闭或重试，但重试必须形成一次新的显式操作；
- 确认框始终位于 HaloCue 主窗口内容最上层，并正确管理焦点：打开时焦点进入确认框，关闭后返回“全部标记已审”按钮。

后端继续通过 `expected_draft_version` 和单事务 `batch_approve_reviews()` 保证版本一致性。桌面外壳不改变审核 API 语义。

## 5. 打包与运行布局

产物目录命名为 `HaloCue-0.9.2-windows-x64/`，对应压缩包为 `HaloCue-0.9.2-windows-x64.zip`。目录入口为 `HaloCue.exe`，至少携带：

- 冻结后的 Python 运行时和所需依赖；
- 全部实际运行模块；
- `ui.html`、`js/`、`css/`；
- HaloCue 图标资源；
- 发布所需的素材标注数据库；
- 使用说明、版本信息和第三方许可证。

用户配置、日志和缓存写入 `%LOCALAPPDATA%\HaloCue`；程序不得依赖开发机盘符、用户名或当前工作目录。便携目录可以放在含中文、空格和较长路径的位置。用户剧本和 AA 工程仍按现有逻辑写入用户选择的工作区。

构建不得包含 API Key、`llm.json` 私人配置、`aa_config.json`、开发缓存、测试输出、用户剧本、AA 工程、骨骼、贴图、音频或其他游戏素材。

## 6. 错误处理

- 缺少 WebView2：显示中文说明和缺失组件名称，然后退出；不打开浏览器；
- AA 工作区未发现：沿用现有 Windows 选择流程；取消选择时安全退出；
- 本地服务启动失败：显示端口或初始化错误的用户化摘要，详细信息写入用户日志；
- 页面健康检查超时：停止当前进程拥有的服务并提示重试；
- 页面运行错误：写日志并在窗口中显示可恢复提示，不暴露完整本机路径或密钥；
- 打包资源缺失：启动检查直接失败并指出损坏的发布包文件。

## 7. 验证与发布门槛

### 7.1 自动测试

- 桌面入口在服务就绪前不创建正式窗口；
- 窗口关闭会停止自有服务，不会停止非自有服务；
- 发布入口不调用 `webbrowser.open()`；
- PyInstaller 资源清单包含全部运行模块、HTML、JavaScript、CSS、图标和数据库；
- 发布目录在没有系统 Python 的环境中可以启动；
- 发布扫描不含密钥、私人配置、绝对开发路径或禁止素材；
- “全部标记已审”取消路径发送零次请求；
- 确定路径只发送一次请求，双击和重复 Enter 仍只发送一次；
- 请求成功、失败和版本冲突均能解除忙碌状态并给出正确反馈；
- 焦点进入确认框并在关闭后返回原按钮。

### 7.2 WebView2 实机验收

必须在打包后的 `HaloCue.exe` 内完成真实 WebView2 检查，不能只用 Node 单元测试或外部 Chromium 代替：

1. 打开一个含待审卡片的草稿；
2. 点击“全部标记已审”，确认弹窗位于应用窗口最前且可操作；
3. 分别验证取消、`Esc` 和关闭按钮不会改变草稿；
4. 验证确定后只提交一次，待审计数归零且草稿版本只按后端契约更新一次；
5. 在确认框打开时切换到其他 Windows 窗口再切回，确认框仍可见、可聚焦；
6. 验证窗口关闭后回环端口释放，重新启动可以正常进入；
7. 验证整个过程没有打开外部浏览器，也没有出现黑色命令行窗口。

### 7.3 便携包冒烟测试

将 ZIP 解压到带中文和空格的全新目录，使用合成 AA 工作区完成启动、选择剧本、打开页面、审核确认和正常退出。测试环境不得依赖源码目录或系统 Python。只有自动测试、真实 WebView2 专项验收和发布内容扫描全部通过，才交付 0.9.2 便携包。

## 8. 非目标

- 不把整个界面重写为 WinUI、WPF 或 Qt；
- 不增加自动更新器、安装器、后台常驻服务或公网监听；
- 不在本次工作中修改与桌面承载无关的生成算法；
- 不承诺兼容 Windows 7/8、32 位 Windows、macOS 或 Linux；
- 不将开发目录中未提交的 0.9.2 业务改动拆分、回退或覆盖。

## 9. 完成标准

用户解压交付 ZIP 后双击 `HaloCue.exe`，直接看到独立 HaloCue 窗口；无需安装 Python，不打开系统浏览器，不出现命令行窗口。现有核心流程可用，“全部标记已审”在 WebView2 中通过应用内确认框完成且不存在取消误提交、焦点丢失或重复提交。关闭应用后自有本地服务正常退出，发布包通过内容扫描和便携环境冒烟测试。
