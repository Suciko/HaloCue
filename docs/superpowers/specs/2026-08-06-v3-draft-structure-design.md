# V3 草稿结构与审查修复设计

## 目标

修复 V3 草稿中普通空行被渲染为卡片、Markdown `---` 分隔符被识别为 unknown、同一背景被重复切换，以及审查状态无法反映结构异常的问题。此次不修改对白、旁白或剧情内容。

## 范围

- 草稿生成/读取链路只保留有意义的内容节点；普通空行不再成为审查卡片。
- `---`、`***`、`___` 统一作为显式场景分隔节点处理，保留原文语义但不产生 unknown 诊断。
- 标注输出只在背景标识实际变化时产生 `@bg`；地点变化仍保留 `@place`。
- 自定义背景脚本引用使用稳定的 AA 键；原始文件名只用于展示和素材追溯。
- 诊断与审查接口必须报告残留 unknown 或不应出现的空节点，不能继续显示“待处理 0”。
- 当前 V3 草稿在修复后重建卡片身份和诊断，仍属于原有 V3，不创建新的剧情版本。

## 非目标

- 不改写任何剧情内容、角色对白、旁白或第 5 点所述的喜剧段落。
- 不重新选择角色表情、动作、音效或背景图片。
- 不删除源文件；源文本仍作为追溯快照保留。

## 方案

在 `document.py` 增加面向草稿的规范化步骤，解析仍保留无损节点以支持编辑回写；`DraftStore.create_draft` 和加载时的兼容路径调用规范化结果构建卡片身份与诊断。Markdown 分隔符转换成 `separator` 节点，普通空行被合并/丢弃。编译器忽略 separator，但审查 API 可以报告其数量供界面显示。

`annotate.py` 在写出连续段落时维护当前背景键，只有键发生变化才写 `@bg`。背景键由候选的 `aa_key` 提供，展示名不再直接作为脚本引用。

`diagnostics.py` 增加结构校验：残留 `blank` 产生错误，未识别 unknown 产生错误，separator 不产生错误。现有 `---` 兼容测试改为断言 separator。

## 验收标准

1. 当前 V3 的卡片列表不再出现普通空白卡片；卡片数量与非空结构行一致。
2. `---` 不再出现在 unknown 卡片中，也不产生 `line.unparsable`。
3. 同一背景连续场景不会重复生成 `@bg`，不同背景仍正常切换。
4. 结构异常会出现在 `/api/validate` 诊断中，并使审查状态显示待处理。
5. 所有新增行为有先失败后通过的自动化测试；现有测试不回归。
