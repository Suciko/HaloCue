# AA 剧本编译器：剧情工作区、共享素材与 BGM 设计

- 日期：2026-08-01
- 状态：已完成交互讨论，等待用户审阅书面规格
- 范围：现有本地 Web UI 改造、历史项目素材复用、自定义 BGM 在 AA 内播放所需闭环

## 1. 目标

把现有“生成剧本”和“自定义素材”两个割裂的功能，改成以一份剧情文件为根的一体化工作区。用户通常启动软件只处理一份剧情；这份剧情对应一个 AA 剧情工程，其全部草稿版本共享角色骨骼、背景、短音效和 BGM 素材，但每个草稿分别保存素材在具体场景或台词中的使用安排。

设计要让用户始终知道：

1. 当前正在处理哪份剧情；
2. 素材将被加入哪个 AA 剧情；
3. 导入正在进行、已经成功，还是需要处理；
4. 历史项目中的素材如何安全复用到当前剧情；
5. 当前剧情是否在 AA 中使用 BGM，以及 BGM 由谁安排。

## 2. 已确认的产品约束

1. 一份剧情源文件通常只对应一个 AA 剧情工程。
2. 同一剧情产生的全部草稿版本共享自定义素材集合。
3. 素材集合共享不等于素材使用安排共享；背景、角色、音效和 BGM 具体放在哪一行或哪个场景，仍属于各自草稿。
4. 任一时刻只有一个当前剧情工作区，不把产品做成多项目管理器。
5. 保留最近使用的历史剧情和历史项目素材复用能力。
6. 历史素材必须复制并重新登记到当前剧情，不能让当前剧情直接依赖历史工程目录。
7. 新剧情默认“在 AA 中不使用 BGM”，即编译使用 `bgmId = 999`。
8. 用户可以主动开启 AA 内 BGM，并选择 AI 自动安排或手动安排。
9. 自定义 BGM 的目标是直接在 AA 工程中播放，不生成后期剪辑配乐清单。

## 3. 非目标

本轮不做：

- 同时打开、并排编辑多个剧情；
- 独立的全局素材管理器；
- 依赖历史工程原路径的“快捷引用”；
- 后期剪辑配乐清单或时间轴导出；
- 在 AA 运行时强行写入工程；
- 未经真实 AA 播放验证就宣称自定义 BGM 已支持。

## 4. 真相源与绑定规则

### 4.1 当前剧情身份

当前剧情的绑定真相源是目标 AA 工程作用域，不是可变的网页输入框，也不是素材导入时重复填写的工程名。首次打开剧情文件时，可用文件名默认生成 AA 工程名；建立工作区后，所有导入、历史复用、编译和安装操作都从当前工作区继承工程作用域。

源文件路径只用于读取原文和展示来源。用户通过“最近使用”恢复已有工作区时，即使原始剧情文件已移动，已登记素材和已有草稿仍属于原 AA 工程；需要重新读取源文件时再要求用户定位新路径。

### 4.2 共享与隔离

| 数据 | 作用域 | 切换草稿时是否变化 |
|---|---|---|
| AA 工程身份 | 当前剧情 | 否 |
| 自定义角色、背景、音效、BGM 集合 | 当前剧情 | 否 |
| 草稿正文和卡片身份 | 单个草稿 | 是 |
| 角色绑定、场景背景、音效位置、BGM 场景安排 | 单个草稿 | 是 |
| 新草稿默认 BGM 模式 | 当前剧情默认值 | 新建时复制到草稿 |
| 编译和安装结果 | 单个草稿的内容 revision/build | 是 |

新增素材后，所有草稿都能在素材选择器中看到它；系统不得自动改写历史草稿。只有用户在当前草稿中应用素材时，才更新当前草稿的内容版本。

## 5. 信息架构

采用“A：剧情为根的一体工作区”。

```text
启动页
├─ 打开剧情文件（主操作）
└─ 最近使用的剧情（次要恢复入口）

当前剧情工作区
├─ 剧情身份与总体状态
├─ 本剧情素材带
│  ├─ 全部
│  ├─ 角色
│  ├─ 背景
│  ├─ 音效
│  └─ BGM
├─ 当前草稿和版本选择
├─ 剧情卡片审查
├─ 伪演出预览
└─ 校验、编译与安装
```

移除独立“自定义素材”工作区。没有打开剧情时，不展示可执行的素材导入入口。页面可以显示功能介绍，但不能允许产生无归属素材。

### 5.1 顶部剧情上下文条

始终显示：

- 剧情文件显示名；
- 目标 `.aap` 工程名；
- 当前草稿版本；
- 保存、审查、编译和安装状态；
- 次要的“更换剧情”入口。

“更换剧情”必须整体卸载当前剧情的草稿、素材、缺失项、预览和任务状态，然后加载新工作区。不得保留上一剧情的工程名或导入表单值。

### 5.2 本剧情素材带

素材带位于剧情上下文条下方，可收起。类型按钮只过滤同一素材集合，不创建独立页面或独立状态。

汇总文案示例：

```text
本剧情素材：角色 3 · 背景 5 · 音效 8 · BGM 4 · 待补 1
```

主要操作：

- 从本地导入；
- 从历史项目复用；
- 搜索；
- 按类型过滤。

## 6. 素材卡片与即时反馈

### 6.1 通用状态

用户选择文件或历史素材后，立即在素材带中创建对应任务卡，不等待后端全部完成才显示反馈。

```text
正在检查
→ 检查通过
→ 等待关闭 AA（需要时）
→ 正在复制并登记
→ 已可用
```

失败卡保留在原位，显示可理解的原因和下一步操作。临时 toast 只能提示操作已开始；真实进度、成功和失败必须落在对应卡片上。

### 6.2 各类卡片内容

角色卡：

- 头像；
- 显示名称；
- Spine 文件完整性；
- 表情数量；
- 表情语义解析状态；
- 来源（本地导入或复用自某历史项目）。

背景卡：

- 缩略图；
- 名称；
- 分辨率；
- 宽高比检查；
- 中文搜索标签；
- 来源。

短音效卡：

- 名称；
- 时长；
- 编码、采样率和声道；
- 原位试听；
- 来源。

BGM 卡：

- 名称；
- 时长和格式；
- 原位试听；
- 音量；
- 循环设置摘要；
- 情绪、场景、节奏等 AI 检索标签；
- 来源。

待补素材卡：

- 显示剧情缺少的内容和出现位置；
- 提供“选择当前剧情已有素材”“从历史项目复用”“从本地导入”；
- 补齐后原卡转为可用状态，不跳页、不另建无法对应的结果通知。

## 7. 历史项目

### 7.1 最近使用

启动页保留简洁的最近使用列表，用于恢复此前剧情工作区。它是恢复入口，不是常驻多项目管理界面。打开一项后，仍然只有一个当前剧情。

### 7.2 从历史项目复用素材

素材带中的“从历史项目复用”打开抽屉：

1. 左侧选择历史 AA 剧情；
2. 右侧按角色、背景、音效、BGM 展示历史项目真实登记的素材卡；
3. 用户勾选素材；
4. 点击“复制到当前剧情”；
5. 后端验证物理文件、同名冲突和目标作用域；
6. 复制到当前剧情 project/save 镜像并更新当前剧情 manifest；
7. 更新当前剧情素材目录；
8. 返回原剧情卡片并完成选择（若该操作由缺失项发起）。

复用后的卡片可显示“复用自：历史项目名”，但运行时不再依赖历史项目。移动或删除历史项目不得影响当前剧情。

## 8. 剧情卡片与素材联动

剧情审查卡片直接显示当前素材安排。例如：

```text
场景：雨夜车站
背景：等待补齐
BGM：静音
[补背景] [选择音乐]
```

```text
凯伊：我们先离开这里。
角色：凯伊约会服 · 表情：警惕 · 音效：雨声
```

点击角色、背景、音效或 BGM 时，统一打开素材选择抽屉，提供三个来源：

```text
当前剧情已有 | 从历史项目复制 | 从本地导入
```

本地导入和历史复用完成后，自动返回触发操作的卡片。若素材加入共享库成功但应用到草稿时发生版本冲突，素材仍保留在共享库；前端刷新草稿后让用户再次应用，不能回滚已经成功登记的共享素材。

## 9. BGM 设计

### 9.1 三个独立维度

音乐设置不得把不同概念混成一个下拉框。

是否使用：

- 不在 AA 中使用 BGM（默认）；
- 在 AA 中播放 BGM。

安排方式（仅启用 BGM 时出现）：

- AI 自动安排；
- 用户手动安排。

来源：

- AA 已登记、可验证的音乐；
- 当前剧情导入的自定义 BGM；
- 从历史剧情复制到当前剧情的 BGM。

### 9.2 默认静音

新剧情创建时，其剧情默认值为静音。新草稿从当前剧情默认值复制音乐模式；用户从未修改过该默认值时，新草稿仍为静音。静音模式下：

- 编译输出使用 `bgmId = 999`；
- AI 提示词不提供 BGM 候选，也不生成 BGM proposal；
- UI 不把“未安排 BGM”作为错误或待处理项；
- 已导入的 BGM 仍保留在当前剧情素材库，但不自动应用。

### 9.3 AI 自动安排

AI 只能从当前剧情已经登记并通过验证的 BGM 白名单中选择。选择依据包括场景、情绪、剧情阶段和用户标签。AI 主要在场景切换或明确的情绪转折处提出换曲，不得按普通台词频繁切换。

每个 BGM 提议必须显示：

- 应用场景或起始卡片；
- 曲目名称和来源；
- AI 选择理由；
- 试听；
- 接受、更换或设为静音。

提议属于当前草稿，遵循现有 proposal 审查和版本协议。

### 9.4 自定义 BGM 登记

本机 AA 数据已确认 manifest 包含 `BgmOverrides`，记录结构至少包含：

```json
{
  "Path": "bgms\\example.ogg",
  "LoopStartTime": "0",
  "LoopEndTime": "0",
  "LoopTransitionTime": "0",
  "LoopOffsetTime": "0",
  "Volume": "1"
}
```

普通用户导入时默认整曲循环并使用音量 1。循环起止、过渡、偏移和音量放入卡片的高级设置，不作为首次导入必填项。

当前程序只初始化和保存 `BgmOverrides` 数组，尚无 BGM 专用验证、复制、登记与 `bgmId` 映射实现。实施前必须通过一次受控 AA 原生导入差异实验确认：

1. AA 如何从 `BgmOverrides` 条目得到可写入脚本行的 `bgmId`；
2. 项目和 save 镜像所需的真实目录结构；
3. 支持的文件格式和编码；
4. 循环字段的单位与默认语义；
5. 关闭并重启 AA 后仍能播放。

验证结论进入自动化测试夹具后，才能开放前端“已可用”状态。

## 10. 关键数据流

### 10.1 打开剧情

```text
选择源文件
→ 创建或恢复 AA 工程作用域
→ 加载共享素材
→ 加载草稿列表和最新草稿
→ 分析剧情
→ 渲染素材带、审查卡片和预览
```

### 10.2 从本地导入素材

```text
当前剧情上下文
→ 原生文件选择器
→ 立即创建任务卡
→ 验证
→ 确认 AA 已关闭
→ 原子复制到 project/save
→ 原子更新两个 manifest
→ 更新当前作用域素材目录
→ 卡片转为已可用
→ 可选：应用到发起操作的草稿卡片
```

### 10.3 从历史项目复用

```text
选择历史项目和素材
→ 读取历史 manifest 与物理文件
→ 作为新导入源执行同一验证/注册事务
→ 当前剧情获得独立副本
→ 历史来源仅作为审计信息
```

### 10.4 编译

```text
当前草稿内容快照
+ 当前剧情作用域素材白名单
+ 草稿 BGM 模式和场景安排
→ 校验引用
→ 创建不可变 Build Bundle
→ 编译 .aap
→ 安装时再次确认 AA 已关闭
```

## 11. 异常与恢复

| 情况 | 前端行为 | 数据保证 |
|---|---|---|
| AA 正在运行 | 任务卡暂停，提示关闭 AA 后原位重试 | 不写任何工程文件 |
| 同名同内容 | 显示“已存在”，直接完成登记/选择 | 幂等，不重复记录 |
| 同名不同内容 | 阻止覆盖，要求重命名或重选 | 原文件和现有素材不变 |
| 历史记录存在但文件缺失 | 显示不可复用，允许重新定位源文件 | 不创建空登记 |
| 验证失败 | 卡片显示具体原因和重新选择入口 | 不复制、不改 manifest |
| 复制或 manifest 写入中途失败 | 显示失败并允许重试 | project/save 和 manifest 成对回滚 |
| AI 调用失败 | 保留草稿与素材，允许手动继续或重试 | 不回滚已登记素材 |
| 应用素材时草稿版本冲突 | 刷新草稿后要求再次应用 | 共享素材保留，草稿不猜测合并 |
| 切换剧情时有运行任务 | 明示任务仍属于原剧情；阻止错误落入新剧情 | 后端任务携带不可变剧情作用域 |
| 原剧情文件移动 | 最近使用仍可恢复已有工程；重新分析时要求定位 | 已有草稿和素材不丢失 |

## 12. 后端契约范围

现有角色、背景和短音效的发现、验证、注册、项目作用域与草稿基础可以复用。为支持本设计，接口层需要确保：

1. 草稿详情向前端返回当前剧情/工程作用域和 BGM 模式；
2. 素材列表按当前剧情作用域返回“当前剧情自定义素材”，不能把全局旧数据库直接当成当前剧情素材；
3. 提供历史项目及其真实 manifest 素材读取接口；
4. 提供“复制到当前剧情”的统一事务接口；
5. BGM 提供验证、登记、列表、试听和高级循环参数更新；
6. BGM 白名单进入 AI 和编译校验；
7. 所有对草稿使用安排的写操作携带 `expected_draft_version`；
8. 仅修改共享素材库的注册操作不伪装成草稿内容修改；应用到草稿时再递增草稿内容版本；
9. 后台任务结果带不可变的剧情/工程作用域，前端切换剧情不能改变任务目标。

## 13. 前端组件边界

建议组件职责：

- `StoryContextBar`：当前剧情身份和总体状态；
- `RecentStories`：启动页最近使用；
- `StoryAssetStrip`：共享素材汇总、过滤和任务卡；
- `AssetCard`：按类型显示已登记素材；
- `AssetTaskCard`：导入/复用过程和恢复动作；
- `AssetPickerDrawer`：当前素材、历史复用、本地导入三来源；
- `HistoryProjectBrowser`：只读浏览历史项目素材；
- `BgmPolicyPanel`：静音/启用、AI/手动模式；
- `BgmCard`：试听、标签、音量和循环摘要；
- `ReviewCardList`：当前草稿素材使用安排；
- `JobStatusStore`：以任务 ID 和剧情作用域跟踪异步状态。

组件不能自行保存工程名。所有需要素材作用域的操作由当前 `StoryContext` 提供；没有上下文时直接禁用。

## 14. 验收标准

### 14.1 工作区与共享

- 未打开剧情时无法执行素材导入；
- 打开剧情后无需再次填写素材目标工程；
- 同一剧情的多个草稿显示同一自定义素材集合；
- 在草稿 A 应用素材不会改写草稿 B；
- 切换剧情后页面、任务和素材没有上一剧情残留。

### 14.2 历史复用

- 能浏览历史项目中真实存在的背景、骨骼、短音效和 BGM；
- 复用操作复制并登记到当前剧情；
- 删除或移动历史项目后，当前剧情仍能使用已复制素材；
- 缺失文件和同名冲突不会留下半成品。

### 14.3 即时反馈

- 选择文件后立即出现任务卡；
- 验证、等待关闭 AA、复制、成功和失败状态均原位可见；
- 错误信息提供可执行下一步，不直接展示原始异常堆栈；
- 页面刷新或恢复工作区后，未完成任务能恢复或明确标为已中断。

### 14.4 BGM

- 新剧情默认静音，所有正常脚本行使用 `bgmId = 999`；
- 静音时 AI 不生成 BGM 提议；
- 启用后 AI 只能选择当前剧情已验证 BGM；
- BGM 使用安排属于单个草稿；
- 自定义 BGM 同时登记到 project/save manifest，并在两个镜像存在相同文件；
- 同名冲突、注册失败和回滚经过自动化测试；
- 自定义 BGM 在 AA 中可试听、进入鉴赏模式播放、循环，并在关闭重启 AA 后继续有效；
- 只有真实 AA 播放验证通过，卡片才能显示“已可用”。

## 15. 实施顺序约束

1. 先完成 BGM 原生导入差异实验和 `bgmId` 映射验证；
2. 补齐按当前剧情作用域查询素材、历史项目读取和复制接口；
3. 实现 BGM 验证、登记、试听、白名单和真实播放测试；
4. 建立前端 `StoryContext`，移除手填素材工程名；
