# Spine 表情标注与素材工作台闭环设计

## 背景

当前表情任务可以完成渲染和数据库写入，但任务结果、素材目录统计和工作台页面没有共享同一份事实源。任务完成后素材详情仍可能显示“0 个文件、0 个表情”，页面只展示少量语义字段，也没有明确保存结果或修改标注的入口。渲染速度和跨骨骼兼容性也需要提升。

## 目标

1. 让任务状态、数据库保存状态和素材目录统计在一次任务完成后保持一致。
2. 让每个表情的图片、编号、识别结果和编辑入口在同一张卡片中可见，桌面和手机都能使用。
3. 将视觉识别改为带编号的 3x3 九宫格批处理，并使用有界并行。
4. 将 Spine 图片恢复改为按 attachment 类型处理，能识别无法安全恢复的情况，而不是针对某个骨骼编号写特判。
5. 在不影响剧本生成的前提下，让“当前任务”成为可理解的任务状态抽屉。

## 非目标

- 不改变剧本语法、台词解析和素材复制规则。
- 不把完整联系表发送给视觉模型。
- 不承诺所有未知 Spine attachment 都能自动修复；无法验证的结果必须显式标记。

## 方案与数据流

### 任务事实源

`FACE_JOB` 继续负责短期运行态，但完成结果必须写入可查询的持久化记录，并包含：`ident`、Spine 签名、服装键、渲染数量、标注数量、数据库保存数量、失败数量、模型、完成时间和状态版本。素材目录接口读取同一持久化结果或由其更新的索引，不再把“未统计”编码成数字 0。

任务状态分为 `queued`、`rendering`、`labeling`、`persisting`、`complete`、`partial`、`failed`。浏览器展示时分别映射为“排队中、渲染中、AI 识别中、保存中、已完成、部分完成、失败”。

### API 契约

- `GET /api/assets/faces/job`：返回运行态、阶段、进度、持久化状态和安全的表情摘要；完整字段包括 `eyes`、`brows`、`mouth`、`blush`、`tears`、`confidence`、`description_cn`，不返回服务器路径。
- `GET /api/assets/faces/labels`：按当前角色、Spine 签名和服装键读取已保存标注，返回卡片所需的图片 token、原始 AI 结果、人工覆盖值、版本和更新时间。
- `PATCH /api/assets/faces/labels/{face_id}`：只更新允许的语义字段，校验 `face_id` 属于当前签名；人工值与 AI 原始值分列保存，返回新版本和保存时间。
- 完成任务后，素材目录接口的 `details.file_count`、`details.face_count`、`expression_status` 由实际结果刷新；执行中返回 `pending` 状态而不是 0。

所有写入操作使用角色键、Spine 签名、服装键和版本条件避免覆盖另一套骨骼或较新的人工修改。保存失败返回可重试的错误和已成功/失败数量。

## 渲染与骨骼兼容

### 有界并行

渲染 worker 默认上限为 4，由配置和运行环境共同限制：`min(configured_workers, 4)`，单个 Spine CLI 失败时降低并行度重试一次。任务日志记录实际 worker 数、重试和失败 attachment。并行实现必须保持结果顺序稳定，缓存命中不占用 CLI worker。

### attachment 恢复策略

- `region`：保留 atlas region 的裁切、旋转、偏移和原始尺寸元数据，恢复时按元数据映射回 attachment 坐标。
- `mesh`：读取 UV、顶点、三角形和 deform 数据，使用原始纹理尺寸和 atlas 变换重建，不把 mesh 当成普通矩形 resize。
- 未知或缺少元数据：输出校准状态 `needs_manual_calibration`，附带 attachment 名称、slot、缺失字段和预览，不静默使用近似坐标。

每个渲染结果执行通用几何校验：透明边界、非空像素范围、attachment 锚点偏移和相邻帧稳定性。校验失败时保留诊断数据并把该表情标为需校准；流程仍可保存其他已验证表情。测试覆盖不同 region/mesh 组合，不允许按动画编号特判。

## AI 九宫格批处理

每批最多 9 张表情，按稳定排序分配 `face_id`，每格绘制清晰编号和统一背景，输出图片尺寸保证单格可读。请求提示要求模型只返回带编号的结构化数组；服务端拒绝未知编号、重复编号和缺失编号，并将合法结果映射回原表情。

批次请求并发上限为 2，遇到限流按退避重试；低置信度、解析失败或编号不完整的批次只对问题表情逐张复核。前端显示批次进度和复核数量，模型从未接收完整大联系表。

## 工作台 UI

### 素材详情

- 详情页右上角放“返回目录”，与从右侧进入素材工作台的路径一致；移动端固定在顶部操作区。
- 角色详情显示实际文件数、已渲染表情数、已保存标注数和当前状态。未知状态显示“统计中/待同步”，不显示误导性的 0。
- 主区域使用表情卡片网格：桌面 4 列，平板 3 列，手机 2 列，窄屏单列。卡片包含较大预览、编号、主情绪、置信度、眼睛/眉毛/嘴部/脸红/泪水摘要和编辑按钮。
- 点击卡片打开同页详情或移动端底部面板，编辑字段并单卡保存；显示“已保存到数据库”的时间和版本。人工覆盖字段带有明确状态，支持恢复 AI 原值。
- 渲染失败或待人工校准的卡片显示原因和重试/校准入口，不与成功结果混在一起。

### 当前任务

“当前任务”改为右侧抽屉入口，不再占用详情页主要空间。抽屉显示队列、当前角色、阶段、`current/total`、渲染/识别/保存计数、失败原因和最近日志；任务完成后保留结果摘要和“查看标注”入口。手机端抽屉变为底部面板，拥有同样字段。

## 错误处理与恢复

- 渲染、AI、数据库保存分别记录阶段错误；部分成功使用 `partial`，保留可用表情。
- 页面轮询失败显示重试状态，不清空已展示结果。
- 数据库保存幂等，重复提交同一版本不会产生重复记录。
- 任务完成后主动刷新素材目录和详情；刷新失败时显示“结果已保存，目录待同步”，并提供手动刷新。

## 测试与验收

### 后端

- 任务状态转换、持久化计数、索引刷新和幂等更新测试。
- 九宫格生成测试：编号、顺序、边界批次（1、9、10 张）和非法模型返回。
- 并行 worker 上限、降级重试和缓存命中测试。
- region、mesh、UV/顶点和缺失元数据校验测试，包含 37-40 作为普通样本而非特判。

### 前端

- 完成、部分完成、保存失败和未知统计状态的 UI 测试。
- 卡片详情与编辑保存、人工覆盖、任务抽屉和返回按钮行为测试。
- 桌面、平板、手机布局测试，确保无双滚动条和卡片文字溢出。

### 验收标准

- 一次成功任务后，素材详情在自动刷新后显示真实文件数、表情数和数据库保存数，且明确显示保存时间。
- 用户能在不离开当前卡片的情况下看清图片与全部主要识别字段并修改保存。
- 10 张表情会形成两个九宫格批次，AI 返回结果能 100% 按编号对应；低置信度只复核问题项。
- 在受支持 attachment 上，错位校验不依赖动画编号；不支持的情况必须显式提示人工校准。
- 默认 4 路并行在测试环境完成，失败时能自动降级，不破坏已有单 worker 配置。
