# Spine 表情预览刷新与任务操作设计

## 目标

让表情工作台始终展示本次渲染生成的头像，避免旧缓存使 37-40 等表情看起来仍未修复；同时简化重复 AI 标注入口，并消除并发预览请求触发的 SQLite 锁冲突。

## 已确认根因

- 当前数据库中的表情记录仍指向 `heads-v4`，而最新任务已生成 `heads-v7`。
- 未读取到 AI provider 或直接复用 AI 缓存时，分析流程在刷新数据库预览路径前返回。
- 预览 URL 没有内容版本，浏览器可能继续复用同一 URL 的旧图片。
- 每个头像 GET 都会经过 `asset_catalog.migrate()`；工作台并发加载图片时，多条连接会重复执行写迁移，产生 `database is locked`。
- 最新 `heads-v7` 中 37-40 的眼睛、脸红和嘴部渲染正常；不得修改这些表情的真实附件几何或添加 ID 特判。

## 行为设计

### 预览刷新

渲染完成后、任何 AI 分支返回前，按当前角色、骨骼签名和服装键刷新已有视觉标注的 `head_path`。刷新覆盖所有模型记录，但只更新预览路径、记录版本和更新时间，不修改 AI 情绪结果、人工覆盖或复核状态。

预览 URL 携带记录版本。路径刷新后，浏览器请求新的 URL，避免继续显示旧缓存。当前 `heads-v7` 已经提供更紧的头像裁切，因此前端保持完整显示，不额外使用 `object-fit: cover` 二次裁脸。

### AI 操作

移除主操作区常驻的“重新请求 AI 视觉标注”复选框。主按钮负责开始解析并默认复用已有 AI 结果。只有已有结果时才显示次要的“强制重新请求 AI”操作；该操作重新请求当前模型，但继续保留人工覆盖。

任务启动时若没有读取到密钥，状态明确显示“当前任务未读取到模型密钥；保存配置后请重新开始任务”。密钥状态在任务启动时确定，不暗示渲染或骨骼失败。

### 数据库并发

SQLite 连接配置有限的 busy timeout。素材库迁移使用进程内串行门闩，并在门闩内再次检查 schema 版本；已迁移数据库走只读快路径。头像预览解析不应为每张图片重复执行迁移写入。

## 验证

- 回归测试证明无 provider 和 AI 缓存复用两条路径都会刷新旧 `head_path`，且人工覆盖不变。
- 回归测试证明预览 URL 随记录版本变化。
- 并发测试同时解析多个头像预览，不出现数据库锁异常，也不重复执行迁移写入。
- UI 测试证明主操作区不再显示复选框，强制重跑只在已有结果时出现，并提交 `force_vision=true`。
- 使用真实素材检查 36-41，确认页面读取 `heads-v7`，头像填充合理且 37-40 部件完整。
