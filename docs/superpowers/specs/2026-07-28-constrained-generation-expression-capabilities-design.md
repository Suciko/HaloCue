# 已登记素材约束与角色差分能力设计

## 目标

使自动标注模型只能选择当前工程已登记且可验证的背景、音效、角色、表情编号、气泡与动作；同时兼容不同骨骼作者的差分组织方式，而不要求自定义骨骼必须使用编号或中文语义命名。

本阶段使用的真实输入样本：

- 剧情：`D:\桌面\蔚蓝档案二创\莹相关内容\凯伊约会短篇\本日行程全部作废_正文.md`
- 骨骼：`D:\桌面\蔚蓝档案二创\角色立绘与美术周边\官方角色立绘\天童凯伊（约会服）\Kei_Date_Outfit`

## 已确认事实

- AA 的 `.aap` 角色记录通过 `name` 引用角色 Identifier，通过 `faceId` 引用一个表情编号；已导入测试角色 `92707271` 的真实记录使用过 `00` 与 `01`。
- `CH0335_spr` atlas 具有 `00_default`、`01_normal`、`03_smile` 等完整表情编号命名，现有解析器可从中提取两位编号。
- `Kei_Date_Outfit` 的 atlas 与 `.skel` 均包含可读的中文语义部件名，例如眼、眉、嘴、脸红及其适用情绪；它们不采用 `NN_名称` 的完整表情编号命名。
- 同一骨骼的文件完整性和可导入性，不等于可以从文件本身推导出可用于 `.aap.faceId` 的编号。
- Chat 是 `emoticon=1`，Jump 是 `action=6`；两者均已经在先前自定义骨骼实际预览、编译、重启验证中成功。
- 当前 `annotate.py` 已在写回标注前丢弃不在允许集合中的 face、音效和背景，但其角色表情模型只表示为单一 `faceId` 列表。

## 设计原则

1. 骨骼“可导入”与“可自动表情演出”分开判定。
2. 语义命名是可选增强，不是导入条件；没有可读标签的骨骼仍可安全使用默认立绘。
3. 模型只能输出已验证的 AA 引用。语义候选、atlas 猜测和模型猜测均不得直接成为 `.aap.faceId`。
4. 任何差分、动作或素材不能证明可用时，宁可降级为不切换，不得编造编号或资源名。
5. 所有自定义角色能力按 `Identifier + skeleton SHA-256 + outfit_key` 作用域保存，避免同角色不同服装或更新骨骼互相污染。
6. 不改变既有官方素材索引、镜头版第一章/第二章，且不修改用户源素材。

## 角色差分能力模型

每个角色变体同时保存两种彼此独立的信息。

### 1. AA 可引用能力（严格输出白名单）

`face_evidence` 中 `source in {aa_verified, aap_observed}` 的 `faceId` 才是模型可输出的 face 白名单。编号式 atlas 只能产生 `atlas_candidate`，不能越过该限制。

动作与气泡也按相同原则保存：只有全局已知且该变体经过实测/显式登记为可用的条目，才进入提示词与编译器白名单。

### 2. 素材语义能力（理解与人工辅助）

新增“表情部件”记录，不含可直接写入 AA 的编号：

```json
{
  "kind": "eyes",
  "raw_name": "圆睁高光眼（惊讶、震惊、期待、好奇）",
  "labels": ["惊讶", "震惊", "期待", "好奇"],
  "source": "atlas_semantic"
}
```

部件 `kind` 可为 `eyes`、`brows`、`mouth`、`blush`、`tear`、`other` 或 `unknown`。解析器必须保留原始名称；无法可靠归类时归入 `unknown`，不得丢失或臆测。

完整表情编号仍保存为 face 候选，例如：

```json
{
  "face_id": "03",
  "raw": "03_smile",
  "label": "smile",
  "label_cn": "微笑",
  "source": "atlas_candidate"
}
```

## 骨骼分类与降级规则

| 分类 | 条件 | 语义能力 | 允许模型实际输出 |
|---|---|---|---|
| `numbered_composite` | 有 `NN_...` 完整表情条目 | 读取编号和名称 | 仅已观察/AA 验证的 faceId |
| `semantic_modular` | 有非编号、可读的部件/情绪标签 | 读取部件及标签 | 已验证 faceId；无映射则保持默认 |
| `opaque_custom` | 无上述可读信息 | 标记未知 | 默认 faceId（仅当已验证），否则不写 face |
| `official_or_observed` | 官方索引或历史 AAP 已有证据 | 使用已有 face 记录 | 已观察/AA 验证的 faceId |

`Kei_Date_Outfit` 在本设计中为 `semantic_modular`。其“微笑、惊讶、害羞”等标签可进入人工检查报告，但在没有 AA 实测 faceId 映射前，不能被转换成一个数字 faceId。

## 数据流

```text
骨骼目录
  -> asset_validation: 校验四文件、解析编号候选与语义部件
  -> asset_catalog / aa_assets.db: 按变体保存安装信息、face 证据、部件语义
  -> merge_model_constraints: 仅导出当前工程已登记素材与严格白名单
  -> prompt / annotate: 给模型展示真实资源和可用 faceId；未知能力明确禁止填 face
  -> annotation validator: 删除越界资源、face、动作、气泡并留下可读告警
  -> script2aap: 只编译通过上述检查的标注
  -> project/save verifier: 再次检查生成 `.aap` 的所有引用
```

## 接口边界

- `asset_validation.py`：只负责文件完整性与解析候选，不注册 AA、不决定模型是否可用。
- `assetdb.py`：负责 SQLite 迁移、变体作用域、表情证据、语义部件的幂等存储和读取。
- `asset_catalog.py`：负责将当前工程已注册资产转换为模型约束；不得把语义部件或 atlas 候选升级为验证证据。
- `prompt.py`：只描述该次生成实际允许的资源和规则；对语义部件只给“理解提示”，不把它伪装成 faceId。
- `annotate.py`：结构化输出与逐字段白名单校验；输出不合法时删除该字段并记录原因。
- `script2aap.py`：保持纯编译职责；不扫描骨骼、不调用模型、不自动猜资源。

## 模型规则补强

- 背景与音效仅可选择资源清单中真实标识；中文标签只能用于检索，不能作为输出标识。
- 角色只能选择当前演员映射中的 Identifier。
- `face` 只能选择当前角色、当前骨骼变体的验证白名单。表情表未知或仅有语义部件时，必须填空串。
- `emo`、`act`、`fx`、`bgfx`、`trans` 只能选清单中允许值；人物没有经验证动作能力时，`act` 必须为空。
- 继续使用既定镜头规则：每场首次入镜 `appear=3`，同场再入镜 `appear=0`，显式 `@enter`/`@exit` 优先，场末不自动渐出。
- 保持原文台词逐字不改，模型只产生演出标注。

## 验证与验收

### 自动测试

1. 编号式 atlas 仍提取 `00`、`01`、`03` 等 face 候选。
2. 约会服 atlas 提取语义部件及中文情绪标签，且不会被标为“无差分”。
3. 语义部件不会进入 face 白名单，除非存在同一变体的 `aa_verified` 或 `aap_observed` face 证据。
4. 同 Identifier、不同 skeleton SHA 或 outfit 的能力彼此隔离。
5. 模型返回不存在的 bg/se/face/emo/act 时，结果中不含该字段并有明确丢弃原因。
6. 非人类说话者不能得到 face、emo、act、fx。
7. 现有 face evidence、项目注册、符号规则和全量既有测试不回归。

### 真实样本验证

1. 从《本日行程，全部作废》创建独立的生成测试目录，不覆盖原文。
2. 使用 `Kei_Date_Outfit` 以用户指定 Identifier 导入独立 AA 工程。
3. 生成前导出实际模型资源清单；报告必须显示该角色的分类、可用 faceId 与语义部件数。
4. 生成标注剧本和 `.aap`，逐项验证人物、背景、音效、faceId、动作引用存在。
5. 若该骨骼尚未得到 faceId 映射，报告明确列出降级的表情意图，而 `.aap` 不含未验证编号。
6. 用户在 AA 中预览/编译后，收集 `.aap` 实际 faceId 证据，重新运行验证，确认白名单只扩展到该变体。

## 非目标

- 本阶段不修改镜头算法或改变现有入场/退场规则。
- 不试图通过视觉猜测为无标签骨骼发明表情名称或 AA 编号。
- 不将用户骨骼、官方资源或密钥上传到外部服务。
