# 审查状态与最近剧情恢复设计

## 目标

修复审查草稿首次打开时右侧剧情预览为空、初审背景候选在重开项目后丢失，以及最近剧情列表过长的问题。

## 设计

### 最近剧情

`RecentStories` 默认只渲染按最近打开时间排序后的前三条。若实际记录超过三条，在列表末尾渲染“打开查看更多”控件；点击后在同一列表中展开剩余记录，控件变为“收起”。展开状态属于当前页面会话，不写入项目数据。

### 预览生命周期

工作区切换或清空时销毁旧 `Player` 实例并清空容器。草稿载入时重新创建播放器，装载卡片后默认选中第一张卡并通过同一选择回调更新右侧预览、背景时间线和活动审查状态。这样首次载入和再次载入走同一条路径。

### 初审背景候选

初审结果中的 `usage_chain[].needs[].candidates`、分数、理由和当前绑定写入项目的预检快照。重开项目优先恢复新鲜快照，不重新请求 AI；只有用户点击重新检查或源文件指纹变化时才重新生成结果。候选展示继续使用快照中的顺序，不把候选压缩成单一 `suggested_aa_key`。

## 错误处理

快照缺失、源文件不可用或指纹过期时显示现有的重新检查提示。播放器重建失败不应阻塞卡片审查，页面应保留卡片列表并显示空预览提示。

## 验证

- UI 测试确认最近剧情默认三条、展开/收起可用。
- UI 回归测试确认清空工作区后旧播放器不会接收新卡片，首次载入会选中第一张卡并渲染预览。
- 工作区/API 测试确认完整背景候选在快照保存和重开后保持不变。
- 运行相关 pytest 子集及完整测试套件。
