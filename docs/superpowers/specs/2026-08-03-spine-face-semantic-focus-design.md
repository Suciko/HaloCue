# Spine 表情语义聚焦工作台设计

- 日期：2026-08-03
- 状态：用户已确认
- 已选方案：情绪名称 + 使用语境，配合跨表情差异聚焦预览
- 范围：视觉标注契约、剧情表情资源提示、表情卡片、内部九宫格、头部预览裁切

## 1. 目标

表情标注只回答一个问题：剧情 AI 在怎样的台词、态度和情绪阶段下适合使用这个表情 ID。

标注应同时满足：

1. 足够准确，避免把愤怒、克制不满、尴尬和无奈等相近状态混用；
2. 不把标签写成机械触发规则，剧情 AI 仍可结合上下文、表情连续性和角色状态自由选择；
3. 不以是否脸红、是否流泪或某个五官形态作为使用条件；
4. 允许多个表情 ID 拥有相同情绪和相同使用语境；
5. 兼容官方骨骼、模块化自制骨骼和未知附件命名方式。

## 2. 语义契约

新的正常标注结果只包含：

```json
{
  "face_id": "37",
  "primary_emotion": "克制不满",
  "usage_hint_cn": "适合冷淡反驳、忍着不发作",
  "confidence": 0.91
}
```

`primary_emotion` 是简短自然的中文情绪或态度名称。`usage_hint_cn` 是一句短使用语境，描述适合怎样的台词、反应、语气或情绪阶段。它不得描述眼睛、眉毛、嘴部、脸红、泪水等画面部件，也不得写成“出现某关键词就必须使用”的硬规则。

视觉模型应优先区分会影响剧情选择的语义差别，但不得为追求唯一性强行区分实际相同的表情。`00` 和 `01` 等视觉与用途相同的 ID 可以得到完全相同的结果。

现有数据库中的 `eyes`、`brows`、`mouth`、`blush`、`tears`、`secondary_json`、`valence` 和 `arousal` 暂时保留，以兼容已有数据库和旧记录；新识别不再要求这些字段，正常工作台也不显示或编辑它们。人工覆盖继续与 AI 原值分开保存，并跨模型保留。

## 3. 剧情 AI 的使用方式

剧情资源提示应为每个可用 ID 提供紧凑语义，例如：

```text
00=平静｜普通交谈或安静倾听
37=克制不满｜冷淡反驳、忍着不发作
39=气急恼火｜情绪失控地抗议或喊叫
```

使用语境是候选提示，不是决定条件。剧情 AI 仍须根据当前台词、上一表情、情绪变化阶段和角色风格综合判断：

- 同一情绪连续表达时可以保持上一表情；
- 多个 ID 语义相同时可以任选符合连续性的一个，不必机械轮换；
- 不得因为台词提到害羞、哭泣等字样就仅按脸红或泪水选择；
- 没有完美差分时，应选择整体情绪和语气最接近的可用 ID；
- 准确重复优于为了多样性使用错误表情。

为控制上下文长度，单个情绪名称和使用语境都设短长度上限；空使用语境允许降级为只提供情绪名称。

## 4. 工作台界面

每张卡片只显示：

- 紧密填充的表情预览；
- 表情 ID；
- 情绪名称；
- 一行使用语境；
- 低置信度或人工修改状态；
- 修改入口。

编辑器只提供“情绪名称”和“使用语境”两个文本字段。置信度不作为用户必须处理的字段，只在需要复核时出现。眼睛、眉毛、嘴部、脸红、泪水及其开关全部退出正常界面。

完整 contact sheet 和编号九宫格只作为视觉模型的内部输入及调试产物，不作为任务完成后的页面内容，也不接在卡片列表末尾。

## 5. 通用预览聚焦

预览问题分为两个层次：

1. Spine 运行时渲染负责忠实呈现源骨骼与 atlas 几何；
2. 工作台裁切负责让表情变化在有限卡片空间内清晰可见。

工作台不得为了某几个 ID 修改 attachment 的 `x`、`y`、`width`、`height` 或缩放。当前样本中，37–40 共用的眼睛附件 atlas 原始尺寸为 `240 x 103`、骨骼区域为 `369 x 159`；相邻附件也使用约 `1.54` 的统一倍率，因此现有证据不支持把它判定为附件恢复漏缩放。

新的裁切使用同一角色全部表情的实际渲染结果计算共享关注区域：

1. 确保各表情画布对齐；
2. 从跨表情像素差异中找出稳定的主要变化区域；
3. 将变化区域与上半身透明像素边界合并，得到带安全边距的共享头部裁切框；
4. 所有表情使用同一个裁切框，避免卡片间跳动和误导性的相对缩放；
5. 没有足够差异、只有一个表情或图像尺寸不一致时，降级到透明像素分布驱动的上半身裁切；
6. 输出固定方形透明 PNG，前端使用稳定尺寸显示，主体应尽量填满而不裁掉主要表情变化。

该算法只改变标注预览，不改变源骨骼和剧情运行时效果。它不依赖 `Eyes` 等 slot 名称，也不依赖中文附件名或特定 face ID。

## 6. 数据流与兼容

视觉标注、人工编辑、`face_evidence` 和剧情提示使用同一份有效语义：人工覆盖优先于 AI 原值。旧记录读取时，现有 `description_cn` 可作为使用语境兼容来源；新写入使用统一的 `usage_hint_cn` API 名称，并在持久层映射到兼容列，避免破坏性数据库迁移。

任务状态、失败容错、四路渲染与单线程降级、GET/PATCH 过期响应防护、同表情保存串行化保持现状。精简字段不得削弱这些已完成的可靠性保证。

## 7. 验收标准

1. 视觉模型的新请求不再要求或鼓励输出脸部零件、脸红、泪水等字段；
2. 情绪相同的多个 ID 可以通过验证并正常保存；
3. 剧情提示包含情绪和可选使用语境，并明确其不是硬触发规则；
4. 工作台卡片和编辑器不出现已移除的视觉字段；
5. 完成任务后页面不显示完整 contact sheet；
6. 预览裁切基于跨表情图像差异并对全部 ID 使用共享裁切框；
7. 测试中不得出现对 37–40 或任何具体骨骼名称的分支；
8. 桌面、平板和手机上图片填充有效、文字和控件不越界、无横向溢出和页面级双滚动；
9. 现有人工覆盖、并发降级、部分失败、任务状态和前端竞态测试继续通过。

## 8. 非目标与真实限制

- 不自动修正用户源骨骼中的附件几何；程序没有权威依据判断尺寸差异是制作错误还是美术意图。
- 不建立关键词到表情 ID 的固定映射。
- 不要求每个表情拥有唯一情绪名称。
- 不删除旧数据库列或旧标注数据。
- 不保证仅靠二维渲染能够识别所有 mesh、deform 或特殊混合效果；无法稳定渲染的项目继续进入现有校准/部分完成状态。
