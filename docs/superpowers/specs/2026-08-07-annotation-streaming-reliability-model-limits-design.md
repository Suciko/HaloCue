# 审查草稿流式进度、可靠性与模型输出上限设计

日期：2026-08-07

## 背景

审查草稿生成目前只在开始处理场景块时更新一次状态。单次模型调用耗时较长时，界面长时间停留在同一句提示，用户无法判断模型是在等待首段响应、持续输出、重试，还是已经失去响应。

本次排查还确认了严重的性能与可靠性回退：

- 当前基础文字模型实际为 `deepseek-v4-flash`，不是旧兼容配置中显示的 Gemini 模型。
- 近期 266 行任务从第一个成功检查点到最后一个检查点耗时约 59 分钟，18 个成功子块中有 10 个来自缩块重试；同期 Gemini 的两个 240 行任务约为 8.4 和 11.9 分钟，且没有缩块。
- 失败任务在完成 101 行后终止，最终错误为 `state_delta.bgfx` 返回 `null`，而 Schema 仅允许字符串。
- `state_delta` 是可选状态增量。这里的 `null` 应表示“不更新”，但现有实现把它当作容量问题，重复原尺寸请求并逐级缩块，产生大量无效输出与费用。
- 18:00 至 19:00 的供应商统计包含 189,114 输入 tokens，其中 130,432 命中缓存，输入缓存命中率约 69%；输出达到 106,711 tokens。主要浪费来自失败响应和重试，而不是缓存完全失效。
- 当前模型配置沿用固定的 `max_tokens=16000`。Token Rhythm 的模型接口为 `deepseek-v4-flash` 返回 `max_completion_tokens=384000`，实际短请求也能接受六位数 `max_tokens`。固定旧默认值可能在其他场景触发截断或漏行，但不是本次 `null` 类型错误的直接原因。

## 目标

- 在等待首段响应和持续接收输出时提供实时、可读的进度。
- 修复可选状态字段的安全 `null` 兼容，不放宽台词标注与原文身份校验。
- 区分容量错误与内容错误，避免无意义的重复请求和逐级缩块。
- 同一任务内记住已验证的安全块大小，避免后续块重复触发同类失败。
- 记录实际模型、请求耗时、首段耗时、重试、缩块、输入、输出与缓存命中数据。
- 从模型接口元数据或经过核对的本地目录自动建议最大输出，并允许用户覆盖。
- 用离线回归测试覆盖多块、恢复、失败分类、UI 状态和规模行为，再进行一次小型真实接口冒烟测试。

## 非目标

- 不重写有状态标注 Agent、剧情记忆、逐行身份协议或草稿结构。
- 不恢复会静默漏行的旧版宽松校验。
- 不根据上下文窗口猜测最大输出。
- 不自动切换基础模型。
- 不把半截 JSON 写入草稿或检查点。
- 不在仓库、日志、检查点或测试夹具中保存 API Key。

## 总体设计

### 流式模型调用

在 Provider 层增加向后兼容的流式 JSON 调用入口。内置 Anthropic 与 OpenAI-compatible Provider 实现真实流式接收；只实现现有 `complete_json()` 的测试或自定义 Provider 自动走完整响应兼容路径。

流式入口逐段累计文本，并向调用方报告：

- 请求开始时间；
- 是否收到首段；
- 已接收字符数；
- 最近活动时间；
- 完成原因与 usage。

完整文本仍在 Provider 内拼接，并继续经过现有 JSON 解析和 Schema 校验。Annotation Agent 只有在完整响应通过协议校验后才提交当前场景块和检查点。

### Job 与界面进度

Job 增加结构化的模型活动字段，不依赖解析中文提示字符串。字段包含实际模型名、当前场景块、模型状态、请求开始时间、首段时间、累计字符数、重试次数和缩块次数。

浏览器继续复用现有约 800ms Job 轮询：

- 首段到达前显示 `等待模型首段响应 · 已等待 N 秒`；
- 首段到达后显示 `模型持续返回中 · 已接收 N 字符 · 已用时 N 秒`；
- 重试和缩块时显示原因与新的块大小；
- 完成后显示实际模型、总耗时、请求次数、缓存命中率和复用检查点数量。

原始流式 JSON 不在界面显示。

## 可靠性修复

### 可选状态的 null 语义

`state_delta` 中的字段均为可选增量。模型返回 `null` 时，将其规范化为字段缺失，即“不修改当前状态”。这项兼容只适用于 `state_delta`。

以下内容继续严格拒绝 `null`、缺失、重复或错误类型：

- 每个目标行的 `source_id`；
- 原文身份与完整目标覆盖；
- 台词标注字段；
- 记忆事件的证据与来源；
- 无台词反应节点的角色、锚点和资源。

### 错误分类

错误分为三类：

1. 容量错误：`finish_reason=length`、响应截断或缺少目标行。允许缩块重试。
2. 可恢复兼容错误：可选状态为 `null` 等有明确无损语义的差异。先规范化，再校验，不触发重试。
3. 内容或协议错误：非法资源、错误字段类型、未知目标行或错误指纹。最多进行一次同尺寸纠正请求；再次失败后保留已有检查点并返回具体错误，不继续假装是容量不足。

### 自适应块大小

当一个块因容量错误从 20 行缩到 10 行并成功后，本次任务记录 10 行为当前 Provider 和响应协议的安全上限。队列中尚未处理且更大的块直接按该上限切分，避免每个后续块都先产生两次失败响应。

该上限只在当前任务内生效，不跨模型、跨配置永久保存。后续任务仍从配置值开始，避免一次偶发故障永久降低吞吐。

## 模型输出上限

### 能力来源优先级

选择或读取模型时，按以下顺序解析推荐最大输出：

1. 模型接口 `/models` 返回的结构化字段，例如 `max_completion_tokens`、`max_output_tokens` 或明确等价字段。
2. 本地模型能力目录中的精确模型 ID、版本别名或有边界的系列规则。
3. 无可靠来源时保留用户当前值，并显示“上限未知，需手动设置”。

`context_length` 只表示上下文窗口，不能作为最大输出回填。

### 本地能力目录

本地目录覆盖应用内的预制供应商和默认模型。每条记录包含：

- 精确模型 ID 或受控别名规则；
- 最大输出；
- 来源 URL；
- 核对日期；
- Provider 协议与备注。

预制模型在实现前逐一以供应商官方文档为准核对。OpenAI 的 GPT-4o 官方模型页当前标明最大输出 16,384 tokens；Token Rhythm 的模型页和 `/models` 当前均标明 `deepseek-v4-flash` 最大输出 384K。聚合服务的自定义模型优先相信该连接自身的结构化 `/models` 元数据，因为其代理限制可能不同于上游官方值。

### 自动填写与手动覆盖

用户从“读取可用模型”列表选择模型后，界面自动填写推荐最大输出，并显示来源，例如 `接口返回 · 384K` 或 `官方资料 · 16,384`。

最大输出输入框保持可编辑。用户修改后标记为“手动设置”，不再被普通刷新覆盖；旁边提供“恢复推荐值”命令。重新选择另一个模型时重新解析推荐值。

保存模型时同时保存实际数值和来源状态，但不依赖远程网页才能运行。运行时只使用已保存数值，不在每次生成前联网抓取文档。

## 缓存与用量统计

OpenAI-compatible usage 解析同时支持：

- `prompt_tokens_details.cached_tokens`；
- `prompt_cache_hit_tokens`；
- `prompt_cache_miss_tokens`；
- 常规 `prompt_tokens` 与 `completion_tokens`。

统计按请求累积，并在任务结果中返回缓存命中 tokens、未命中 tokens 和输入缓存命中率。没有提供缓存字段的服务显示“未报告”，不得显示为 0% 命中。

缓存统计用于解释费用，不改变模型返回或检查点指纹。稳定资源提示继续位于变化上下文之前，以保留前缀缓存机会。

## 测试设计

### 单元测试

- `state_delta.bgfx=null`、其他可选字符串、数组和对象状态为 `null` 时规范化为不更新。
- 台词字段、身份字段和必需事件字段为 `null` 时继续失败。
- DeepSeek 与 OpenAI usage 字段均能正确累计缓存命中和未命中 tokens。
- `/models` 的不同上限字段映射到统一能力记录。
- `context_length` 不会被误用为最大输出。
- 本地目录精确匹配、版本别名、未知模型和手动覆盖行为正确。

### Agent 回归测试

- 模拟前六个块成功、第七个块返回 `state_delta.bgfx=null`，最终完整生成草稿。
- 容量失败后缩块成功，后续大块直接采用已学习上限。
- 非容量类型错误不会逐级缩到 5 行。
- 失败后保留之前检查点；修复后重试只请求未完成目标。
- 240 行剧本每个目标行恰好有一个已验证结果。

### Provider 与 UI 测试

- Anthropic 和 OpenAI-compatible 流式片段正确拼接，并只在最终结果完整后解析。
- 首段前、接收中、重试、缩块、完成和连接中断状态可见。
- 实际模型名、字符数、耗时和缓存统计显示正确。
- 不支持流式的 Provider 仍能完成任务。

### 真实接口冒烟测试

在离线测试全部通过后，使用用户授权的 Token Rhythm 连接执行一次 5 至 10 行测试：

- 使用自动识别的 `deepseek-v4-flash` 最大输出；
- 验证首段与累计字符进度；
- 验证包含可选空状态的响应不导致整项失败；
- 记录耗时、请求次数、完成原因和 usage；
- 不记录密钥或原始 Authorization 头。

若真实模型仍返回新的协议差异，先把原始响应特征转化为脱敏离线夹具，再决定是否增加有明确无损语义的兼容；不得直接放宽整个协议。

## 验收标准

- 截图中的 `state_delta.bgfx=null` 场景不再导致整项失败。
- 相同非容量错误不会因缩块而重复消耗多次请求。
- 用户在每个模型请求期间都能看到等待首段或持续接收状态。
- Token Rhythm 模型选择能够从 `/models` 读取 `max_completion_tokens=384000` 并自动建议。
- 用户手动覆盖最大输出后不会被刷新覆盖，并可恢复推荐值。
- 缓存字段存在时显示真实命中率，不存在时显示“未报告”。
- 离线回归、240 行规模测试和一次授权的真实小型冒烟测试通过。
