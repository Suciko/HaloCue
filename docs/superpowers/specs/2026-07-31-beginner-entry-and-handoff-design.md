# 普通用户启动入口与交接设计

日期：2026-07-31

## 目标

让不熟悉命令行、Python 和文件路径的 Windows 用户也能独立完成：

1. 找到唯一且明确的启动入口。
2. 双击后自动检查程序、Python、素材数据库和 AA 工作区。
3. 在网页里看懂首次使用顺序，并能随时重新打开帮助。
4. 遇到缺失背景时知道程序是在等待素材，而不是“报错坏了”。
5. 让下一位 AI 只读一份接手文档，就能继续开发和验证。

## 方案比较与选择

### 方案 A：只补 README 和批处理文件

改动最少，但环境或路径出错时仍会出现黑色命令行报错，普通用户不知道下一步。

### 方案 B：一键入口、Python 启动器、网页新手帮助

由顶层中文批处理文件作为唯一入口，Python 启动器做环境体检和友好报错，网页继续承担所有业务操作。这种方案不引入桌面框架，能直接复用现有网页程序，也方便以后被安装包调用。

### 方案 C：现在就封装完整桌面应用

体验最好，但会提前引入打包、升级、签名、杀毒软件误报和进程管理问题，不适合当前尚在快速修改业务规则的阶段。

本轮选择方案 B。

## 用户入口

总目录新增：

- `启动AA自动写剧本.cmd`：普通用户平时唯一需要双击的文件。
- `检查运行环境.cmd`：程序打不开时双击，显示清晰体检结果。
- `使用说明-从这里开始.md`：不依赖程序即可阅读的五分钟说明。

程序目录新增：

- `launcher.py`：可测试的 Windows 启动和环境体检逻辑。
- `启动程序.cmd`：同目录备用入口，也供以后打包脚本调用。
- `检查运行环境.cmd`：同目录备用诊断入口。

启动流程：

1. 批处理文件自动进入正确目录。
2. 优先使用 `py -3`，否则使用 `python`。
3. `launcher.py` 检查 Python 版本、核心文件、Pillow、素材数据库和 AA 数据目录。
4. AA 目录无法自动找到时，弹出 Windows 文件夹选择框，用户可选择 `data` 或其上一级工作区。
5. 启动器把有效路径写入 `aa_config.json`，随后启动本地网页。
6. 如果 8770 端口已经是本程序，直接打开现有页面，避免重复启动。
7. 失败时写入 `启动失败日志.txt`，显示中文原因和解决办法。

## 网页新手体验

### 首次使用卡片

生成剧本页面顶部显示三项准备状态：

- AA 工作区：必须连接。
- 素材数据库：必须存在。
- AI 模型：仅“AI 自动安排演出”需要；仅转换格式时可以不配置。

卡片明确告诉用户平时从哪个文件启动，并提供：

- 打开设置。
- 开始选择剧本。
- 暂时收起。

收起状态只保存在当前浏览器；侧栏“使用帮助”可随时重新打开完整说明。

### 使用帮助抽屉

帮助内容按真实任务组织，而不是按技术模块组织：

1. 第一次使用。
2. 生成一章剧情。
3. 导入背景、音效、人物骨骼。
4. AI 要求补背景时怎么办。
5. 如何停止程序和重新打开。
6. 常见故障与对应的诊断入口。

## 后端状态接口

新增 `setup_status()` 与 `GET /api/setup/status`，只返回非敏感状态：

- AA 是否连接和当前路径。
- 素材数据库是否存在。
- 当前素材数量。
- 是否存在当前模型配置及其显示名称。
- 建议的启动入口文件名。

接口不得返回 API Key、凭据目标名称或其他秘密。

## 错误处理

- Python 未安装：批处理文件显示“需要 Python 3.9 或更高版本”，等待用户按键后关闭。
- 缺少 Pillow：诊断结果给出精确安装命令，不自动联网安装。
- AA 路径错误：允许重新选择文件夹；选择结果不含 `projects` 时拒绝保存。
- 素材数据库缺失：说明需要初始化素材库，不伪装成网页正常启动。
- 端口占用但不是本程序：由现有 `free_port()` 自动选择后续端口。
- 所有失败均保留可复制的 UTF-8 日志。

## 视觉系统

- 定位：面向普通用户的桌面工具，观看距离为笔记本屏幕，气质安静、明确、可信。
- 颜色：沿用 `#2f6fed` 主色、深蓝侧栏、白色卡片和绿色成功状态。
- 字体：沿用 Windows 中文 UI 字体栈。
- 间距：以 8px 为基础，帮助卡片使用 16–24px 间距。
- 圆角：10–14px，状态胶囊为全圆角。
- 动效：160–220ms；遵守 `prefers-reduced-motion`。
- 不增加渐变、表情符号或新的装饰色。

## 验证标准

1. 在总目录双击入口能启动页面。
2. 从任意当前目录调用入口都能定位程序目录。
3. `launcher.py --check --json` 可被自动测试并且不启动服务器。
4. AA 路径规范化支持选择 `data` 或工作区父目录。
5. 网页能显示三项准备状态且不泄露密钥。
6. “使用帮助”和“设置”互不冲突，键盘和窄屏可用。
7. 全量 Python 测试通过。
8. 浏览器桌面、平板和手机宽度无溢出，控制台无错误或警告。
9. 发布安全检查通过。
10. AI 接手文档经无上下文读者问题测试后，能够回答入口、架构、测试、风险和下一步。
