# AA 演出语义、资源与性能优化设计

- 日期：2026-08-06
- 状态：设计已获用户确认，待文档复核
- 范围：表情语义、动作与气泡密度、登场渐变、无台词 wait、官方与自定义 Spine 资源、剧情生成性能

## 1. 目标

本次优化同时提升演出质量和生成效率：

1. 喜剧和高情绪场景能够更准确、更高频地使用表情符号与短动作。
2. 表情选择能区分结巴掩饰、生闷气、无奈、惊疑和真正爆发，避免被句末标点单独带偏。
3. 角色首次出现、跨场景重现和长时间离镜后的重现使用渐变，但不制造额外独立停顿。
4. 支持真正的无台词反应节点，例如“……”后等待 2500ms。
5. 官方 Spine 没有视觉标注时仍可稳定生成；自定义 Spine 可以通过渲染和视觉标注获得更丰富语义。
6. 减少重复上下文和请求次数，但不减少资源能力或降低模型判断质量。

## 2. 设计原则

- 资源库保存完整合法资源和完整语义；只压缩每次请求中与当前镜头无关的重复上下文。
- 模型负责语义、反讽和喜剧节拍；程序负责状态机、资源合法性、密度约束和确定性兜底。
- 语义正确优先于表情多样性；重复使用正确表情优于机械轮换。
- 任何优化都必须记录前后指标，确认速度提升没有质量回退。
- 新字段全部可选并兼容旧记录，官方和旧项目不能因缺少视觉标注而阻塞生成。

## 3. Spine 语义分类

### 3.1 多轴标签

视觉标注结果保留现有 `primary_emotion` 和 `usage_hint_cn`，增加可选多轴字段：

```json
{
  "face_id": "17",
  "primary_emotion": "慌乱尴尬",
  "emotion_family": "embarrassment",
  "intensity": 2,
  "expression_class": "accent",
  "beat_fit": ["reaction", "denial"],
  "hold_policy": "short",
  "special_tags": [],
  "usage_hint_cn": "适合被看穿心思、结巴掩饰或手足无措地辩解",
  "avoid_when_cn": "不适合真正发火、训斥或强硬命令",
  "confidence": 0.95
}
```

字段含义：

- `emotion_family`：`neutral`、`joy`、`surprise_fear`、`embarrassment`、`irritation_anger`、`sadness_hurt`、`confusion_resignation`。
- `intensity`：0–3，表示情绪强度。
- `expression_class`：`base`（日常常驻）、`accent`（明确反应）、`peak`（情绪峰值）、`special`（哭泣、特殊眼、夸张颜艺等机制）。
- `beat_fit`：`statement`、`reaction`、`denial`、`teasing`、`command`、`emotional_climax`、`silent_beat` 等使用功能。
- `hold_policy`：`hold`、`short`、`flash`，表示允许持续、短暂保持或只用于瞬间峰值。
- `special_tags`：闭眼、流泪、冷汗、特殊眼等非情绪本身的视觉属性。
- `avoid_when_cn`：明确不适用的语境，作为候选排除提示而不是关键词硬规则。

普通素材卡片只展示情绪名称、使用语境和少量徽标（如“峰值”“强度 3”“短留”“特殊”）；完整字段放在高级编辑区。

### 3.2 模型决策顺序

剧情模型选择表情时按以下顺序判断：

1. 台词真正表达的情绪来源，包括结巴、掩饰、反讽和转移话题。
2. 情绪家族。
3. 情绪强度。
4. 持续状态还是瞬间反应。
5. 最后参考问号、感叹号和省略号等标点。
6. 在当前角色的合法候选中选择具体 `face_id`。

例如“总、总之！”优先判断为慌乱掩饰，不因句末感叹号直接升级为羞恼或愤怒。

## 4. 官方与自定义资源能力

### 4.1 语义能力等级

每个角色的表情资源具有以下能力等级：

- `rich`：有视觉模型标注、人工覆盖或完整多轴语义。
- `basic`：有官方名称、旧版情绪和使用语境，但没有完整多轴标注。
- `unknown`：只有编号或不可靠名称，程序允许其作为合法资源存在，但不让模型猜测含义。

来源优先级：人工修正 → 丰富视觉标注 → 旧视觉标注 → 官方基础语义 → Spine 部件名称解析 → 未知。

官方角色没有视觉标注时直接走 `basic`；未来接入便宜视觉模型后，可将同一资源记录增量升级为 `rich`，无需重写剧情生成链路。

### 4.2 自定义 Spine 标注流程

现有“渲染 Spine、渲染每个表情头像、统一裁切、九宫格视觉识别、低置信度复核、缓存和重试”流程保留。

需要调整的部分：

- 视觉模型 Schema 增加上述多轴字段，但新字段全部可选。
- 已有 `spine_signature + outfit_key + face_id` 且模型版本未变化的结果直接复用。
- 只对新增表情、骨骼签名变化或低置信度记录重新标注。
- 旧两字段记录自动以 `basic` 兼容读取；人工覆盖继续优先于 AI 原值。
- 标注缺失或视觉模型不可用时，渲染结果仍可进入素材库，状态为 `basic` 或 `unknown`，不阻塞剧本生成。

资源合并层不再把完整语义永久压成单一字符串；对旧消费者继续提供兼容的 `semantic_cn` 展示值。

## 5. 演出导演规则

### 5.1 表情、气泡与动作

不再使用“10 行最多 2–3 个气泡”“相邻气泡一律删除”等硬限制。改为：

- 普通连续气泡可合并或降低频率。
- 喜剧节拍允许更高频的 `Surprise`、`Steam`、`Dot` 等气泡。
- 情绪峰值允许“表情 + 气泡 + 动作”组合。
- `jump` 用于单次短促反应；`hophop`既可表示持续兴奋，也可表示连续两下的愤怒爆发。
- 相邻强动作只有在语义连续且强度递进时保留，否则降级或清除。
- 后处理优先降级强度或替换重复动作，不直接删除所有相邻演出；只清除非法资源或明显冲突。

确定性兜底只覆盖高确定性语义：

- `！？/？！` 提供 Surprise 候选。
- 持续抱怨、压着火气、生闷气提供 Steam 候选。
- 强烈短促反驳至少考虑一次 `jump`。
- 普通感叹号不会单独触发 `jump`。
- `……` 只有构成明确沉默反应时才使用 Dot。

### 5.2 登场渐变

触发条件：

- 当前场景首次出现。
- 切换场景后再次出现。
- 连续离镜达到 8 条有效对白后再次出现。

多人画面按正常自动槽位渐变，只有单人画面居中。渐变与该角色首句放在同一节点，不增加独立空文本、不写显式 `#wait`，也不额外制造 1–1.5 秒停顿。少于 8 条对白的短暂切镜直接回镜，不重复渐变。

### 5.3 无台词 `wait`

普通对白行继续使用严格一行一响应协议；另增加独立 `beats` 数组表达导演留白：

```json
{
  "anchor_id": "line-42",
  "position": "after",
  "who": "凯伊",
  "face": "31",
  "emo": "Dot",
  "act": "",
  "wait_ms": 2500
}
```

编译器将其生成为空文本反应节点。气泡默认停顿约 2500ms、动作或进退场约 1500ms 时，不重复叠加显式等待；显式 `wait_ms` 仅用于真正需要导演控制的无台词反应。

## 6. 上下文与性能

资源库和本地 allowlist 保持完整；每次请求只发送：

1. 当前角色的完整基础表情。
2. 根据台词筛出的丰富候选。
3. 最近表情、气泡、动作和场景状态。
4. 当前场景可能用到的背景、音效和特效候选。

剧本普通批次目标为 40–50 行，保留场景边界和共享状态。默认仍按状态依赖串行；没有共享角色状态的场景才允许并行。失败按 50 → 30 → 20 行回退，而不是整章重跑。

每批只传递短状态对象，例如 `visible_characters`、`last_faces`、`recent_emoticons`、`scene_tone` 和 `open_threads`。静态规则、完整资源表和当前批次数据分离，以便端点缓存和减少重复传输。

## 7. 失败处理与质量指标

每次生成记录请求次数、输入/输出 token、总耗时、重试次数、合法资源率、表情/气泡/动作密度、`wait` 数量、低置信度数量和人工修正数量。

优化必须同时满足：

- 总耗时和 token 明显下降。
- 合法资源率不下降。
- `Surprise`、`Steam`、`Dot`、`jump` 示例稳定命中。
- “总、总之！”优先判为慌乱或掩饰。
- 无台词反应节点可保留。
- 无视觉标注官方角色仍可生成。
- 自定义角色完成视觉标注后质量高于基础模式。
- 登场渐变不产生额外独立停顿。

## 8. 非目标

- 不删除官方或自定义资源。
- 不强制所有角色先完成视觉标注。
- 不用关键词表取代剧情模型对反讽和混合情绪的理解。
- 不修改 Spine 源文件、atlas 几何或运行时角色资源。
- 不为了提速并行所有场景，破坏跨场景状态。
