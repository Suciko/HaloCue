# HaloCue 0.9 Beta：B站介绍视频策划

- 日期：2026-08-09
- 状态：创意方向已确认，待用户复核书面规格
- 产品：HaloCue 0.9 Beta
- 副标题：AzureArchive 剧情演出工具
- 目标时长：约 5 分钟，允许在 4 分 30 秒至 5 分 30 秒之间调整

## 1. 视频目标

视频首先面向已经使用 AzureArchive 的《蔚蓝档案》二创作者，证明 HaloCue 能把一整章已经写好的中文剧情转化为可审查、可运行的 AA 演出工程。观众看完后应当：

1. 理解 HaloCue 解决的是表情、动作、站位、镜头、背景和声音的重复编排工作，而不是代写剧情。
2. 相信它能处理长篇、多场景剧情，而非只对短演示样例有效。
3. 愿意加入交流群获取群内整合测试版并参与试用。
4. 知道核心代码公开，并欢迎开发者参与。
5. 知道手机版计划在下一个版本推出。

## 2. 核心定位与措辞

主品牌始终写作 `HaloCue`，首次完整出现时使用：

> HaloCue 0.9 Beta  
> AzureArchive 剧情演出工具

“AA 自动写剧本”和“AA 剧本编译器”均为历史工作名，不作为视频产品名。视频不得把 HaloCue 描述为自动创作剧情的工具。推荐的一句话定位是：

> HaloCue 把已经写好的中文剧情，变成可以审查并在 AzureArchive 中运行的演出工程。

技术宣传坚持以下事实边界：

- AI 理解剧情上下文并提出演出安排，不改写原台词。
- AI 不直接生成 AAP；审查后的中间标注由确定性编译器转为 AA 工程。
- 模型只能使用已登记、真实存在的角色与素材。
- 长剧情按场景处理并保存进度，中断后可以继续。
- 用户保留审查、修改和最终决定权。

## 3. 创意路线

采用“长剧情压缩展示 + 成果证明 + 少量技术解释”的成果先行路线。开场不能先正常播放一段普通 AA 剧情，以免观众误以为这是二创故事视频。第一秒即显示 HaloCue 品牌，并在 20 秒内连续展示长剧本、生成过程和 AA 成品。

内容比例约为：

- 70% 真实软件操作与 AA 成果。
- 15% 普通观众能理解的 AI 与编译流程。
- 15% 开源说明、试用引导、开发者招募和手机版预告。

## 4. 演示案例选择

使用一篇完整的长剧情，而非专门为宣传编写的 30 秒短样例。演示章节应满足：

- 至少包含三个明显场景，能展示背景切换。
- 至少包含三名有立绘角色，能展示角色识别和演员映射。
- 包含情绪转折、人物进退场、动作和可听见的环境或物理声音。
- 已经在 HaloCue 与 AA 中完整跑通，录制时不会依赖临时修复。
- 不包含未公开剧透、个人敏感信息、API Key、本机路径或无权公开的素材。

开场正常速度保留的片段应当在一句或两句台词内同时体现表情变化、动作或气泡变化；不选择只靠长对白推进的片段。

## 6. 快进与剪辑规则

生成等待过程和 AA 长篇成品都需要快进，但作用不同：

- 生成过程用于证明处理规模。删除所有无状态变化的等待，只保留进度、场景名和阶段发生变化的画面；采用延时、跳切和进度数字叠加，不连续播放加载动画。
- AA 成品快进用于证明整章内容丰富。以 2–4 倍速和速度渐变跨越多个场景，不把对白高速播放产生的尖锐声音留在成片中。
- 开头必须保留 6 秒左右的 1 倍速演出片段，后半段再保留一个 8–12 秒的 1 倍速片段。全片如果只有快进，观众无法判断质量。
- 快进片段使用音乐和界面音效承接；正常速度片段恢复 AA 原声或清晰的剧情音效。

## 7. AI 技术段落

技术段落只解释能建立可信度的系统边界，不罗列模型名称、参数或接口配置。推荐旁白：

> HaloCue 并不是让 AI 直接生成 AAP 文件。AI 负责理解上下文，提出表情、动作、镜头和声音等演出安排；这些安排只能使用已经登记的真实素材，并且可以逐项审查。确认之后，再由确定性的编译器生成 AA 工程。

画面使用一条六阶段流程线，并穿插三类真实证据：场景分段进度、可审查的演出建议、最终 AAP 或 AA 工程。不要用抽象的“AI 大脑”“黑科技网络”动画代替实际界面。

## 8. 开源、Spine 与群内版本说明

推荐旁白：

> HaloCue 的核心代码会在 GitHub 开源。由于 Spine 相关组件存在公开分发限制，GitHub 版本不会包含这部分。加入交流群可以获取已经整理好的群内整合测试版，不需要另外安装 Spine。

公开表达遵循以下边界：

- 群内版本称为“整合测试版”，不称为“破解包”或以“完整版”贬低公开版本。
- 仅在确认具有相应分发权后，才宣传和提供含第三方组件的整合包。
- 不展示第三方组件的二进制来源、授权信息、破解方式或绕过授权的方法。
- 明确 HaloCue 是第三方创作工具，不宣称获得《蔚蓝档案》、AzureArchive 或相关权利方的官方授权。

片中只展示发布时有效的群二维码与 GitHub 仓库首页，不口播容易变化的群号和完整网址。二维码画面至少停留 6 秒，并在视频简介和置顶评论重复提供获取方式。

最终定格文案：

## 10. 配音、声音与字幕

- 使用 GPT-SoVITS 生成中文旁白，选择自然、清晰、不过度角色化的讲解音色。
- 旁白以短句为主，每句只表达一个信息；语速约每分钟 200–230 个汉字。
- 最终旁白控制在约 850–1000 个汉字，为 AA 原声片段和视觉停顿留出空间。
- 自动字幕必须人工校对 `HaloCue`、`AzureArchive`、`AAP`、`Spine` 和角色名。
- 背景音乐保持低于旁白，不使用会遮蔽界面提示音的高密度曲目。
- 视频简介注明旁白使用 AI 语音合成，按发布时平台提供的 AI 内容标识如实申报。

## 11. 视觉与品牌

- 16:9、1080p 或更高分辨率录制；软件界面文字必须在手机端播放器中仍可辨认。
- HaloCue 图标与名称从第一秒出现，开场快进期间以小型角标持续存在。
- 重点操作使用局部放大、光标强调和一句话字幕，不使用大量箭头同时指向多个区域。
- 避免满屏代码。开发者招募通过流程设计和真实运行结果建立可信度。
- 推荐工作标题：`我做了一个能把整章剧情变成 AA 工程的工具｜HaloCue 0.9 Beta`。
- 推荐封面主文案：`一整章剧情 → AA工程`；HaloCue 标识作为副信息，不在封面堆叠功能列表。

## 12. 录制素材清单

录制前一次性准备：

1. 已跑通的长篇原始剧情及无敏感信息的副本。
2. HaloCue 从导入、初审、生成、审查到编译安装的完整录屏。
3. 生成进度的近景录屏，确保场景名和进度数字可读。
4. 两个可用于正常速度播放的 AA 高质量片段。
5. 三个以上场景的 AA 快进蒙太奇素材。
6. GitHub 仓库首页或发布页录屏。
7. 发布时有效的群二维码。
8. HaloCue 图标、透明背景版本和统一标题字样。
9. 不含 API Key、本机路径、聊天通知和个人账号信息的干净桌面环境。

## 13. 不在本视频展开的内容

以下内容留给后续教程，避免介绍视频失焦：

- API 与模型配置的逐项教学。
- 自定义角色、背景、音效和骨骼的完整导入流程。
- 所有审查按钮、卡片操作和高级指令。
- 安装环境排错、开发部署和源码结构详解。
- 手机版的具体功能承诺；本视频只确认其计划在下个版本推出。

## 14. 成功标准

成片发布前必须满足：

- 前 5 秒能看见 HaloCue 名称，并能判断这是 AA 创作工具而非普通剧情视频。
- 前 20 秒同时展示长剧情规模、生成过程和可判断质量的正常速度成品。
- 至少一次明确说出“不改写原台词”和“AI 不直接生成 AAP”。
- 人工审查、真实素材约束、长剧情续作和确定性编译均有真实画面或界面证据。
- 开源版本、群内整合测试版和 Spine 公开分发限制的说明不互相矛盾。
- 结尾同时包含试用入群、开发者参与和手机版下版本预告，但主行动仍是加入测试。
- 全片不出现 API Key、个人路径、未授权素材包内容或无法验证的效率数字。
