# HaloCue 安卓端仅导出模式设计

日期：2026-08-10

## 背景与结论

HaloCue 已在 vivo X100s Pro、Android 16、OriginOS 16 上完成本地 Python 启动、真实 `script2aap` 编译和 `MediaStore` 公共目录导出验证。

真机同时确认：普通 APK 无法把文件写入原版 AzureArchive 的 `Android/data/com.foxxlight.AzureArchive/` 专属目录。vivo 文件管理器的复制目标界面也无法进入 `Android/data`。这属于系统权限边界，不是继续补充目录标签或辅助功能导航可以解决的问题。

因此安卓端采用仅导出模式：HaloCue 负责生成、保存和分享 `.aap`；用户自行决定后续如何导入原版 AA。应用不再申请辅助功能授权，也不再声称自动导入成功。

## 用户流程

1. 用户输入工程名和剧本文本。
2. 用户点击“生成工程文件”。
3. HaloCue 在应用私有工作区运行现有编译核心并校验生成结果。
4. HaloCue 通过 `MediaStore.Downloads` 把文件发布到 `Download/HaloCue/<工程名>.aap`。
5. 页面显示“已生成，尚未导入原版 AA”，并显示公共目录中的文件名和相对位置。
6. 用户可以点击“分享工程文件”，通过系统分享面板发送到电脑、网盘或其他工具。
7. “打开原版 AA”继续保留，但只负责启动原版应用，不暗示文件已经导入。

## 架构调整

### 保留

- `AndroidCompilerBridge` 和 Chaquopy Python 3.13 运行时。
- 已同步的真实 `script2aap` 编译核心及其 Python 合同测试。
- `AapPublicExporter`，继续使用 `IS_PENDING` 安全发布到 `Download/HaloCue/`。
- 原版 AA 包名检测与启动能力。
- 应用内 WebView 外壳和现有窄屏布局基础。

### 移除

- `VivoAaImportAccessibilityService` 及其清单注册和服务配置。
- `AaImportCoordinator`、`AaImportTaskStore` 和 vivo 文件管理器导航状态机。
- 首次辅助功能授权卡片、继续导入按钮和自动导入状态。
- “生成并导入原版 AA”“已导入原版 AA”等无法被普通 APK 证明的文案。
- 仅服务于自动复制流程的测试和设备脚本。

### 新增或调整

- 原生编排改为“编译 -> 公共导出 -> 返回导出结果”。
- 页面消费统一的导出状态：`IDLE`、`GENERATING`、`EXPORTED`、`FAILED`。
- 导出成功载荷只包含 `displayName`、`relativePath` 和 `shareAvailable`；最近一次导出的 `content://` URI 只保留在原生层，页面不接触 URI 或私有工作区路径。
- 增加“分享工程文件”桥接方法，以 `ACTION_SEND`、`FLAG_GRANT_READ_URI_PERMISSION` 和 `application/octet-stream` 打开系统分享面板。
- 分享功能只对最近一次成功导出的文件启用。应用重启后用户仍可直接在公共下载目录找到文件，不额外引入持久化索引。

## 数据与安全边界

- HaloCue 只删除自己通过 `MediaStore` 记录的上一次同名公共暂存项。
- 不读取、覆盖或删除原版 AA 的项目和存档。
- 不申请传统存储权限、所有文件访问权限或辅助功能权限。
- 不把 ADB、Root、Shizuku 或修改版 AA 当作普通用户能力。
- 分享时只向用户选择的目标应用临时授予当前文件的读取权限。

## 错误处理

- 编译失败：显示“生成失败”及可理解的错误摘要，不创建公共成功记录。
- 公共目录写入失败：保留私有编译结果，显示“保存到下载目录失败”，不显示分享按钮。
- 分享目标不可用：保留导出文件，并提示用户可前往 `Download/HaloCue/` 查找。
- 原版 AA 未安装：“打开原版 AA”不可用或提示未安装，不影响生成与分享。
- 任意失败状态都不能显示“已导入”。

## 界面文案

- 主按钮：`生成工程文件`
- 初始状态：`尚未生成`
- 处理中：`正在本机生成…`
- 成功状态：`已生成，尚未导入原版 AA`
- 成功说明：`文件已保存到 Download/HaloCue/`
- 次要操作：`分享工程文件`、`打开原版 AA`

页面不显示辅助功能说明、自动复制步骤或权限引导。

## 测试策略

- Python 合同测试继续验证真实编译核心和生成文件结构。
- JVM 测试覆盖导出状态映射和失败时不产生“已导入”状态。
- Android 仪器测试继续验证 `MediaStore` 文件内容、名称、相对路径和无存储权限运行。
- 分享意图测试验证 MIME、URI 和临时读取授权。
- 真机页面契约验证主按钮、状态文案、分享按钮及辅助功能文案缺失。
- 真机验收使用唯一工程名，确认文件存在于公共目录、系统分享面板可打开、原版 AA 项目目录未被修改。

## 版本与迁移

- 下一个可交付开发版本为 `versionCode = 3`、`versionName = "0.3.0-dev"`。
- 覆盖安装后清理旧的自动导入任务偏好，但保留已经导出的公共 `.aap`。
- 关闭或删除旧辅助服务后，系统设置中不应再显示 HaloCue 自动导入项目。
- 设备验证产生的唯一探针文件和 UI dump 在验收后按明确文件名清理。

## 非目标

- 不在普通版本中集成 Root、Shizuku 或厂商私有权限。
- 不修改、重签、注入或替换原版 AzureArchive。
- 不承诺在手机上完成原版 AA 的项目导入。
- 不迁移完整桌面 WebUI 的所有高级能力；本次只收口生成、导出和分享闭环。

## 验收标准

- APK 能在目标 vivo 设备上独立生成真实 `.aap`。
- 文件发布到 `Download/HaloCue/`，退出应用后仍可访问。
- 系统分享面板能读取并分享最近生成的文件。
- 应用不申请或依赖辅助功能权限。
- 界面始终明确区分“已生成”和“已导入”。
- 原版 AA 及其现有项目保持不变。
