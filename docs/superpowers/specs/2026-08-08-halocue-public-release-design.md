# HaloCue 0.9 Beta 开源与双版本发布设计

- 日期：2026-08-08
- 状态：已确认方向，待用户复核书面规格
- 产品名称：`HaloCue`
- 产品版本：`0.9.0-beta.1`
- 公开仓库：`Suciko/HaloCue`

## 1. 目标

将当前开发目录整理为可公开、可复现、可在其他 Windows 电脑运行的 HaloCue 0.9 Beta，并形成三个边界清晰的交付面：

1. GitHub 公开源码仓库：公开全部原创运行源码、前端源码、测试、开发工具和经过清洗的用户文档。
2. GitHub 公开 Release：普通用户无需预装 Python，解压后双击启动，只需选择自己的 AzureArchive 安装或工作区。
3. 本地私发 Release：以公开 Release 为基线，可在确认具有分发权后额外加入 Spine 程序；任何情况下都不加入个人骨骼、游戏素材或用户作品。

首发不以“绝对没有 Bug”为不可验证承诺，而以可重复执行的发布门槛控制风险。任一硬性门槛未通过时，不发布对应产物。

## 2. 品牌与版本

沿用已确认的 HaloCue 品牌方案：

- 主品牌固定写作 `HaloCue`。
- 中文副标题为“AzureArchive 剧情演出工具”。
- 英文副标题为“Narrative Staging for AzureArchive”。
- 普通界面显示 `HaloCue 0.9 Beta`。
- 程序元数据、诊断信息、标签和文件名使用 `0.9.0-beta.1`。
- 公开包命名为 `HaloCue-0.9.0-beta.1-windows.zip`。
- 私发包命名为 `HaloCue-0.9.0-beta.1-private-windows.zip`。

### 2.1 原创程序图标

HaloCue 使用独立原创的“光环 + 提示符”程序图标：深海军蓝圆形核心内放置白色演出提示三角，外围由三段不对称青蓝光环、两个定位刻度和一个珊瑚色提示点构成。它只提炼轻盈发光、同心环和科技分段等一般视觉语言，不复刻任何具体角色光环、校徽、官方标识或人物素材。

仓库只保留最终原创资产：`branding/halocue-icon.png`（1024×1024、透明背景）、`branding/halocue-favicon.png`（64×64、透明背景）和 `branding/halocue.ico`（16–256 像素多尺寸）。参考图片、生成过程中的洋红底原图和视觉检查拼图不进入仓库或任何 Release。图标用于 Windows 可执行文件、浏览器 favicon、README 和程序界面；在 16、32、48、64、128、256 像素及明暗背景上都必须保持可辨识。

“AA 自动写剧本”和“AA 剧本编译器”仅在迁移说明中作为历史工作名出现一次。现有 Python 模块名和已有用户数据不因品牌更名而强制迁移。

## 3. 当前审计基线

当前开发环境的完整测试结果为 `1173 passed, 2 skipped`，说明主代码基线稳定。发布审计同时发现以下不能带入首发的缺口：

- 现有 `prepare_release.py` 漏掉运行模块、`js/` 和 `css/`，生成包无法导入 `webui.py`。
- 现有发布包错误包含本机生成的 `aa_resources.json` 和内部开发文档。
- 现有 `requirements.txt` 在中文 Windows 默认编码下无法被 pip 读取。
- 代码使用 Python 3.10 语法，但启动器和文档错误宣称支持 Python 3.9。
- 纯 Git 文件复制到全新 Python 3.12 环境后，测试结果为 `1123 passed, 22 failed, 4 skipped, 26 errors`；失败主要来自测试依赖未公开的本地配置、索引、私人演员表和未安装的 Playwright 浏览器。
- 原始 `aa_assets.db` 含 147 处本机路径、个人工程记录或缓存路径，不能原样发布。
- `docs/custom-assets-test-report.md` 和 `docs/superpowers/` 含个人路径、真实测试工程名与内部实施记录，不进入公开仓库。

这些问题属于发布工程与测试隔离缺口，不能由“本机测试全过”替代修复。

## 4. 公开源码仓库

### 4.1 建仓方式

公开仓库使用干净首提交，不直接推送当前开发仓库历史。现有历史未发现大体积素材对象，但包含本机路径和内部实施文档；干净首提交能避免已删除内容继续留在 Git 对象中。

公开仓库应包含：

- 全部原创 Python 运行源码。
- `js/`、`css/`、`ui.html` 等全部前端源码。
- `tests/` 全部测试源码，但测试必须改成只依赖公开夹具或临时目录。
- `tools/` 全部开发诊断工具，但示例参数必须使用通用路径。
- `README.md`、普通用户说明、格式说明、命令说明和演出说明。
- 通用示例配置和不含个人作品的最小示例剧本。
- 构建脚本、发布清单、运行依赖、开发依赖和 CI 配置。
- MIT `LICENSE`、第三方声明和项目免责声明。
- 经过确定性清洗与复查的公开标注数据库。

### 4.2 不进入公开仓库的内容

- `.skel`、`.atlas`、角色贴图、背景、CG、头像、音频和 AssetBundle。
- Spine Editor、Spine CLI、Spine Runtimes 或任何第三方二进制，除非另有明确兼容许可和分发方案。
- `aa_config.json`、`llm.json`、`llm_profiles.json`、API Key、凭据和本机路径。
- 原始 `aa_assets.db`、本机 `aa_resources.json`、安装记录、个人别名和个人工程索引。
- 个人演员表、剧本、章纲、输出工程、配音和其他创作内容。
- `out/`、`output/`、`.thumbs/`、`.playwright-cli/`、缓存、日志和截图。
- `.superpowers/`、`docs/superpowers/`、真实素材测试报告和其他内部实施记录。

## 5. 公开标注数据库

### 5.1 原则

可公开的是原创或机器生成的文字标注与互操作元数据，不是产生这些标注的原始素材。公开数据库必须由脚本从开发数据库生成，不能通过人工复制原数据库完成。

### 5.2 清洗规则

公开数据库生成器应：

- 从全新 SQLite 文件和当前公开 schema 开始。
- 保留通用背景、音效、角色、表情、枚举及其语义标签。
- 保留个人骨骼产生的纯文字表情标注和表情语义组合；标注本身可以公开，但不得附带骨骼、预览图或本机记录。
- 删除 `asset_install`、用户素材库档案、个人别名和其他工作区状态。
- 删除所有绝对路径、缓存图片路径、安装路径、个人工程名和本机来源字段。
- 背景、音效和骨骼专用标注可以保留稳定名称、角色标识、表情编号、语义文本和用于防止误匹配的内容签名；内容签名只是校验元数据，不提供或还原原始素材。
- 删除视觉缓存文件引用、安装状态、项目归属和无法脱离个人工作区解释的状态记录。
- 对 JSON 文本字段递归清除路径类键和值，不能只清空顶层列。
- 写入公开数据库版本、生成器版本、源 schema 版本和生成时间，不写开发数据库路径。
- 生成后执行 `VACUUM`，保证删除内容不残留在 SQLite 空闲页。

### 5.3 数据库验收

公开数据库必须满足：

- 全库扫描不存在 Windows、UNC、Unix 用户目录或 URL 凭据形式的路径。
- 不存在 API Key、访问令牌、邮箱、电话号码或用户名标识。
- 不存在素材二进制 BLOB。
- 不存在 `asset_install` 和个人别名记录。
- 骨骼相关记录只含标识、内容签名和文字标注，不含骨骼字节、纹理、预览图或文件系统位置。
- 随机抽样角色、背景、音效和表情标签能被程序正常加载。
- 使用公开数据库运行数据库迁移两次结果一致。

## 6. 公开 Release

### 6.1 形式

公开 Release 使用 Windows x64 一目录便携包。包内携带 HaloCue 所需 Python 运行时和第三方 Python 依赖，目标电脑无需预装 Python。采用一目录而非单文件形式，便于稳定携带网页静态资源、SQLite 数据库和许可证文件，也减少首次启动自解压与杀毒软件误报风险。

公开包至少包含：

- HaloCue 启动程序。
- 全部运行模块与前端静态资源。
- HaloCue 原创程序图标、Windows 多尺寸图标和网页 favicon。
- 清洗后的公开标注数据库。
- README、普通用户说明、MIT License 和第三方许可证声明。
- 可供诊断的版本与构建清单。

公开包不包含测试、内部文档、开发工具、本机索引、任何 Spine 程序或任何素材。

### 6.2 首次运行

首次启动流程为：

1. 验证包完整性和公开数据库可读性。
2. 尝试从当前用户的 AzureArchive 设置中只读发现安装与工作区。
3. 未发现时弹出文件选择器，让用户选择 `AzureArchive.exe`；仍不能识别时允许选择含 `projects` 的 `data` 或其上级工作区。
4. 将用户配置保存到 `%LOCALAPPDATA%\\HaloCue`，不写入程序包目录；继续兼容读取旧版程序目录中的 `aa_config.json`。
5. 启动仅监听 `127.0.0.1` 的本地服务并打开浏览器。
6. 设置页显示 AA 工作区、资源包、图片预览和模型配置的独立状态；缺少 Spine 只禁用 Spine 表情渲染，不阻止其他功能。

错误信息必须告诉用户缺少什么、如何处理以及诊断日志位置，不能只显示 Python 堆栈。

### 6.3 路径与机器隔离

- 程序不得依赖开发者盘符、用户名、桌面路径或当前工作目录。
- 所有程序内资源都相对可执行文件或打包资源根目录解析。
- 用户数据、配置、日志和缓存写入当前用户的 LocalAppData；用户作品继续写入用户选择的 AA 工作区。
- 发布包可放在任意可读目录，包括含空格和中文的路径。
- 只读扫描 AzureArchive 程序、设置和资源缓存；除用户明确执行安装操作外，不写 AA 目录。

## 7. 私发 Release

私发 Release 由同一个确定性构建流程产生，以已经通过验收的公开 Release 为输入，只允许额外加入经授权的 Spine 程序目录。

私发构建器必须：

- 通过显式 `--spine-source` 参数接收外部 Spine 目录，源码和默认配置不写死私人路径。
- 在复制前要求记录分发授权确认；没有确认时拒绝构建含 Spine 的包。
- 只允许 Spine 程序和运行所需的官方随附文件，不扫描或复制邻近用户目录。
- 对输入和最终包递归拒绝 `.skel`、`.atlas`、`.spine`、`.aap`、`.aas`、AssetBundle、贴图、背景、CG、头像、音频、激活码、用户邮箱和许可证凭据。
- 将 Spine 目录列入私发构建清单，但不把二进制、哈希、绝对来源路径或私发包上传到公开 GitHub。
- 首次启动优先使用包内已授权 Spine；不存在时允许用户选择自己的 Spine 安装。

个人骨骼和游戏素材在公开版与私发版中都属于绝对禁止项。

## 8. 依赖与许可证

- HaloCue 原创代码使用 MIT License。
- README 明确 MIT 不覆盖 AzureArchive、Spine、Nexon、Yostar 或其他第三方程序与素材。
- 公开便携包若携带 Python 和第三方依赖，必须收集并附带对应许可证与版权声明。
- OpenAI-compatible 接口继续使用标准 HTTP，不把不需要的 OpenAI SDK 列为强制运行依赖。
- Anthropic、UnityPy、Pillow 和 Windows 凭据支持按实际运行路径确定是否打包；不能仅凭旧 requirements 延续无用依赖。
- Spine Editor 或 Runtimes 不适用 HaloCue 的 MIT License，必须遵守其独立许可。

## 9. 测试与发布门槛

### 9.1 源码门槛

- 从公开文件清单复制到全新目录，不带任何 ignored 文件。
- 安装 `requirements-dev.txt` 和浏览器测试依赖。
- 源码明确支持 Python 3.10 至 3.13，并至少在 Python 3.10、3.12 和 3.13 上运行完整测试。
- 全部必需测试通过；缺少可选外部软件的测试必须明确跳过，不能在收集阶段报错。
- 测试不得读取开发者真实 AA、私人演员表、原始数据库、`llm.json` 或 `out/`。

### 9.2 公开包门槛

- 从干净构建目录生成，不读取工作区 ignored 文件。
- 包内模块导入、静态资源清单、数据库迁移和入口启动全部通过。
- 在没有系统 Python 的 Windows 环境中可启动。
- 在没有 AA 配置时能进入选择流程；使用合成 AA 工作区完成保存配置、重启和重新发现。
- `GET /`、CSS、JavaScript 和设置状态接口全部返回成功，浏览器控制台没有启动错误。
- 使用 mock 模型完成最小“导入剧本—初审—生成草稿—编译”流程。
- 对包执行密钥、绝对路径、个人信息、禁止扩展名和大文件扫描，结果为零。
- ZIP 解压到含中文、空格和较长路径的目录后重复一次启动测试。

### 9.3 私发包门槛

- 先完整通过公开包门槛。
- 在没有任何骨骼或素材的情况下发现并调用包内 Spine 程序。
- 对私发包执行与公开包相同的内容扫描，并额外验证仅授权 Spine 目录构成公开包之外的差异。
- 用合成 Spine 夹具验证路径传递；真实骨骼只做本机人工验收，不进入测试夹具、日志或产物。

### 9.4 发布证据

每次 Release 记录：

- Git 提交 SHA。
- 完整版本号。
- Python、依赖与打包工具版本。
- 源码测试、公开包冒烟测试和内容扫描结果。
- ZIP SHA-256。
- 已知限制和跳过测试原因。

## 10. CI 与复现

GitHub Actions 在 Windows 上至少执行：

1. 安装运行与开发依赖。
2. 安装 Playwright Chromium。
3. 运行完整测试。
4. 生成并扫描公开数据库。
5. 构建公开便携包。
6. 对构建包运行无本机配置冒烟测试。
7. 仅在版本标签与源码版本一致时上传公开 Release 产物。

私发包只允许在本地显式构建，不进入公开 CI，也不上传到公开 GitHub Releases。

## 11. 不在 0.9 Beta 首发范围内

- 自动下载或分发 AzureArchive、Spine、游戏资源或用户素材。
- macOS、Linux 和非 x64 Windows 打包。
- 自动更新器。
- 云端服务、远程监听或遥测上传。
- 将内部开发历史、个人测试数据或真实作品迁移到公开仓库。

## 12. 完成标准

只有同时满足以下条件，HaloCue 0.9 Beta 才视为可发布：

- `Suciko/HaloCue` 的公开首提交只包含允许公开的文件。
- GitHub 源码可从零建立开发环境并通过完整测试。
- 公开便携包在不依赖系统 Python 和开发者配置的环境中完成首次启动与核心 mock 流程。
- 公开数据库和所有公开产物通过零泄漏扫描。
- 私发包与公开包的有效载荷差异仅为获授权的 Spine 程序及相应独立许可文件；包名、版本清单和私发标记允许随之变化。
- README、界面、诊断和文件名统一使用 HaloCue 与 `0.9.0-beta.1`。
