# 初审角色骨骼头像选择器设计

## 目标

让用户在 AI 初审阶段快速确认剧本角色映射到了哪套骨骼，并在修改映射时优先找到自定义骨骼。界面依靠头像、分组和选中状态传达信息，不增加引导段落。

## 范围

- 初审“角色映射”结果行显示当前骨骼头像。
- “选择对应角色”弹层按“自定义骨骼”和“官方骨骼”分组。
- 自定义骨骼始终排在官方骨骼之前。
- 搜索、旁白和未指定操作继续沿用现有行为。
- 不改动骨骼导入、表情标注和背景标注流程。

## 交互设计

### 初审角色行

每一行使用紧凑横向布局：头像、剧本角色与映射信息、修改按钮。头像约 40px，显示当前映射骨骼的预览；旁白、未指定或缺少预览时显示稳定的文字占位。映射信息继续标明“自定义骨骼”或“官方骨骼”。

### 骨骼选择弹层

候选项使用紧凑列表，不改为大图网格。每项显示约 52px 头像、角色名、角色标识、社团和已标注表情数量。列表按以下顺序分组：

1. 自定义骨骼
2. 官方骨骼

空分组不显示。搜索同时过滤两个分组，过滤后仍保持自定义优先。当前已映射的骨骼具有明确的选中状态和无障碍属性。

### 图片回退

接口已有头像地址时直接使用。头像地址为空或图片加载失败时，显示角色名首个可见字符；占位区域尺寸固定，避免图片加载造成布局跳动。

## 数据与边界

现有 `/api/characters` 已返回 `avatar` 与 `source`，选择弹层直接使用这两个字段。初审当前映射如果没有头像字段，前端通过已经加载的候选角色信息按角色标识补全，不把本机文件路径暴露到页面。来源值统一归并为“自定义”或“官方”，未知来源按官方分组处理，确保旧数据仍可选择。

## 错误处理

- 头像加载失败只回退占位，不影响选择。
- 角色搜索失败继续显示现有失败状态。
- 某一分类为空时隐藏标题，不显示空卡片或额外说明。
- 所有列表项保持键盘可聚焦，并提供当前选中状态。

## 验证

- UI 运行时测试验证自定义分组先于官方分组。
- 测试验证头像、缺图占位、当前选中状态和搜索后的分组顺序。
- 测试验证选择自定义骨骼后，初审行显示自定义来源与对应头像。
- 在桌面和窄屏浏览器中检查弹层无横向溢出，长角色名不会遮挡按钮。
