# HaloCue 0.9.2 官方演出导演规律研究与状态化导演层设计

## 1. 目标与边界

HaloCue 的输入是已经写好的、没有 AA 演出标注的剧本。AI 的职责是为原剧本补充 `(face)[emo]{act}<fx>`、`@...` 以及确有必要的无台词 beat；AI 不改写、增删、润色台词，也不输出官方剧情文本。

本设计的目标是从官方主线、活动和羁绊剧情的连续演出中提炼导演判断过程，供 HaloCue 0.9.2 升级提示词和确定性后端使用。官方语料库只作为离线研究和派生规律的来源，不进入用户结果，不作为官方全文复刻或直接全文检索材料。

本阶段不修改生产代码，不改变 `.aap` 编译格式，不自动生成官方剧情复本。

## 2. 研究方法

研究单位不是单行密度，而是连续剧情段落。每一拍按以下顺序解释：

```text
场景功能
→ 人物关系与空间状态
→ 台词表层含义
→ 当前情绪与潜台词
→ 上一拍状态
→ 官方 face / emo / act / 镜头 / 声音 / 停顿选择
→ 下一拍承接
```

已研究的代表性完整样本：

- 羁绊：`bond:10004:3:1000405`、`bond:10013:1:1001302`、`bond:16008:4:1600806`
- 活动：`event:801:3`、`event:802:17`、`event:838:623`
- 主线：`main:101120`、`main:102110`、`main:42150`

样本覆盖私人关系、群体喜剧、说明蒙太奇、通讯、战斗、集结、威胁、情绪软化和行动命令等连续演出段落。

## 3. 核心发现

### 3.1 官方按演出段落工作

官方标注不是逐句独立决策。最小判断单元应包含 `scene_function`、`emotion_phase` 和该段的连续状态。常见段落结构包括：

- 建立空间：标题/地点、空镜或脚步、第一位角色进入；
- 登场/集结：角色按 1→2→3 人逐步加入，形成群体规模；
- 说明：空镜、旁白、背景切换和少量立绘承担信息传递；
- 问答：说话者与听者保持同屏，镜头可以落在听者反应；
- 喜剧升级：轻反应→误会→被戳穿→沉默/掩饰→升级→反差收尾；
- 冲突/威胁：立场确认后才进入特写，真正爆点才使用重背景效果；
- 情绪转折：连续无台词、微小换脸和停顿后进入新的关系状态；
- 战斗/行动：允许长段画外动作和声音，最后用正式命令或单人特写落点；
- 收尾：结束当前情绪段，同时保留下一段行动钩子。

### 3.2 三类剧情的导演重心不同

| 类型 | 主要叙事目的 | 常见演出重心 |
| --- | --- | --- |
| 羁绊 | 关系距离和私人情绪推进 | 微反应、沉默、连续保持的 face、私人特写 |
| 活动 | 群体节奏、喜剧机制和场面调度 | 同步反应、逐人入退镜、反应链升级、快速切换 |
| 主线 | 信息、危险、战术立场和空间规模 | 空镜、通讯状态、环境效果、画外动作、决断特写 |

同一个“惊讶”在三类剧情中不应使用同一套模板：羁绊可能是迟疑后轻微换脸，活动可能是群体同步气泡，主线可能是警报/通讯/镜头切换后再给单人反应。

### 3.3 人物状态需要显式建模

每个可见人物至少维护以下状态：

- `baseline_attitude`：角色一贯的说话姿态；
- `current_emotion_phase`：试探、困窘、被戳穿、压抑愤怒、软化、决断等阶段；
- `subtext`：人物想隐藏、推动或确认的内容；
- `relation_distance`：与当前对象的心理/叙事距离；
- `previous_visible_state`：上一拍 face、是否在镜、是否通讯、是否刚被打断；
- `reaction_target`：当前反应针对谁或什么事件。

这解释了几个官方常见现象：同一羞涩 face 可以跨多句保持；被戳穿后先沉默再升级；群体同步反应保持方向一致但强度不同；通讯角色即使不在现场仍维持 `sig` 和空间关系。

### 3.4 场景功能的细化规则

| 场景功能 | 可靠触发 | 常见演出序列 | 不应触发 | 结束条件 |
| --- | --- | --- | --- | --- |
| 建立空间 | 新地点、新时间、新叙事空间 | 地点/背景→环境声或脚步→人物进入→第一句 | 对话中普通话题变化 | 第一组人物和空间关系稳定 |
| 登场/集结 | 新人物或新小队需要被观众认识 | 单人进入→第二人加入→群体成形→行动焦点 | 已在镜角色的普通发言 | 人员规模和领队明确 |
| 说明/介绍 | 连续信息、路线、设施或背景知识 | 空镜/旁白→背景切换→少量人物承接 | 每句说明都切人物或加表情 | 信息结束或危机/问答打断 |
| 问答/对话 | 一方提出问题，另一方回应或回避 | 提问者→听者反应→回答者→提问者确认 | 只按说话人机械切镜 | 问题解决、回避成功或冲突升级 |
| 喜剧升级 | 认知错位、重复机制、掩饰失败 | 正常态→小异常→误解→反应链→峰值→冷处理/反差 | 单纯语气活泼；无升级证据时连续堆气泡 | 笑点落地或切入新任务 |
| 冲突/威胁 | 立场对立、命令、真实危险 | 警觉→对峙→立场确认→特写/重音→行动 | 普通感叹号、轻微抱怨 | 一方退让、行动开始或危险解除 |
| 情绪转折 | 被戳穿、得到肯定、关系靠近、认知改变 | 旧 face 保持→停顿/无台词反应→轻微换脸→新状态 | 每句情绪词都当作转折 | 新情绪连续维持两拍以上 |
| 战斗/行动 | 敌我行动、追逐、救援、物理冲击 | 环境状态→画外动作/声音→受击/爆点→队伍接管→命令 | 用对白解释所有动作；给每一枪单独重效果 | 战术阶段变化或战后对话开始 |
| 收尾/行动命令 | 当前段落情绪已经落地 | 回收环境/人物→领队或核心人物单人焦点→决定/离场 | 情绪尚未结束时提前硬切 | 转场、离场或下一场标题 |

开始和结束必须显式记录。特别是 `通讯`、`特写`、`bgfx` 和群体在镜状态，不能依赖“角色离镜才结束”这种无限继承。

### 3.5 人物与镜头焦点规则

人物演出不能等同于“当前说话者演出”。每拍先选择焦点类型：

- `speaker`：信息、立场或命令由说话者承担；
- `listener`：被戳穿、误解、等待回答或关系推进时，台词属于 A，但画面重点是 B；
- `group`：共同受到同一刺激、形成队伍或产生同步反应；
- `offscreen_space`：声音、通讯、战场动作或说明蒙太奇发生在立绘之外。

人物入镜遵循“先让观众识别，再形成关系”的原则。新人物第一次承担信息时可先给单人或清晰位置；集结时逐人加入；群体稳定后才用领队特写收束。退出也应有叙事理由，例如离场、空间切换、焦点转移或听者不再相关，而不是只因若干行没有说话。

关系距离改变时，镜头和表情一起变化：

- `distant`：礼貌、戒备或陌生，更多单人切换和较少私人特写；
- `normal`：稳定对话，双人或小群体镜头保持；
- `approaching`：关心、试探、被肯定，先给听者反应再缩短镜头距离；
- `intimate`：私人情绪已经成立，可让特写跨完整情绪段维持；
- `remote`：通讯/画外关系，保持对应显示效果和报告链。

## 4. 标注语法的语义边界

- `face` 是持续在脸上的状态。情绪阶段未变时允许保持；阶段、潜台词或关系距离改变时才换。
- `emo` 是一拍的瞬时强调。连续出现是允许的，但每一拍都必须有独立刺激或强度变化；不使用全局固定冷却。
- `act` 是原地身体反应，必须有身体证据。心理震撼不能用 `shake` 代替。
- `move` 只表示真实位置变化；因镜头人数变化产生的基础站位由后端处理。
- `fx` 表示叙事距离或显示方式：通讯、剪影、特写不是情绪强度的同义词。
- `bgfx` 是整场环境状态，可以跨多个节点保持；集中线等爆点效果应稀少且有明确落点。
- `se` 只绑定实际发生或紧邻语境可靠推出的声音；情绪本身不是音效。
- `beat` 是独立无台词反应或必要留白，不重复 AA 已有的默认停顿。

### 4.1 Face 的选择与连续性

Face 判断使用以下组合，而不是关键词或编号轮换：

```text
角色基础态度
+ 当前情绪阶段
+ 潜台词
+ 对话对象与关系距离
+ 上一个 face
+ 当前刺激强度
+ 镜头目的
→ 当前 face 语义
→ 该角色资源表中的可用编号
```

模型先选语义，再从角色专属资源表选择编号。不同角色的同一编号不保证同义；`07` 以上的高编号尤其不得按通用表猜测。当前只有上下文证据、没有真实立绘视觉标签时，只能记录“推断语义”，不能升级为素材事实。

换 face 的可靠条件：

- 情绪阶段发生变化，例如防备转为动摇；
- 潜台词改变，例如解释转为掩饰；
- 刺激强度升级，例如疑惑转为惊愕；
- 关系距离改变，例如正式回应转为私人软化；
- 镜头目的改变，例如群体状态切到个人决断。

保持 face 的可靠条件：

- 同一情绪段跨多句持续；
- 一句话被拆成多个气口；
- 连续威胁、羞涩、通讯报告或战术说明没有新刺激；
- 角色素材中没有更合适且视觉已确认的候选。

禁止为了“画面有变化”而换成语义不合的 face，也禁止把“同一 face 连续多句”一律视为错误。

### 4.2 常见情绪链

| 情绪链 | Face 变化 | 可用强调 | 镜头与停顿 | 恢复方式 |
| --- | --- | --- | --- | --- |
| 惊讶/发现 | 常态→注意→疑惑/惊愕 | 疑问、惊疑、惊叹；必要时 stiff/jump | 先看到刺激，再给反应；强刺激才短特写 | 确认事实后转认真、警觉或喜剧反应 |
| 被戳穿/尴尬 | 常态→僵住→回避/困窘 | Dot、冷汗、短 stiff；羞涩峰值才脸红 | 优先听者反应和无台词 beat | 掩饰、承认或转移话题后结束 |
| 害羞/关系靠近 | 防备/平静→动摇→羞涩 | 少量脸红或爱心，不能把友好等同爱意 | 特写可跨完整私人情绪段 | 话题转开、恢复正式态度或离场 |
| 愤怒/威胁 | 不满→压抑→爆发→命令 | 冒烟/怒筋、stiff/hophop；重爆点可集中线 | 立场确认后再特写，物理撞击才抖背景 | 行动执行、对象退让或角色主动冷却 |
| 悲伤/失落 | 否认/维持→沉默→低落 | 悲伤、叹气、落泪按强度区分 | 少切镜，多留白；不强制重效果 | 得到回应后微笑/平静，或保持到转场 |
| 认真/决断 | 思考/犹豫→确认→正式态 | 通常不需要气泡；可用点头或特写 | 由群体/信息镜头收束到决定者 | 行动开始即结束决断段 |
| 喜剧误会 | 正常→错愕→错误推理→自信升级→反差 | 气泡可连续但需逐拍变化；动作随升级增强 | 给被影响者和旁观者反应，不只看说话者 | deadpan、群体沉默或突发事件切断 |

这些是状态转移模板，不是固定动作套餐。文本没有对应刺激时，不得为了套模板补重效果。

### 4.3 Emo、Act 与重效果的组合规则

`emo` 表示瞬时心理符号，`act` 表示身体反应。两者可以组合，但必须描述同一拍：例如突然受惊可使用惊叹加 stiff；持续恼火可以先冒烟，真正爆发时再进入怒筋或 hophop。相邻重复只有在出现新刺激、强度升级、群体同步或喜剧节拍明确时成立。

强度从轻到重应遵循：

```text
face
→ face + emo 或轻 act
→ face + emo + act
→ 特写或重 bgfx
→ 物理冲击/战斗声音与背景抖动
```

一般一拍只需要其中一层或两层。只有剧情峰值才同时组合多层。背景抖动仍只服务爆炸、撞击、跌落等物理冲击，不能表现“内心受到震撼”。

### 4.4 角色专属 Face 词典

Face 编号必须按“角色 + 服装/骨骼版本”隔离建档。建议词典至少包含：

```text
character_id
outfit_key
spine_signature
face_id
primary_emotion
secondary_traits
arousal_level
control_level
social_stance
visual_evidence
confidence
review_status
```

证据分为三级：

1. `visual_confirmed`：真实立绘渲染图已经人工或视觉模型确认，可用于自动选择；
2. `asset_semantic`：素材自身存在稳定语义名或可靠元数据，可用于自动选择并保留来源；
3. `context_inferred`：只能根据官方上下文推断该编号当时承担的情绪功能，只用于研究，不直接作为视觉事实写入资源表。

同一 face 可能同时包含“轻笑 + 无奈”“认真 + 戒备”等复合特征，不能只存一个宽泛情绪词。模型选 face 时，应同时匹配情绪方向、强度、控制程度和社交姿态；没有 `visual_confirmed` 或 `asset_semantic` 候选时，留空或进入人工审阅。

## 5. 统一场景决策模型

AI 在处理一段剧本时，先建立段落状态，再生成行级标注：

```text
scene_type
scene_function
space_state
relation_state
emotion_phase
visible_cast
focus_target
environment_state
continuity_state
```

每一行的决策顺序为：

1. 判断该行是否改变场景功能、空间或关系状态；
2. 确认当前说话者、听者/受影响者和反应目标；
3. 读取上一拍 face、emo、动作、焦点和环境状态；
4. 选择最小充分演出层，优先保证语义和承接；
5. 判断是否需要无台词 beat、镜头焦点切换或环境状态持续；
6. 生成行级字段，并更新连续状态；
7. 将无法由素材或上下文证明的选择交给人工审阅。

## 6. 提示词、协议与后端的职责

### 6.1 AI 提示词

提示词应新增但不暴露为台词改写能力的内部判断字段：

- 剧情类别：`main / event / bond`；
- 场景功能：上述九类功能之一；
- 当前情绪阶段和潜台词；
- 反应焦点：`speaker / listener / group / offscreen_space`；
- 连续状态：开始、维持、升级、结束；
- 标注理由的短枚举，而非长篇解释。

AI 仍只返回原文对应的行级标注和必要 beat，内部判断值用于约束决策、审阅和回归，不进入最终 AA 文本。

### 6.2 标注协议

现有行级字段继续兼容。协议需要补充段落/状态元数据和可验证的焦点信息，至少包括：

- `scene_function`、`emotion_phase`；
- `focus_target` 和 `reaction_target`；
- `visible_characters` 的显式意图，而不只是状态快照；
- `continuity`：`start / hold / escalate / end`；
- beat 的来源行、角色、等待时长和插入原因枚举。

这些字段必须能被后端校验，非法值降级为空并进入审阅，不得改变原台词。

### 6.3 确定性后端

后端负责资源和编译契约，而不是重新猜剧情：

- 验证 face/emo/act/fx 和音效资源；
- 继承并结束持续特写、通讯和 `bgfx`；
- 根据焦点意图布置说话者、听者、群体或空镜；
- 保证槽位、站位、切镜和 `.aap` 结构合法；
- 对角色专属高编号 face、复杂空间和资源不确定项产生审阅提示。

- [camera.py](D:/桌面/蔚蓝档案二创/AA自动写剧本文件/01-完整程序/aa/camera.py) 主要按说话顺序切镜，无法表达听者反应、群体同步、逐人集结和主线画外空间。
- [direction_rules.py](D:/桌面/蔚蓝档案二创/AA自动写剧本文件/01-完整程序/aa/direction_rules.py) 的固定气泡/动作冷却会删除官方合理的连续升级。
- [performance_rules.py](D:/桌面/蔚蓝档案二创/AA自动写剧本文件/01-完整程序/aa/performance_rules.py) 能维持特写，但缺少可靠的结束语义，可能把特写错误延长到角色离镜。

## 8. `0.9.2` 推荐路线

采用“状态化导演层”：

1. 先由 AI 对连续段落做场景功能、情绪阶段、焦点和关系状态判断；
2. 再由 AI 输出兼容现有 AA 的行级标注和必要 beat；
3. 后端只做确定性状态继承、资源验证、镜头落地和 `.aap` 编译；
4. 对视觉语义不确定的 face、复杂多角色空间和重效果保留人工审阅；
5. 官方语料只提供脱离原文的导演规则、结构化特征和回归样本。

不推荐第一阶段直接做官方全文检索增强：它会增加文本泄露和过度相似风险，也不能解决人物状态与镜头焦点缺失的问题。

## 9. 验收标准

- 同一段剧情中，AI 能说明场景功能、当前情绪阶段和反应焦点；
- 连续 face、emo、act、特写和 `bgfx` 不再被全局冷却规则机械删除；
- 羁绊、活动、主线在相同台词结构下产生不同的导演策略；
- 主线支持画外动作、通讯和环境持续状态；
- 活动支持群体同步、逐人入退镜和喜剧升级；
- 羁绊支持沉默、微反应、关系距离变化和持续私人特写；
- 原文逐字不变，最终仍由确定性后端生成合法 `.aap`；
- 官方全文、完整台词和可直接复用的官方剧情文本不进入用户输出。

### 9.1 回归样本设计

回归测试不保存完整官方台词，只保存自行编写的最小剧情和预期状态变化，至少覆盖：

- 同一害羞 face 跨多句保持，话题切换后明确结束；
- 连续“疑惑→惊讶→愤怒”气泡不会被全局冷却误删；
- 台词由 A 说但焦点落在被戳穿的 B；
- 三人从逐步入镜到群体成立，再由领队特写下命令；
- 主线通讯效果跨多句保持，在通讯结束时明确关闭；
- 战斗 `bgfx` 跨段维持，战后切回普通环境；
- 无台词 beat 只在关系转折或等待回答时插入；
- 未视觉确认的高编号 face 被标记为需要审阅，而不是猜测使用。

测试同时验证原文指纹、行身份和 `.aap` 结构，确保导演层不能借机改写或重排台词。
