# 均衡自动导演系统设计

日期：2026-08-06

## 目标

让 AI 演出标注不再只选择角色表情，而是联合考虑人物走位、表情、气泡符号、动作和画面效果。系统应能补足明显遗漏的演出，同时保持视觉小说所需的克制节奏。

本轮采用“均衡”密度：明显反应可以自动补足，普通对白保持安静；气泡、动作和重效果均有密度限制，不因单个标点机械触发。

代表性目标包括：

- `全身上下就嘴巴最灵光……走了！` 可使用 AA 的 `Steam` 气泡，资源中文名为“冒烟”。
- `……你为什么要把「普通」说得那么不普通。` 可使用 `Dot`，资源中文名为“沉默”。
- `……！` 应在没有更高优先级标注时补 `Exclaim`，资源中文名为“惊叹”。
- `那就更不行了！！` 可使用 `jump` 表达短促而强烈的身体反应。

这些句子是行为样例，不是穷举关键词表。实现必须包含反例，防止普通省略号、普通感叹句和所有强语气都得到相同演出。

## 现状与问题

`script2aap.py` 已能把 `face`、`emo`、`act`、`move`、角色效果和背景效果写入正确的 AAP 字段。`stage.py` 和 `camera.py` 也会根据镜头人物自动安排基础站位。

缺口位于标注阶段：

- `prompt.py` 对气泡和动作的说明偏笼统，没有要求模型把不同演出维度作为一个整体判断。
- `annotate.py` 的合法性过滤只会拒绝不存在的值，不会补足高置信度遗漏。
- `normalize_emoticon_density` 只负责删除过密气泡，没有动作密度或跨维度冲突控制。
- 原剧本已有演出、模型合法输出和确定性补全之间缺少明确优先级。
- 帮助文档只概述推荐写法，没有告诉用户怎样提供地点、动作、情绪转折和物理事件等可供 AI 判断的依据。

## 方案比较与选择

### 方案 A：只增强模型提示词

模型最擅长理解反讽、停顿和上下文，但相同输入仍可能漏掉 `Dot`、`Exclaim` 等明显演出。该方案灵活，但不能稳定修复当前问题。

### 方案 B：模型语义判断、高置信度补全和密度控制

模型负责复杂语义和角色表情，确定性规则只补空缺字段中的高置信度演出，最后统一处理密度与冲突。该方案既保留语义能力，又能稳定覆盖明显遗漏。

### 方案 C：纯确定性规则引擎

输出可预测，但中文语气、反讽、克制情绪和角色个性难以用关键词完整表达，容易过拟合少量示例。

本轮选择方案 B。

## 处理流程与优先级

处理顺序为：

```text
原剧本与前后文
  -> AI 联合判断 face / emo / act / fx / move / shot
  -> 资源合法性过滤
  -> 高置信度缺失补全
  -> 密度与冲突控制
  -> 渲染为标注剧本
  -> script2aap 编译和最终效果守卫
```

每个字段采用以下优先级：

1. 原剧本人工标注。
2. 模型给出的合法选择。
3. 确定性补全。

低优先级不得覆盖高优先级。确定性补全只填空字段，不替换角色表情，不猜测角色专属 `faceId`，也不修改原台词。

## 各演出维度

### 角色表情 `face`

角色表情继续由模型按照资源表中的逐编号语义判断。每句都重新判断，但同一情绪可以保持上一表情；不得为了多样性机械轮换。由于不同骨骼的编号语义不同，确定性规则不生成 `faceId`。

### 气泡 `emo`

气泡表达瞬时心理反应，而不是持续情绪。提示词应明确常用符号的语义差异，并要求结合整句、前一句刺激来源和当前情绪阶段判断：

- `Dot / 沉默`：无语、尴尬停顿、犹豫或一时无法回答。普通省略号不自动成立。
- `Exclaim / 惊叹`：突然震惊、警觉或无词的强烈反应。纯反应句 `……！` 属于高置信度情况。
- `Steam / 冒烟`：恼火、急躁或气得冒烟，尤其是从压抑转为催促、训斥的尖峰。普通命令句不自动成立。
- 其他气泡继续使用资源表真实中文名，由模型按语义选择。

确定性规则仅覆盖少量高置信度模式，并要求说话者存在可显示立绘。对存在歧义的句子只依赖模型，不强行补气泡。

### 动作 `act`

动作表达身体反应，与气泡的心理反应分开判断：

- `jump`：突然震惊、强烈反驳、突然振奋或短促的情绪爆发。
- `stiff`：受惊、压抑紧张或克制的小幅颤动。
- `shake`：文本明确支持的强烈发抖或剧烈身体反应。
- `hophop`：持续而外显的兴奋，不用于单次强调。
- 倒下等方向性动作只在文本明确发生对应身体动作时使用。

双感叹号不是 `jump` 的充分条件。补全必须同时满足短促表达、明显情绪跃迁或强烈反驳等语义特征。模型可以在真正的情绪峰值同时选择气泡与动作，但确定性规则不为了“热闹”堆叠多个强调层。

### 走位 `move`

基础站位和因镜头人数变化产生的移动继续由 `camera.py` 与 `stage.py` 自动处理。`move` 只表示文本中真实发生的位置变化，例如走近、退后、走到另一人身边或转身离开。

确定性补全不猜测位置编号。模型只有在文本明确移动且目标位置可合理确定时才填写 `move`；普通情绪反应使用 `act`，不改变站位。

### 角色效果与背景效果

`fx`、`bgfx`、`shake` 和音效只用于文本支持的关键演出：

- 特写用于关键情绪或距离变化，不替代站位。
- `FocusLine` 仅允许单人、中央位置、已经特写的镜头。`performance_rules.py` 保留最终守卫，非法组合只移除集中线，不改写角色名单或强制制造特写。
- 背景抖动只对应爆炸、撞击、拍桌等物理冲击，不对应心理震撼。
- 音效只对应实际发生或紧邻语境可可靠推断的声音。

## 高置信度补全

新增一个边界清晰的导演补全模块，输入为已经完成合法性过滤的台词项和角色能力，输出为对空字段的候选补全及原因。它不调用模型，不接触 AAP 文件。

候选判断使用以下信息：

- 完整台词，而不是单个关键词。
- 句首和句尾标点组合。
- 台词长度和是否为纯反应句。
- 前一条有效对白提供的刺激或对比。
- 当前说话者是否有立绘。
- 当前行已有 `face`、`emo`、`act` 和重效果。
- 同一角色近期使用过的气泡和动作。

补全模块返回来源和规则名，便于测试与审查。没有达到高置信度阈值时保持空白。

## 密度与冲突控制

均衡密度采用以下边界：

- 相邻对白不连续显示自动气泡。
- 同一种气泡在四条对白内不重复；“脸红”沿用八条对白冷却。
- 同一角色的同一种自动动作在三次出声内不重复。
- 相邻两条对白不连续补 `jump`、`shake` 或 `hophop` 这类强动作。
- 原剧本人工标注不因自动密度规则被删除；模型标注只有在违反硬冲突时才被规范化。
- 一行可以有相互协调的表情、气泡和动作，但自动补全默认只增加一个主要强调层。
- `FocusLine`、闪白、背景抖动等重效果继续按已有生命周期和合法镜头规则处理。

密度计算跨分块生效，不能因为模型按 40 行分批调用就在边界处连续堆叠演出。

## 提示词改进

`prompt.py` 增加以下要求：

- 把 `face`、`emo`、`act`、`move` 和效果作为一个镜头整体判断。
- 先确定人物在这一句的情绪阶段和身体反应，再选择字段。
- 明确 `Dot`、`Exclaim`、`Steam` 以及全部动作的适用与反例。
- 区分 `act` 的原地身体反应和 `move` 的真实位置变化。
- 在一个强烈演出已经足够时不要继续堆叠气泡、动作和重效果。
- 前文展示近期气泡与动作使用情况，帮助模型避免机械重复。

结构化输出 schema 的字段说明同步更新，避免 schema 中的简短描述抵消系统提示词。

## 推荐剧本格式与帮助文档

网页“使用帮助”、`使用说明-从这里开始.md` 和 README 的剧本格式说明保持一致，提供可直接照写的推荐结构：

```text
## 场景一：商店街，午后

旁白: 商店街人声嘈杂，凯伊已经在服装店门口等候。
老师: 久等了。
凯伊: ……你为什么要把「普通」说得那么不普通。
旁白: 凯伊短暂地噎住，随后向老师走近一步。
凯伊: 那就更不行了！！
```

帮助文档说明：

- 一行一个角色的一句台词，角色名在全文中保持一致。
- 用 `##` 标明场景，并自然写出地点、时间、光线、环境声音和气氛。
- 把真实身体动作和位置变化写清楚，例如“走近一步”“后退”“猛地转身”。
- 情绪转折可以通过台词和旁白表达，无需手工填写 AA 内部枚举名。
- 标点应服务真实语气，不要为了触发演出堆叠省略号或感叹号。
- 换背景、可听见的声音和物理冲击应有文本依据。
- AI 生成的演出仍需在审查草稿中确认。

高级语法继续保留，但普通用户的主路径不要求预先学习 `faceId`、气泡名或动作 verb。

## 错误处理与安全边界

- 无立绘角色不能得到 `face`、`emo`、`act`、`move` 或角色效果。
- 资源表不存在的气泡或动作仍由现有 allowlist 拒绝。
- 补全规则发生异常时跳过补全并保留合法模型结果，不阻断草稿生成。
- 所有规则只处理本程序内的剧本文本和草稿，不写入 AA 安装目录、配置、资源包或工作区。
- AAP 仍只在用户执行现有编译与安装流程后生成。

## 测试设计

### 单元测试

- 四条代表性台词分别得到预期候选：`Steam`、`Dot`、`Exclaim` 和 `jump`。
- 普通的“好的！”不自动 `jump`。
- 叙述性省略号和未形成反应的停顿不自动 `Dot`。
- 普通命令和轻微不满不自动 `Steam`。
- 双感叹号但缺少情绪跃迁时不自动添加动作。
- 无立绘角色永远不被补全角色演出。
- 原剧本人工标注不会被模型或补全覆盖。
- 相邻气泡、重复动作和强动作冷却按均衡密度生效。
- 分块边界前后的密度限制保持一致。

### 提示词与帮助契约测试

- 提示词包含跨维度联动、常用气泡语义、动作反例和 `act`/`move` 区别。
- schema 描述与提示词使用同一术语。
- 网页帮助和 Markdown 文档包含推荐格式、动作依据、场景信息和审查提醒。

### 集成测试

- 使用假模型返回空演出，经过补全后渲染出预期剧本标注。
- 使用假模型返回合法演出时，补全不覆盖结果。
- 标注剧本经 `script2aap.build` 后，气泡进入 `emoticon`、动作进入 `action`，两者不串字段。
- `FocusLine` 仅在单人中央特写镜头保留。
- 现有完整测试、JavaScript 语法检查和发布检查全部通过。

## 验收标准

1. 四个用户示例得到符合设计的演出，其中确定性强例能够稳定复现。
2. 反例不会因简单标点匹配被过度演出。
3. 人工标注、模型选择和自动补全的优先级可由测试证明。
4. 生成结果中的走位、气泡、动作和效果写入正确 AAP 字段。
5. 帮助入口能直接看到推荐剧本格式和辅助 AI 判断的写法。
6. 全量测试、`node --check js/app.js` 和 `python prepare_release.py --check` 通过。

## 非目标

- 不用确定性规则推断角色专属 `faceId`。
- 不重写用户台词或自动添加新的旁白。
- 不把所有情绪判断改造成关键词规则。
- 不新增演出密度设置界面；本轮固定采用均衡默认值。
- 不修改 AA 的 EXE、配置、AssetBundle、工作区文件或时间戳。
