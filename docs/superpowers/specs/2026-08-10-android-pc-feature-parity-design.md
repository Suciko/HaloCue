# HaloCue 安卓端 PC 功能对齐设计

日期：2026-08-10

## 目标

在现有安卓导出基础上，把 PC 端 HaloCue 的 WebUI、HTTP API 和 Python 业务逻辑尽量原样迁入 APK，使安卓端具备与 PC 端一致的剧本生成、模型配置、草稿审阅、素材管理、故事工作区和 `.aap` 导出能力。

迁移采用“APK 内本地 Python HTTP 服务 + 原 PC WebUI + Android 平台适配层”。不重写整套原生 UI，不重新实现已经稳定的 Python 业务规则。

安卓端继续遵守现有边界：只能把 `.aap` 发布到 `Download/HaloCue/` 并调用系统分享，不能声称已经自动导入原版 AzureArchive。

## 已确认的产品决定

- 采用方案 A：在 APK 内运行适配后的 `webui.py`，WebView 加载本机服务提供的原 PC 页面。
- PC 端页面布局、交互和 API 合同尽量保持不变，只调整移动端无法使用的系统入口。
- 官方人物表情直接读取资源中已有的语义标识，不需要 Spine 渲染，也不需要 AI 图像识别。
- 自定义人物不做 Spine 画面渲染。程序读取可用的骨骼、插槽、附件、皮肤和动画名称，必要时让现有文本模型生成可编辑的语义建议。
- AI 结果不能覆盖用户已经手工修改的表情语义。
- Spine 语义识别失败不阻止资源导入、手工编辑或按原始表情 ID 编译。
- Windows 直接安装到 AA 的流程由安卓公共导出与系统分享替代。

## 总体架构

### Android 外壳

Kotlin 层继续负责应用生命周期、WebView、文件选择、凭据安全存储、公共导出、系统分享和启动原版 AA。

应用启动时：

1. 初始化 Chaquopy Python 3.13。
2. 创建或升级应用私有工作目录。
3. 启动只绑定 `127.0.0.1` 的 Python HTTP 服务，并使用系统分配的空闲端口。
4. 生成本次进程有效的随机会话令牌。
5. WebView 打开本地 UI，并由统一请求封装为 `/api/*` 请求附加会话令牌。
6. 页面加载完成后恢复 PC 端原有工作区状态。

HTTP 服务不能绑定外网地址。没有正确会话令牌的状态修改请求必须拒绝，避免其他本机应用探测端口后调用 HaloCue API。

### PC WebUI

以下内容从 `01-完整程序/aa` 选择性同步进入 APK：

- `ui.html`、`css/`、`js/` 和页面使用的静态资源。
- 页面依赖的 API 路由和数据合同。
- 页面状态、卡片编辑、草稿审阅、模型设置和素材库交互。

前端只允许进行必要适配：

- 统一 API 请求附加安卓会话令牌。
- Windows 路径选择入口改为调用 Android 文件或目录选择器。
- “安装到 AA”改为“导出工程文件”和“系统分享”。
- 调整安全区、软键盘和窄屏滚动行为，但不重新设计 PC UI。
- 隐藏仅在 Windows 上成立且没有安卓等价能力的状态文案。

### Python 服务与业务层

优先复用以下 PC 模块及其现有 API 行为：

- AI 标注与生成：`annotate.py`、`llm.py`、`prompt.py`、`script2aap.py`。
- 草稿与审阅：`draft_store.py`、`document.py` 和卡片 API。
- 模型管理：`model_profiles.py`、`model_router.py`、`model_capabilities.py`。
- 素材管理：`asset_catalog.py`、`assetdb.py`、`asset_validation.py`、`asset_import.py`。
- 故事与历史：`story_workspace.py`、`history_assets.py`。
- 官方资源索引：`official_preview_index.py`、`aa_resource_cache.py`、`official_catalog.py`。
- Web API：从 `webui.py` 抽取或适配页面实际依赖的路由。

Windows 专属判断不得散落在这些业务模块中。它们通过一个明确的平台接口访问文件、凭据、导出和外部应用能力。

## Android 平台适配层

平台适配层提供以下稳定能力：

| 能力 | PC 实现 | Android 实现 |
| --- | --- | --- |
| 选择文件 | tkinter/Windows 对话框 | Storage Access Framework `ACTION_OPEN_DOCUMENT` |
| 选择目录 | Windows 文件夹选择 | `ACTION_OPEN_DOCUMENT_TREE`，仅用于系统允许的位置 |
| 保存 API Key | Windows Credential Manager | Android Keystore 加密后的应用私有存储 |
| 工作目录 | PC 用户目录 | `context.filesDir` 下的应用私有目录 |
| 导入资源 | 本地文件路径 | SAF URI 流式复制到私有资源库 |
| 导出 `.aap` | PC 文件系统或 AA 目录 | `MediaStore.Downloads/Download/HaloCue/` |
| 分享文件 | 桌面文件操作 | `ACTION_SEND` 和临时 URI 读取授权 |
| 启动 AA | Windows 可执行文件 | `PackageManager` 启动 `com.foxxlight.AzureArchive` |

Python 业务层只接触已经复制到私有工作区的普通路径，不直接解析长期有效的 `content://` URI。Kotlin 层负责 URI 权限、流式复制、文件名清理、容量限制和错误转换。

## 数据与同步策略

APK 不复制 PC 端约 2 GB 的生成目录。同步脚本使用白名单，只打包源码、UI、必要数据库种子、模板和运行时资源，并为每个同步文件记录来源与哈希。

运行数据放在应用私有目录中：

```text
files/
  runtime/       # 同步的 Python 和 WebUI 运行资源
  workspace/     # 当前故事、草稿和中间文件
  assets/        # 用户导入并归档的素材
  databases/     # 素材、故事和设置数据库
  cache/         # 可重建缓存
  exports/       # 等待发布的 .aap
```

数据库升级必须有版本号和可重复迁移步骤。升级不能删除用户草稿、模型配置、素材标签或人工编辑的表情语义。可重建缓存可以清理，但必须与用户数据分开。

## 模型配置与凭据

安卓端保留 PC 端模型档案、路由、能力检测和供应商配置界面。

- 非敏感模型配置继续使用现有结构化设置格式。
- API Key 不写入 JSON、日志、数据库明文字段或 WebView 本地存储。
- 页面读取凭据时只获得“已配置/未配置”和脱敏尾号，不能取回完整 Key。
- 发起模型请求时由 Python 通过受控平台桥获得当前请求所需的凭据。
- 凭据读取失败时只影响对应模型调用，不影响本地编辑、素材管理和 `.aap` 编译。

第三方 Python 包先进行 Chaquopy/arm64 兼容验证。无法直接打包的依赖通过等价纯 Python 实现、Android 原生能力或延迟加载替换，不允许因为一个可选功能失败而使整个服务无法启动。

## 素材导入与官方资源

用户通过系统文件选择器选择压缩包或资源文件。Kotlin 将内容复制到临时私有目录，Python 完成格式校验、索引和数据库写入；全部成功后再原子移动到正式素材库。

官方资源不随 APK 分发。需要官方素材时，由用户选择自己持有的资源包或可访问目录，HaloCue 在私有目录建立索引。安卓系统不允许访问的 AA 专属目录不能作为默认来源，也不能提示用户授予不存在的权限。

无预览能力的资源仍可进入素材库，但 UI 必须明确显示“无预览”，而不是把它当作损坏资源。

## 表情语义识别

### 官方人物

优先读取 `.atlas`、`.skel`、皮肤、动画或现有索引中已经携带的表情编号和语义名称。解析结果至少包含：

- 表情总数。
- 原始表情 ID。
- 官方语义名称。
- 组成该表情的附件或部件名称（存在时）。
- 数据来源。

官方语义名称直接用于素材检索和剧本生成，不调用 AI。

### 自定义人物

扩展现有 `spine_semantic_faces.py` 的只读解析能力，保留以下文本元数据：

- 骨骼名称。
- 插槽名称和默认附件。
- 附件路径或名称。
- 皮肤名称。
- 动画名称及零时刻启用的表情附件组合。
- `.atlas` 中的区域名称。

识别顺序固定为：

1. 使用现有确定性规则从中文、英文和常见命名中提取眼睛、眉毛、嘴型、脸红、汗滴等语义。
2. 已经得到明确语义时直接保存，不消耗模型调用。
3. 仍为空或冲突时，把原始表情 ID、相关部件名称和规则结果作为纯文本交给当前配置的模型。
4. 模型只返回结构化的语义标签、简短说明和置信度，不生成或查看图片。
5. 页面把结果显示为“AI 建议”，用户可逐项接受、修改或忽略。
6. 用户一旦修改，该记录标记为人工来源，后续重新扫描或 AI 识别不得自动覆盖。

每条语义记录保存 `face_id`、`labels`、`display_name`、`source`、`confidence`、`raw_parts` 和更新时间。允许的 `source` 为 `official`、`rule`、`ai_suggestion`、`manual`。

若二进制版本不受支持、名称没有语义、模型未配置、网络失败或结构化输出无效，系统仍列出原始表情 ID 和数量，允许用户手工填写并继续使用角色。

### 不包含的 Spine 能力

- 不在安卓端加载 Windows `Spine.com`。
- 不集成原生 Spine Runtime 进行画面渲染。
- 不生成自定义人物表情预览图。
- 不根据画面像素进行视觉识别。

这些能力留到后续版本单独评估，不阻塞 PC 基础功能迁移。

## API 与页面兼容

现有 `/api/*` 返回字段和错误结构优先保持兼容。需要 Android 平台操作的接口返回明确的异步任务状态，不让 Python HTTP 请求无限等待系统选择器或分享面板。

文件选择流程为：页面创建选择请求，Kotlin 打开系统选择器，选择结果复制完成后回传任务结果，页面再调用原有导入 API。用户取消选择属于正常结果，不显示为程序崩溃。

耗时任务继续使用 PC 端已有的进度或轮询机制。模型请求、资源索引、大文件复制和 `.aap` 编译不能占用 WebView 主线程。

## 生命周期与恢复

- App 进入后台时保留短时生成任务，系统终止进程后允许从已落盘状态恢复。
- 页面刷新或 Activity 重建不能丢失已经保存的草稿和素材数据。
- Python 服务端口和会话令牌每次进程启动重新生成，不能持久化。
- 服务启动失败时显示可重试的本地错误页，不能退回远程网页。
- 数据库写入使用事务；中断的资源导入只留下可清理的临时目录。

## 错误处理

- Python 服务启动失败：显示启动阶段和可读错误摘要，保留日志供用户导出。
- 可选依赖不可用：禁用对应功能并显示原因，其他功能继续工作。
- 文件格式错误：不写入正式素材库，返回具体缺少的文件或不支持的版本。
- 空间不足：停止复制或导出，清理本次临时文件，不删除已有用户数据。
- AI 语义识别失败：保留规则结果和原始名称，转为人工编辑。
- 导出失败：保留私有 `.aap`，允许重试发布或分享。
- 原版 AA 未安装：禁用“打开原版 AA”，不影响生成和导出。

日志必须过滤 API Key、Authorization 头、会话令牌、完整用户剧本和 SAF URI 授权信息。

## 实施阶段

### 阶段 1：完整 UI 与本地服务骨架

同步 PC WebUI，启动适配后的本地 HTTP 服务，建立会话保护、生命周期管理和平台接口。页面能够打开并完成基础 API 健康检查。

### 阶段 2：剧本、模型、草稿和生成链路

迁移模型设置、故事工作区、草稿审阅、卡片编辑、AI 标注、真实 `script2aap` 编译，并接入已经验证的公共导出与分享。

### 阶段 3：素材库与表情语义

迁移素材数据库、资源导入、官方索引、表情数量/ID/语义读取、自定义文本推断、AI 建议和人工编辑。

### 阶段 4：剩余 PC 能力对齐与回归

逐页核对 PC 页面和 API，补齐历史素材、官方预览等未覆盖能力；对没有安卓等价实现的 Windows 功能提供明确替代或禁用说明。

每个阶段都必须保持上一阶段的真实生成、公共导出和分享能力可用。

## 测试策略

- 同步合同测试：白名单文件、来源哈希和禁止打包目录。
- Python 单元测试：PC/Android 共用业务模块在相同输入下产生一致结果。
- API 合同测试：关键 `/api/*` 的状态码、JSON 字段和错误结构与 PC 一致。
- 表情解析测试：官方命名、自定义命名、无语义命名、Spine 3.8 二进制和不支持版本。
- AI 回退测试：未配置模型、网络失败、无效 JSON、低置信度和人工标签防覆盖。
- Kotlin 单元测试：Keystore 包装、URI 导入、任务状态和错误映射。
- Android 仪器测试：WebView 启动、本地服务会话保护、文件选择回传、公共导出和分享 Intent。
- 数据升级测试：从现有 0.3 私有数据升级后，草稿和导出文件不丢失。
- 真机验收：vivo X100s Pro / Android 16 上完成完整剧本、模型、素材和导出工作流。

已知 vivo 固件上的 Espresso Web/ActivityScenario 卡顿不能作为唯一页面验证手段。页面使用真实操作、UI hierarchy、API 探针和最终文件校验组合验收。

## 验收标准

- APK 内显示原 PC WebUI，主要页面和交互不依赖桌面浏览器。
- 用户可以配置模型、保存草稿、编辑卡片、执行 AI 标注并生成真实 `.aap`。
- 用户可以通过 Android 文件选择器导入资源，并在素材库中检索和编辑。
- 官方人物能够显示表情数量、ID 和官方语义，不依赖 Spine 渲染。
- 自定义人物能够显示表情数量和部件名称；规则或 AI 可提供语义建议，用户可以手工修正。
- 人工表情语义不会被重新扫描或 AI 自动覆盖。
- 生成文件可以发布到 `Download/HaloCue/` 并通过系统分享。
- 应用不申请无障碍或所有文件访问权限，不修改原版 AA 项目目录。
- 单个可选功能失败不会导致整个本地服务或基础编辑工作流不可用。

## 非目标

- 安卓端 Spine 实时渲染和自定义人物表情预览。
- 自动写入原版 AA 的 `Android/data` 专属目录。
- 修改、重签、注入或替换原版 AzureArchive。
- 把 Windows `Spine.com`、Windows Credential Manager 或桌面文件选择器直接打包进 APK。
- 打包或分发用户没有提供的官方素材。
