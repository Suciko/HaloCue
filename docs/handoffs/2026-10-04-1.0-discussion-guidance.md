## Collaborator report and resulting behavior

At the end of ideation the author cannot find a clear next step; public chat
contains a JSON code block instead of a reply/question card; the model claims
characters are missing despite the 102-card bundled reference library.

Discussion JSON parsing was strict whole-response parsing. Prose surrounding a
valid envelope therefore went through a fallback that displayed the entire
payload. Recovery now recognizes one complete public discussion envelope,
preserves surrounding authored prose, projects questions and existing choices,
and retains ordinary code samples. Recovered readiness flags cannot execute a
task; embedded tool calls are excluded. Native structured tools retain their
checked path. Malformed/ambiguous envelopes fail clearly. The UI also projects
valid old persisted replies without rewriting their historical bytes.

The maintainer clarified the UI during implementation: one small button,
chosen by the Agent, with ideation carried into prose; inspect in the in-app
browser at 16:9. This supersedes the initial large guidance card. The optional
`next_step` reply field chooses organize/review/structure/draft or null from the
available server-scoped actions. Only the latest completed reply may show one
button; missing/null means no button. UI still checks actual pending candidates,
scene IDs and stage state before presenting an action. Completing an Agent/user
organize request supplies the actual review entry. Normal discussion no longer
adds a standalone next-action status card. Navigation never generates prose or
accepts a candidate.

Entering prose through that button associates the exact selected ideation
thread with the scene conversation. Both new and existing scene threads support
the version-checked association. Same-work work threads and matching chapter
threads are allowed; unrelated works/chapters are rejected. An optional
`discussion-continuation/1.0` projection supplies validated historical summary
plus the existing bounded recent-message window to scene discussion and prose
candidate generation. The fixed input retains it for retry. Old source messages
remain retrievable in bounded chunks only from the current or explicitly linked
thread. The small scene caption includes a working return to the source chat;
original histories remain separate and unchanged. This carries writing requests,
not confirmation of inferred character/world facts.

The old library flow supported only manual import. The maintainer has now
explicitly authorized automatic source-card reuse during ideation; see the
updated [reference pack record](../architecture/bundled-reference-pack.md).
Names/aliases in original author discussion are matched before the model input
is fixed. The existing validated importer copies missing cards with original and
cleaned source archives/hashes. Repeated mentions keep stable revisions;
custom/archived/unconfirmed cards are preserved. Longer names win overlapping
mentions (明日奈 versus 日奈); shared aliases require author selection. Receipts
show actual added/reused/ambiguous/blocked/unavailable results. On a prose
request, recent original author messages can recover earlier named characters;
model suggestions and attachment content cannot seed cards.

A second defect was found by the runtime readiness regression: non-explicit
scene assembly compared brief names only to full card display names, so 日奈 and
亚子 still failed after importing 空崎日奈 and 天雨亚子. It now resolves unique
canonical names and aliases while keeping explicit selection unchanged.

## Contracts and validation

The optional receipt uses `character-reference-resolution/1.0`, with its JSON
Schema under writing docs/contracts. It is stored in fixed conversation input
and public reply content; no project/database migration is needed. Formal
AI-authored changes remain proposals until their existing author decision.
The additional contracts are `discussion-next-step-1.0.schema.json` and
`discussion-continuation-1.0.schema.json` (including the persisted source-link
shape). They are optional additions; existing threads without links retain
their existing scope. Restart, source retrieval, candidate input and schema
round-trip behavior are covered with synthetic data.
