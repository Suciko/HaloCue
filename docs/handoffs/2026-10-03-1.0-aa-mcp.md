## Delivered

The integrated MCP connection now independently grants selected production-run IDs, including existing imported tasks without a writing origin. A user may authorize AA alone. Four added host tools find productions, read numbered card windows/current cast, retrieve frozen resource choices (including face semantics/emotion/action enums), and propose annotation/directive batches. This extends the prior four prose tools to eight; no per-task package export/import or provider generation is needed.

HC owns read handles, stable IDs, versions, stale/unread checks, receipts and author decisions. The host can edit line face/emo/act/fx, edit existing directives, resolve a background request to a frozen key, or insert validated directives after read cards. Background/sound keys must already be frozen in the task; raw code, prose/speaker changes and foreign scopes are denied. Cast mapping and new asset import remain in HC. Exact retry survives read-window eviction and returns the same proposal/status. Each submitted batch is at most 40 edits; after author adoption the host rereads the changed draft.

The main review surface shows human-readable before/after changes with Apply/Reject. Pending proposals open the review stage directly; refresh retrieves external results. Applying revalidates versions and choices, locks the draft, applies the complete batch with rollback/restart recovery, keeps source-card identities/frozen dialogue, marks affected cards pending and invalidates previous build/install claims. Rejection changes no draft content, including stale proposals. A fixed-file before-image journal covers edited text, identity, diagnostics, session, frozen resources and MCP state. Existing tasks without MCP state avoid extra parsing. No apply, model, compile or install tool is exposed to the host.

Contracts: connection `1.1.schema.json` adds AA scope/catalog/capabilities. SQLite migration adds `run_ids_json DEFAULT '[]'`; old grants retain their work scope and receive no inferred AA access. The retained 1.0 schema remains valid for old snapshots. `external-performance-proposal/1.0.schema.json` describes public proposal changes; private task-local JSON stores read snapshots and receipts. Standalone writing explicitly reports AA unavailable. Production owns proposals; integrated runtime binds it directly after writing initialization.
