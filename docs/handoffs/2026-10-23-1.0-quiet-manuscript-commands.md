## 参考与实际调整

阅读了 [AppFlowy Editor 的浮动工具栏源码](https://github.com/AppFlowy-IO/appflowy-editor/blob/main/lib/src/editor/toolbar/desktop/floating_toolbar.dart)：工具栏跟随非空选区，选区折叠后收起。另以 [MarkText 官方 README 的所见即所得、简洁界面与段落快捷操作](https://github.com/marktext/marktext#features)作为阅读体验的对照。资料观察日期为 2026-10-23。参考交互组织，现有 ProseMirror 和 HaloCue 数据协议继续负责实现，本轮没有新增依赖。

| Before / 改前 | After / 改后 | 原因 |
| --- | --- | --- |
| 正文前常驻撤销、重做、操作提示与保存工具条 | 合并为章节标题和状态，修改后才出现“保存”；撤销／重做进入章节菜单 | 减少正文前的操作层级；Ctrl/Cmd+S、撤销和重做快捷键保留 |
| “任务包交换”占据一行 | 收入章节菜单 | 按需使用的跨工具操作不占正文空间 |
| “记录本场进展”与“更多”并排 | 普通记忆操作进入场景菜单；待确认候选或运行状态直接显示 | 将维护操作收起，同时保留实际待处理事项 |
| 当前段落同时露出上移、下移、删除 | 收成就近的段落菜单 | 保持段落可读，具体命令在主动展开后出现 |
| 灰色工具带和较大的场景前间距 | 页头使用正文底色，缩短场景前间距 | 在正常缩放下更早看到正文 |

三个菜单使用原生 details / summary，提供明确的可访问名称、键盘焦点、触屏尺寸、Esc、外部点击和执行后收起。撤销／重做与段落操作执行后回到编辑宿主。可选陪跑的模式、暂停、下一步控件也进入章节菜单；首次教学仍根据真实作品状态运行，不默认开启旧用户陪跑。

章节标题保持可达，审查工具栏通过实测标题高度确定吸顶偏移，避免依赖旧的固定保存工具条高度。正文输入、光标、稳定 IDs、整章保存、候选的原位置审查和显式采用协议保持原实现。没有更改后端、持久化字段或 1.1 仓库。
