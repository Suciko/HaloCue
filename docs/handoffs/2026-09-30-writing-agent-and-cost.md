## 正文修改交互续验（原位对比）

- 维护者确认：能由 Agent 调用工具完成的写作任务，用户只需描述要求并发送，不再点击生成候选按钮。该规则和正文原位对比规则已写入根 `AGENTS.md`。
- 新增 `propose_scene_text_edit` 原生工具。工具要求固定正文版本、真实段落 ID、逐字一致的原文，只提交涉及的段落。工具先准备修改，最终运行授权与版本校验通过才创建候选；显式应用前正式正文不变。
- 聊天支持继续调整未采用的修改；按候选 ID 与内容哈希固定输入，在同一提交事务中替代旧候选，保留其他候选改动。讨论或“不要修改”不触发写入工具。
- 连续章节正文在修改对应的原文范围内渲染完整改前、改后；保留周围段落顺序。新增、删除、多段替换均使用原文范围，不再把主要对比放入场景底部的独立折叠清单。
- 勾选与部分应用使用原来的服务端变更 ID；隐藏原文控件仅用于本地草稿捕获，候选不进入自动保存。待审场景手动编辑暂只读，避免正文基准漂移。
- 每处修改旁提供“应用 N 项修改”和引用这处继续讨论；单项还可直接保留原文。应用按钮共享提交锁。Agent 完成后直接定位第一处改动，取消覆盖定位的章节滚动帧。
- 冗长的工具成功解释折叠到“查看助手说明”；模型提示要求一到两句、无内部 Proposal 术语。整章检查改为紧凑的连贯性检查与剧情记忆展示，已完成记忆只读折叠。
