# 1.0 Codex 演出请求修复候选

Issues: [#84](https://github.com/Suciko/HaloCue/issues/84), [#85](https://github.com/Suciko/HaloCue/issues/85)。Branch: `codex/1.0-full-ui-acceptance-20261007`，基于 PR #80；不得直接合入 main。

## 问题与结果

协作者在 CLI 0.160.1 / gpt-6.1-sol 上报告：代理恢复后真实演出返回 HTTP 400 invalid_json_schema；原始 annotation Schema 的必填列表不完整，动态状态字典含远端不接受的 maxProperties。独立 error 事件被忽略，界面只收到任务未完成。Codex 请求超时也未进入既有分块检查点逻辑。

Codex 边界现在复制并递归转换输出 Schema：全部对象属性 required，原本可选的非 null 字段用 null 表示省略，所有对象拒绝额外属性。动态字典通过 key/value 条目数组传输，再还原为本地字典；重复键拒绝。远端移除对象数量限制，但还原后仍执行原始 Schema 校验，站位/表情数量上限与领域检查保持有效。原 Schema 不被修改。实际演出连接测试使用 build_chunk_schema 和一个无操作目标；写作连接测试保持独立。

原生 error 事件与 RPC 错误保留有界消息、HTTP 状态、错误类型和错误码，并遮盖凭据。可重试事件不会提前结束成功任务；失败事件经生成控制器到作业诊断仍保留元数据。不会转用 API。

Windows 子进程保留显式代理；未提供时读取 HKCU 静态系统代理和绕过列表，补齐大小写代理环境变量。显式 NO_PROXY（包括空值）优先。此功能不解析 PAC，不修改系统或父进程设置。

codex_timeout 进入已有 deadline 检查点流程，结束本次请求并保存较小的 resume_target_limit，继续时缩小未完成块。不是在同一作业中无限重试。Codex 面板显示 5–600 秒单次请求超时；已登录状态不声称已通过请求测试。启用按钮在设置滚动区保持可达。

背景编译现已复现独立故障：小写拼写原样参与 xxh32，得到不同 AA 标识。标注过滤、默认/场景/指令背景和工程预览恢复注册资源的准确大小写；有歧义则拒绝猜测，未注册自定义名称仍按原规则处理。没有修改协作者现有项目。

## 验收边界

这些结果证明源码边界与模拟 stdio/浏览器回归，不是一次新的真实账号生成。此环境的隔离 HaloCue Codex profile 未登录；未读取或复制 OAuth 凭据。协作者报告的七场景成功结果属于其本机临时兼容器，不能记为本次原生源码验收。原 222 条正文/角色映射、draft v11、人工审查及 AA 原生播放均未动。暂未发布新测试包。
