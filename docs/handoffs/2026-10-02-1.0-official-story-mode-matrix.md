## Findings and acceptance limits

- **Execution-mode semantics fail acceptance.** Service/adapter persist `layout_mode` and forward it, but `annotate.py` uses it only in the checkpoint fingerprint. Both adapter generation and the common compiler path run regardless of execution mode. The `rules` selection still makes model calls; the `pure_ai` selection still uses the shared backend compiler/layout. A valid export does not certify three implemented modes or determinism.
- **Style changes are real.** Conservative/standard have distinct versioned rules hashes. Within each style the stable prompt prefix is identical across execution selections; observed output differences between mode labels cannot be attributed to a distinct implemented mode.
- Standard outputs add more emotion/actions and many persistent-camera directives; frequent solo cuts can weaken simultaneous group reactions. One standard output adds a boom sound at the final comic anger beat. These are artistic review concerns, not invalid resource IDs.
- Compare the official fatigue beat, multiple silent participants and final anger beat, rather than require identical shot counts. The original finale hides all portraits, enlarges text and shakes the background; generated outputs often use a portrait close-up/jump instead. A deliberate restaging may be reasonable, but it is not reproduction of the official staging.
- **Actual animation/audio/timing remain unverified.** `performance_preview` explicitly returns a draft representation. Current capability says `spine_animation_rendered=false`, renderer `not_configured`, reason `spine_cli_not_configured`. Browser proof shows background, dialogue and annotation labels, not rendered standing-character action/position/transition/audio. Do not certify native playback from this preview or from compilation.
- Canonical speaker labels use bound AA identities; official TW prose can still contain the original international aliases. The local resource display also contains traditional/simplified variants. A separate reviewed import normalization step is needed before claiming script-wide Japanese fandom naming consistency.
