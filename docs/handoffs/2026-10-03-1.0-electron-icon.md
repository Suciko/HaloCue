## Delivered behavior and provenance

The portable `HaloCue.exe` is official Electron 44.5.1, with a hidden title bar and native Windows minimize/maximize/close controls integrated into the existing 56 px header. The sandboxed, context-isolated renderer exposes no Node/general IPC API. The host owns a frozen `HaloCueBackend.exe`, authenticated shutdown and one instance lock; MCP/updater remain separate frozen root executables sharing `_internal`. Default data paths and story contracts are unchanged. Headless and legacy flags remain compatible. Clipboard text copy is permitted only in the trusted main frame; reads and other permissions remain denied.

The original selected blue/white/cyan SVG is restored exactly. Generated ICO/PNG/favicon and the boot icon come from that master; all seven actual PE icon entries match the generated ICO. No new icon design was introduced.

The editor no longer awaits remote feedback sync before showing: works and capabilities load concurrently and feedback runs after boot. A pure Node VM regression proves a never-resolving feedback request does not block opening. Startup stages are local metrics, without manuscript/credential telemetry.

Boot and native caption colors now restore manual dark/light mode before first paint. System mode resolves current OS appearance rather than a stale cached effective theme. Only validated appearance fields are cached; missing origin preferences are restored if the service changes ports. Existing localStorage preferences win. Normal startup has no self-test screenshot delay.

| Before | After | Why |
| --- | --- | --- |
| White boot page before a dark editor | Boot, window background and caption use saved/current theme | Removes the white flash |
| Separate outer window title row and workbench header | Native controls share the existing header; buttons opt out of dragging | Keeps one top bar and usable controls |
| Different brand mark/spacing | Original icon at 24 px, consistent 8 px wordmark gap | Keeps startup and workbench branding aligned |
