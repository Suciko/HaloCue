# HaloCue 1.0 合作者验收测试单

这份测试单用于合作者对 1.0 改编流程做正式验收。目标是验证“原文范围 → 改编计划 → 试读/候选 → 逐章采纳 → 后续追加”的闭环，不要求合作者维护 JSON、索引或 Agent 状态。

除小说改编外，当前自动化基线已经覆盖正常 Agent、提案/知识影响、发布门禁和制作交接：正常 Agent 链路 130 项、写作 UI/异步操作 38 项、制作服务与 UI 125 项、旧版 Annotation/LLM 兼容 72 项通过；浏览器 phase1、phase3、phase5 在桌面和 390px 移动视口均通过，横向溢出为 0、Console 问题为空。合作者仍需用真实浏览器和真实模型做一次独立复验。

## 当前可以验收的范围

- TXT、DOCX 原文导入；DOCX 以最终正文为准。
- 十万字以下短篇、接近十万字的作品、较长多章作品的分章和窗口覆盖。
- 已完结和未完结作品。未完结作品只处理已提供内容，不续写、不补结局、不回收未解释伏笔。
- 改编计划确认、章节候选生成、来源对照、Proposal 审阅和 Revision 采纳。
- 追加章节、更新指定章节、重复导入检测、旧发布保持不变。
- 暂停、取消、重启后的检查点恢复，以及预算和调用次数限制。

## 合作者先做的三条主流程

### A. 短篇未完结首轮

准备 2—3 章、每章 500—3000 字的 TXT 或 DOCX，最后一章留一个明确未解问题，并标记作品“未完结”。

1. 导入原文并检查章节标题、顺序、段落内容。
2. 创建改编任务，只选前两章，确认计划和一场试读。
3. 生成第一章候选，逐段对照原文后采纳。
4. 检查候选是否保留人物关系、事件顺序和未解伏笔。
5. 确认没有自动增加结局、后续事件或角色提前泄密。

通过条件：第一章可正式采纳；未完结状态仍然保留；第二章未完成不阻塞第一章发布。

### B. 追加和更新

在 A 的同一作品中追加一章，再导入一次完全相同的文件，最后修改其中一章后再次导入。

检查：

- 完全相同的文件被识别为重复，不重复生成任务。
- 追加模式保留旧章 ID，只新增章节。
- 更新模式先展示差异和受影响候选，不静默覆盖已采纳正文。
- 旧任务仍指向旧原文快照；新增后文产生冲突时，只标记受影响候选。

### C. 十万字边界和恢复

准备接近 100,000 字的多章文本，启动批量分析后暂停，再恢复；随后取消一个新任务并重新创建。

检查：

- 窗口覆盖连续，没有漏掉窗口首尾段落。
- 暂停后不再发起新调用，恢复从最后检查点继续。
- 取消后迟到结果不会写入候选或正文。
- 前章修改后，只重算依赖它的后章结果。

五十万字只做确定性压力验证，不把压力结果当作文学质量验收。

### D. 正常 Agent 和网页工作台

使用一个普通原创写作作品，不走小说改编入口：

1. 创建作品，填写创作想法、人物和章节目标。
2. 让 Agent 先讨论，再生成一个场景候选。
3. 检查运行计划、工具调用摘要、候选 Diff 和 Proposal 状态。
4. 退回一次候选，再重新生成一次；确认正式正文没有被退回结果改变。
5. 采纳候选，进入审查、连续性检查和发布门禁。
6. 刷新页面、切换到任务列表再返回作品，确认对话、运行状态和审查结果仍然存在。
7. 在桌面宽度和手机宽度各操作一次，确认没有横向滚动、重复 Composer 或无法关闭的弹层。

这条流程要单独记录真实模型名、运行 ID、候选状态和页面截图。小说改编的真实 Gemini 验收不能替代普通 Agent 的真实模型验收。

## 必须重点观察的质量问题

每章候选都要记录以下结果：

- 事件是否遗漏、重排或新增。
- 角色说话人是否正确。
- 角色是否说出了当时尚不知道的秘密。
- 作者私设是否被官方资料或模型擅自纠正。
- 内心想法是否被错误写成公开台词。
- 未完结作品是否被补成结局。
- 来源引用能否定位回原文段落。
- 返修是否只改了指定正文块，没有改动范围外内容或来源 ID。

## 设置和模型连接

使用设置页先分别测试写作模型和演出模型，再激活。切换接口时确认旧 Key 没有被自动带入。测试失败时旧配置应继续可用；两个域一成功一失败时，页面应分别显示结果。

运行中的任务切换模型后，继续使用原模型快照；新模型必须通过新尝试生效。

## 通过门槛

以下项目全部满足，才建议标记“1.0 候选通过”：

1. A、B、C 三条流程均完成。
2. 至少一章真实模型候选被作者逐段审阅并采纳。
3. 未完结作品没有补结局或越界续写。
4. 追加、更新和重复导入没有破坏旧发布。
5. 暂停、恢复、取消和预算耗尽行为符合预期。
6. 发现的问题都有原文段落、章节 ID、任务 ID 或截图定位。

复现步骤：
