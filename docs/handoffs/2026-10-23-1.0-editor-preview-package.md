## 构建与复现

内部版本为 HaloCue **1.0.0-beta.4**、Electron **44.5.1**、官方 Codex **0.153.4**。Python **3.13.12** 的独立 venv 仅安装声明构建依赖，`pip check` 无冲突；Node **22.19.0**。未修改全局 Python、产品版本、用户配置或 1.1。

保留正常公开源码导出、源码清单／字节校验、完整源码扫描、PyInstaller、官方 Codex 校验、Electron 打包、许可证和完整程序扫描，随后生成逐文件清单、ZIP 和 SHA-256。导出器与 builder 的完整源码扫描在不同进程中读取同一份完成的不可变快照；两项都成功后才允许冻结。没有减少扫描目录或跳过门禁。

首次下载 Codex 和 Electron 遇到网络停滞，缓存后恢复正常构建。更正版本在下载 Codex NOTICE 时又遇到 TLS EOF；继续使用同一份已经通过双重源码扫描的冻结目录，补入符合仓库固定 SHA-256 的 LICENSE／NOTICE，重新生成并核验 Codex provenance，再完成 Electron、正常完整程序扫描及归档，没有重用旧包的产品字节。Codex 压缩包符合仓库固定 SHA-512；Electron 下载镜像取得的 ZIP SHA-256 为 `9b382492dcfee91f8f9e92c91f7972550a1b95d2299cac72279dab33a600d7db`，与官方 GitHub release asset digest 及 SHASUMS256 一致。镜像与代理变量仅用于本次构建进程，没有关闭完整性检查。

异机使用独立环境，正常构建命令如下。占位符均为复验者自己新建的目录，不依赖维护者本机路径；固定下载如遇传输失败，须先按仓库记录的 hash 核验缓存。

```text
python -m venv <BUILD_VENV>
<BUILD_PYTHON> -m pip install -r requirements.txt -r requirements-mcp.txt -r requirements-desktop-build.txt
python tools/export_public_source.py --source <REPO> --output <BUILD_ROOT>/source/HaloCue --build-root <BUILD_ROOT>
python tools/build_public_release.py --source <BUILD_ROOT>/source/HaloCue --output <BUILD_ROOT>/artifacts --python-executable <BUILD_PYTHON> --node-executable <NODE_22>
python tools/verify_portable_release.py <FINAL_ZIP> --root <FRESH_DRIVE_ROOT> --keep
```

原生窗口验收使用解压后的 `HaloCue.exe --self-test --no-update`，MCP 入口为 `HaloCueMCP.exe --check-runtime`。运行时使用自有临时 LocalAppData / AppData / UserProfile、移除 Python/Node PATH 及开发环境变量；不能直接在作者实际数据上执行窗口自测。
