# 1.0 portable startup correction

Owner: backend/client/release. Issue [#56](https://github.com/Suciko/HaloCue/issues/56).

are outside scope. Decisions follow [ADR-0009](../adr/0009-1.0-electron-host.md).

## Report and reproduction

The collaborator's shipped backend crashes during production import with
`IndexError: 5`; the Electron host then reports that the workbench could not
start. Previous acceptance used a deep workspace extraction location and did
not prove shallow-path portability. That earlier result remains evidence of
those conditions, not evidence of another machine's successful startup.

Actual adapter source executed with shallow PyInstaller-style `__file__` and
a valid frozen resource root reproduces exactly `IndexError: 5` in both services.
The unchanged R2 backend also fails to write a readiness receipt within eight
seconds when copied into a physical shallow directory below the system drive.
It is terminated by the test's owned process handle afterward. No author state
is used. Source-only tests record four failures and one pass before the fix.

Ranked causes checked: eager source-parent evaluation despite a frozen root;
missing bundled model/static resources; current-directory/developer environment
dependence. The first cause is confirmed: `getattr` evaluates its default
argument before selecting `_MEIPASS`. Both model adapters use `parents[5]`, and
catalog discovery unconditionally appends the same source fallback even when
the bundled candidate exists. Central resource resolution had the same eager
pattern with `parents[2]`.

## Change and acceptance boundary

The existing service resource-root helper now selects the frozen root in an
explicit branch. Both model adapters use it, and the catalog drops its duplicate
source-depth fallback. Source mode still resolves the repository root. The
remaining writing `server.py` parent calculations belong to its source-only
standalone CLI; the shipped launcher enters the integrated service directly.
No story/MCP wire contract or user-data migration changes.

The runtime-source path audit also found a maintainer-drive fallback for the
optional audio probe in `asset_validation.py`. It now uses only an explicit
probe or system PATH. Missing tools continue to report `probe_unavailable`.
An additional regression fails if discovery probes an implicit machine path;
explicit probe selection remains supported. The initial R3 builder was stopped
before compilation to include this correction in the sealed source.

Audio validation/probe checks: 24 passed. The HTTP/docs/workflow check initially
had 136 passes and one failure because CI still named the Beta 2 archive. CI now
names the current Beta 4 candidate. Both package and manual release jobs install
the tested Node 22.19.0 runtime and run the new shallow/renamed ZIP gate before
upload/publication; no workflow was manually dispatched. Workflow checks now
pass all 11 tests. The unchanged Electron host's seven Node tests also pass.

Five regressions cover cold adapter imports, shipped metadata lookup, a shallow
central-module filename and source mode. Focused runtime/model/catalog/build
checks: 82 passed, 1 skipped. Lint on new/changed helper, adapter, verifier and
test files passes. The catalog has seven pre-existing E702 findings outside the
changed locator; its check with E702 excluded passes. The new test/verifier files
are formatted.

`tools/verify_integrated_release.py` now checks selected-profile state and runs
from an unrelated working directory; `--fresh-profile` exercises normal
LocalAppData resolution with no `HALOCUE_USER_DATA_DIR`. Developer Python
variables and Python PATH are removed. `tools/verify_portable_release.py` owns
a new physical directory directly below a drive root, verifies two starts,
renames the package to a Chinese-and-space name and verifies two more starts.
It refuses existing roots and checks containment before relocation/cleanup.
Example, using a fresh receiving-machine path:

```powershell
python tools/verify_portable_release.py <RELEASE_ZIP> --root C:\HC-QA-Fresh
```

This is a reproducible local environment/path matrix, not a claim that a clean
VM or a second physical computer was tested. The collaborator should try the
new archive on the previously failing computer. Frozen backend rebuilding,
final source/bundle/notices audits, actual matrix results, ZIP digest, PR and
delivery receipt will be appended after they succeed. R2 stays preserved and
is superseded for collaborator distribution by the forthcoming R3 correction.
