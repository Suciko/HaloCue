# 1.0 AA 工作面焦点滚动修复

- Issue：[71](https://github.com/Suciko/HaloCue/issues/71)。
- 分支：`codex/1.0-aa-scroll-20261006`，基于 PR #70 的 `b0d97084`；仅涉及 1.0 AA 嵌入网页。
- 依据：client 上下文、ADR-0009、产品方向与会话治理规则。没有数据迁移、契约或制作流程改动。

## 问题与修复

合作者 R6 截图显示工作面在窗口中部截断、下方大片空白。最初只直接滚动内容页的源码/私有 Electron 检查未复现；在第一版 R8 候选 ZIP 的真实页面中，通过粘贴文本→识别→确认分场的实际控件操作复现了同样视觉症状，因此该候选包未交付。

内容页高度正确，但外层 `productionModule` 在聚焦/scrollIntoView 时也会滚动：内部浏览器测得 host.scrollTop≈393 px，窗口底部 720 px 而页面底部≈327 px。`overflow:hidden` 仍是可程序滚动的容器。

桌面宽度 >760 px 时把外层 host 改为 `overflow:clip`，让内部内容页独立滚动；不改变移动端既有策略。更新外层和 Shadow DOM 的 CSS 资源版本，避免复用旧 CSS。修复后内部浏览器重复相同操作：host.scrollTop=0，页面与窗口底部都为720 px，内容页 scrollTop=754，草稿方式与底部按钮可见。

## 测试包与磁盘空间事件

用户报告 `materialize_bundled_metadata` 抛出 `sqlite3.OperationalError: database or disk is full`。同一错误在本机 C 盘浅目录验收复现；当时 C 盘仅113,807,360字节空闲。五份本轮私有 Electron QA 副本约2.5 GB 留在 C 盘临时目录，确实加重了空间不足，已在确认路径和无存活进程后移到 E 盘。只移动本轮测试副本，未动作品和正常用户数据。

原候选包从实际 ZIP 重新解压、正常 LocalAppData 新用户目录、仅 System32 PATH、不相关工作目录、中文和空格改名后，四次启动/重启全部通过。该候选后来因上述 UI 复现被停止交付；重新构建包必须重新验收。此事件是空间清理结果，没有声称增加了磁盘不足错误页或改动 SQLite 行为。
