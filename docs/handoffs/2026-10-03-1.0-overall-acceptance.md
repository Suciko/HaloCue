## Decision

Conditional Beta acceptance, not a claim that every feature is fully accepted.
The existing release baseline has 4,081 passing tests and 16 skips. This session
adds real-resource, actual AA project, recovery and browser evidence and fixes
one reproducible clean-install naming defect. The source fix is a follow-up
candidate, not already present in the published Beta 2 executable.

## Reproduced defect and fixes

With no private name-baseline file, the official AA `세리카` resource displayed
`茜香` instead of the maintainer-confirmed `芹香`. The regression failed before
the change (1 failed, 3 passed).

`CharacterNameBaseline` now includes the five exact AA identities already
confirmed in official-story acceptance. A user baseline retains priority;
explicit resource `name_ja_fandom` metadata also wins over the bundled fallback.
Unreviewed identifiers and costume variants retain their existing source names.
Resource IDs, Spine paths and source prose are preserved. There is no schema,
file-layout or frozen-release migration.

The broader production suite also exposed two non-isolated teacher-delivery
fixtures: they install only into a synthetic temporary workspace but queried
the user's actual AA process. An unrelated AA installation was running, so
the real process guard correctly rejected them. The fixtures now mock only
their process probe. Production's running-AA guard remains intact and the
user's process was not stopped. The initially failing run is retained:
**479 passed, 2 failed, 291.59 s**; it is not called a passing suite.

This is limited reviewed coverage, not a complete Japanese-server translation
dictionary for the 102 bundled cards or every AA character. Official source
prose still contains two `茜香` references. An author-reviewed upstream writing
revision is required to standardize those references before creating a new
release; production must not silently rewrite an immutable source snapshot.

## Skip audit

The baseline's 16 distinct skips comprise 10 deliberately superseded legacy
behaviors, four Windows symbolic-link cases blocked by privilege (WinError
1314), and two optional catalog tests tied to an obsolete installation path.
The two catalog behaviors were exercised directly against the available real
catalog/cache. The four symlink cases remain unverified; a junction used by the
private native harness does not certify symbolic-link test coverage. Legacy
skips are not newly accepted product capabilities.

## Private receipts and continuation

The maintainer also requested subscription-only Agent use, with no metered
model API charges inside HaloCue. This is a follow-up requirement, not an
implemented capability in this patch. The recommended evaluation order is
Codex App Server with managed ChatGPT login, then Claude Code/Agent SDK with
subscription authentication; expose existing scoped proposal tools via MCP.
Reject API-key authentication and paid fallback, pause at subscription limits,
and require account-side extra usage to be disabled. Domestic Agent support
must be checked against each vendor's official integration entry point.
MCP alone does not provide model inference or subscription billing.

Current official references: [Codex App Server](https://learn.chatgpt.com/docs/app-server),
[Claude subscription/SDK status](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan),
and [Claude authentication priority](https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code).
The Claude SDK page's June 15 change is paused; its older credit table is not
the current rule. Reverify supported auth and billing before implementation.
