# 1.0 composer choices and dark work modal

Owner: client presentation over the existing writing service. Issue [#58](https://github.com/Suciko/HaloCue/issues/58). Branch `codex/1.0-choice-ui-20261004`, based on `c17653e2` / draft PR #57. The source-of-truth direction, client/backend context, ADR-0009 and session/remote collaboration protocol apply. The sibling 1.1 editor is outside this slice.

## Report and changes

The maintainer's screenshots show a dark new-work modal with white controls, faint text and a clipped action row. The modal's form could be taller than the outer clipping container, while its footer used negative margins. Its `div[role=dialog]` also falls outside generic native-dialog dark selectors. Header, scrolling fields and footer now have separate layout responsibilities. Controls and footer use existing appearance tokens; the footer retains bottom padding at regular, short and mobile dimensions.

Choice markup was rendered in the independently scrolling history. The redesign cascade also replaced its absolute layout with a normal block, hiding the submission action below long options. Only ordinary `choose` cards now float above the composer, with matching reading width. The option list scrolls independently, keeping the shared custom reply and send action visible. Selection updates a checked radio, checkmark and status. Custom text is always directly editable without a nested Other control; it sends the existing `__custom__` decision response. Busy locking prevents repeated sends; an API failure keeps the answer, renders a retry error and restores focus. Dismiss/reopen retains the draft. Proposal/approval behavior stays on its existing path.

There is no story model, wire contract or author-data migration. Discussion still does not silently create a formal Revision. Existing R3 frozen-resource fixes and portable acceptance gate remain prerequisites for a new package.
