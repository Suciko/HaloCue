## 已实现

章节正文取消阅读／编辑切换，空场景可以直接输入，已有正文点击文字即可放置光标。排版在阅读和输入时保持一致；段落编号、类型、人物名和相邻操作使用文档旁的空间，普通正文不再套输入框。人物名不受狭窄表单布局挤压。

每场使用一个 ProseMirror 编辑宿主，段落是文档节点，不是独立可聚焦输入框。同场内支持 Enter 分段、Shift+Enter 换行、边界合并、跨段拖选、替换、纯文本粘贴以及结构撤销／重做。保存与本次保存触发的重新渲染复用编辑器实例，保留光标、选区和历史。保存过程中继续输入的内容仍为待保存状态。外部正文真正改变时才替换文档状态。

顶部和章节工具栏同步显示保存状态，Ctrl/Cmd+S 保存当前章节，弹窗或其他文本控件输入时不抢快捷键。正式稿仍通过既有整章原子接口保存，使用既有场景版本校验、冲突反馈和稳定 block IDs；草稿缓存继续使用原有 sessionStorage 协议。空的临时段落可留在编辑器内，提交时按原有正式稿规范过滤。

单段选中文字后可主动点击“问助手”或“建议改写”，此时才将选区传给现有助手流程。选中文字本身不改变助手目标；按钮仅引用原文并预填“帮我把这段改得自然些，保留原意和人物语气。”，不会自动发送。未保存时提示先保存正文。

AI 候选继续在原文位置显示，并且只有显式采用才形成正式修订。可审查的待定候选使用只读投影，不采集为手写草稿；过期或与本地修改冲突的候选提供提示与放弃入口，正文仍可编辑。首次教学改为直接在用户自己的正文中输入／修改，移除阅读模式分支，保留按正式修订完成教学的条件。

场景仍是独立文档，不支持跨场景合并或一次编辑多个场景。原生跨段编辑不受单段限制，但助手引用沿用既有单段选区契约。没有新增后端 API、持久化字段或跨上下文契约。

## 依赖与构建

`services/halocue/writing/editor/` 保存可维护的源码、精确版本依赖、锁文件与构建脚本，生成本地 `web/manuscript-document.js`。使用 ProseMirror 的文档、输入与历史实现，避免自己维护一组互相独立的 contenteditable 输入框。

```sh
cd services/halocue/writing/editor
npm ci --ignore-scripts
npm run build
```

构建已通过；生成的 bundle 和 `web/vendor/manuscript-document/LICENSES.txt` 随源码提交。原始 MIT 许可证与组件版本可追溯，`THIRD_PARTY_NOTICES.md` 区分运行组件和仅构建时使用的 esbuild。网页不依赖 CDN，用户不需要 Node。`node_modules` 已确认被忽略，没有入库。

新增连续文档用例包括直接输入、段落结构、撤销／重做、稳定 IDs、显式保存、保存后撤销、真实鼠标点击句中光标位置、跨段鼠标拖选替换、纯文本粘贴、中文 composition 与异步页面渲染，以及只有主动按钮才引用给助手。桌面明暗主题和 390×844 深色有自动回归。旧用例的 textarea 操作换为真实文档点击／键盘输入；未删掉保存、冲突、审查或光标断言。
