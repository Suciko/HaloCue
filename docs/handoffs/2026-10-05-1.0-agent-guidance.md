## Confirmed causes and resulting behavior

- The service dispatched `load_workflow_template` and `read_work_context` when
  a reply requested no tools. Reply finalization and the simulation provider
  independently fabricated the same two success rows. All three fallbacks are
  removed: ordinary replies can have zero tool calls and zero activity steps.
- Existing native model tool calls execute on demand. Follow-up prompts now
  allow lookup results to lead to a draft or scoped prose edit in the same
  user turn, rather than allowing only another read. The three-round limit,
  validation, permissions, cancellation guards and Proposal boundary remain.
- A shared public vocabulary classifies actual tools as character references,
  work data, conversation, prose, creative organization, conflict checks,
  attachments or document retrieval. Expandable details show bounded results
  such as card counts and character names, or actual failures. Raw output JSON
  and private paths are not used as the default result summary.
- Character preparation comes from the durable `character_resolution` receipt:
  show names added/reused and unresolved references as compact activity rows.
  These rows explicitly identify system preparation; they are not fabricated
  Agent tool calls. Formal approval of new knowledge is still separate.
- Completed native tools are saved before the model consumes their results.
  Finalization updates the same run/ordinal rows, preserving tool-call IDs.
  Polling previously discarded running results; it now updates only the
  visible running activity row when progress changes, rather than rerendering
  the conversation/composer every polling tick.
- Optional category/origin metadata is additive. Existing presentation schema
  and DB tables remain compatible; no migration is required. Existing historical
  activity records are preserved, not rewritten to pretend they never happened.

## Discussion rules and research

The product copy of the BA writing Skill now loads `knowledge/创作讨论.md`
for discussion rather than the manuscript startup SOP. Respond to the author's
scene, genre and character reactions first. Short everyday scenes, comedy,
relationships, OC/IF and serious stories are all supported according to the
author's goal. Questions default to none; ask only for an answer that changes
the next step. Full manuscript requirements remain for manuscript candidates,
while one-write/no-edit restrictions are explicitly limited to blind testing.

Read representative local analysis and script openings requested by the
maintainer, not every complete script:

- `剧本评价结构化分析表.md`, `剧本评价标准.txt`;
- flow/appeal analysis files `老师变成了吸血鬼.txt`, `星织.txt`,
  `无糖的蘑菇面包.txt`;
- identified script openings `星野的女儿穿越来了！？.txt`, `鱼子酱日记.txt`,
  `三一保安的第三次机会.txt`, `为昨日献上奇迹.txt`;
- the maintainer's BA writing architecture/collaboration memory.

Only original general guidance was added: concrete interactions, differing
reactions, payoff for the promised scene, and genre-specific use of tension or
emotion. No third-party scripts, reviews, dialogue samples or local research
paths were copied into product prompts. Research originals were preserved;
this handoff records the product-Skill change. Background/expression assets
remain on the AA production side as established in PR #66; they do not limit
the author's imagined writing locations.

The pack includes the new source in its index and synthetic fixtures. Content
hashes generate a new immutable Skill manifest on loading; old snapshots remain.
Prompt cache-prefix and formal manuscript rule regressions pass.
