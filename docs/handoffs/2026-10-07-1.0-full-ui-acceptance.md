## 本轮修复

1. 新 ScriptRelease 冻结可选 location 并据冻结数据组装标题，交付启用资源自动草拟。精确匹配该地点，排除 CG 与时间冲突，不从对白猜背景、不自动批准、不覆盖已有映射。旧发布无新字段时文本与校验保持原样。两个 1.0 schema 仅增加可选字段，没有删除旧能力。
2. 正文已有本场 thread 的整体对话关联使用服务已有 POST 接口，修复实际 501。
3. AA 夜间嵌套面板、表情/流程/辅助按钮对比度；人物提示占满资料网格；新作失败以弹窗内持久 role=alert 显示，保留输入并允许重试。
4. 自动创建本场对话会增加 work.version；整章保存等待自己持有的创建请求并使用完成后的版本，仍拦截外部正文版本冲突。不会以迟到回包覆盖新作品或更新版本。
5. 保存途中继续输入时保留新草稿，并把它衔接到本次已成功保存的正文修订；不误当外部冲突，也不把外部更高版本当作自己的保存基准。红测复现失败后，14 个整章浏览器测试通过（34.49 秒）。
6. 测试夹具等待真正已提交的变化，重载后允许显示合法当前/完成步骤，避开 Chromium 禁用端口。写作规则由共享隔离 fixture 提供，测试不再继承本机旧版私有规则目录。新增有上限、去 query/headers/body 的 HTTP/传输诊断，保留原有断言。

## 全量失败调查

读取了 PR 80 两轮三版本日志；六种原始失败包括章节焦点/保存时序、AA 步骤重载断言、移动端世界建议按钮、逐条正文修改到 AA 的流程、旧素材预检 ERR_NO_BUFFER_SPACE。

保存时序在实际浏览器得到复现并修复。重新运行逐条正文修改流程时，发现该测试在创建 runtime 后才设置规则目录，进程继承维护者的旧规则，被当作 discussion_only 拦截。共享 fixture 现在在 runtime 创建前隔离规则；1440 明/390 暗流程都通过。不能将这一环境问题冒充原始远程 CI 的确定原因。世界建议与预检本地已通过，但旧远程失败未捕获直接根因；新诊断和最新远程矩阵须继续核对。

本地两次早期全量记录不能计为通过：一次 99% 被中断；另一次 Windows 默认编码写入 pytest UTF-8 捕获流，在页面关闭产生的中文 socket 错误后触发捕获解码错误，后续成批 setup/teardown 报错。又一次复验未先创建 basetemp 父目录，是本次命令错误，不是产品缺陷。最终复验明确创建独立根目录并使用 UTF-8；最终结果待末尾收据。

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONUTF8='1'
New-Item -ItemType Directory -Path <FRESH_ISOLATED_ROOT>
python -m pytest -vv -o faulthandler_timeout=180 `
  --basetemp <FRESH_ISOLATED_ROOT>/pytest `
  --junitxml <FRESH_ISOLATED_ROOT>/results.xml
```

相关窄验收包括发布/资源草拟 26 passed（21.85 秒）、两项 AA 页面（65.41 秒）、窗口 Node 检查 8 passed、连接 UI/发布依赖 51 passed/1 skipped、最后依赖审计与两个全流程 11 passed（165.37 秒）。日志和测试数据留在忽略的本地目录，公开交接不携带用户资源、账户或研究脚本。
