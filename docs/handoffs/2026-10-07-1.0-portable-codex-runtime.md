- 问题：测试者未安装系统 Codex CLI 时，原有订阅接入缺少必需的本地运行程序。最终提交和 PR 收据在末尾。

## 实现

Electron 发布构建下载并随包携带官方 `@openai/codex` Windows x64 原生 0.153.4，固定 npm SHA-512 完整性值。只写入已列明的八项依赖，拒绝非普通条目、未知文件和超限内容，保留官方 tag 的 LICENSE/NOTICE，记录逐文件 SHA-256 与来源。解压后执行原生 `--version` 自检。运行时无需下载、Node、npm 或系统 Python。

运行发现优先级为显式用户覆盖、随包原生程序、系统 PATH/npm。冻结后从主程序所在目录定位 `tools/codex`。Electron 发布审计要求完整运行依赖与合法通知，不能在工具目录缺失时绕过；公开扫描仅允许已列明的官方原生程序，私有账户状态不进入包。

设置页面准确区分未安装、已就绪待登录和已登录。缺程序时禁用登录按钮并给出完整解压/官方安装入口；有程序时提示登录自己的 ChatGPT 账号。沿用账户隔离和禁用 API 费用回退，不复制维护者登录资料。

## 验证与限制

- 新依赖单元测试和既有 Codex/发布/Electron 测试：51 passed、1 skipped，16.01 秒；更新连接 UI 后相关浏览器/原生发现/发布检查：51 passed、1 skipped，33.26 秒。
- 最后加入“有 Electron asar 但没有工具目录”的审计回归，连同两种作者到 AA 流程：11 passed，165.37 秒。Codex 许可 fixture 必须同时声明 Chromium、Node.js 与 Electron，不能把不完整 fixture 当产品审计失败。
- 八项浏览器组合覆盖安装/未安装、明暗、1280×720/1600×900：按钮状态、提示、边距和无登录副作用。该部分使用可控状态，不是账户认证证据。
- 另下载真实官方依赖，在独立用户目录、仅 System32 的 PATH、无 auth.json 状态启动原生 app-server，实际返回 installed=true、logged_in=false、codex_login_required；没有写入账户认证。原生文件公开扫描通过。
- 内部浏览器 1600×900 夜间界面也实际显示“Codex 已就绪，请登录自己的 ChatGPT 账号”，登录按钮可用；没有点击真实账户登录。

依赖解压约 396 MB，尚未制作新完整 HaloCue 包或测量新 ZIP 增量。真实 ChatGPT 登录、模型推理、订阅额度回执以及新冻结包在第二台电脑的启动仍须分别验收。单独原生依赖启动不能代替上述验收。
