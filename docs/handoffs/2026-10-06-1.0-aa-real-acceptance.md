## 修复及原因

### 已绑定角色头像

旧 UI 只读取目录前 200 项，后面的角色没有头像状态；搜索又用结果替换缓存，使其他已绑定角色丢失头像。真实复现为日奈缺头像，搜索日奈后改成亚子缺头像。

`production/ui/app.js` 按当前任务已绑定角色的精确 ID 读取冻结详情，并按 ID 合并搜索结果。切换任务不复用其他任务缓存，失败读取可重试。既有角色详情响应补充可选 `face_count`、`preview_available`，后者只来自任务素材或冻结预览，保持自定义预览优先。

最初怀疑预览清单只包含 `_Small`，完整检查后证伪：原名称与 `_Small` 均存在。没有引入该猜测的路径回退代码。

### 夜间审查／安装界面

安装构建摘要、安装名称摘要、演出建议摘要使用写死的浅色背景，导致夜间文字对比度低。主题增加这些真实组件及建议状态的覆盖，保持浅色样式和图片颜色。安装窗口在 1280×720 原来顶到标题栏上方，现限定在标题栏下且保留底部间距。同步更新嵌入样式缓存版本。

### 查看重命名安装结果

重启后“查看安装结果”原来恢复源任务名、重新预检并显示“确认安装”；服务实际禁止同一已安装状态直接再次安装。现在读取已有 `last_installed_project` 与 `existing_install` 展示记录，隐藏命名表单和重复安装入口，不发安装预检。显示工作区内相对位置；当前配置找不到该工程时明确提示检查工作区／移动情况。首次安装成功立即进入相同结果视图；重新编译后恢复正常安装表单。

真实资源来自维护者授权的本地目录且只读；任务、草稿、配置副本、模型收据、生成项目和安装目标均在隔离 QA 目录。模型使用维护者已有服务配置，原用户设置与工程未修改。私有文件及截图不进入 Git，共享测试使用合成资源。
