## 当前行为

接续[面板与阅读模式交接](2026-10-20-1.0-first-use-followup.md)，教学终点及老用户默认自由创作仍以[方案第 0 节](../1.0-guided-workflow-plan-2026-10-19.md#0-同日纠正与当前交付边界)为准。

- 完整 AI 路线已覆盖：空白作品 → 想法 → 方向候选与明确采纳 → 结构候选与明确采纳 → 正文视图 → 具体场景 → 本场人物选择 → 起草请求 → 原位候选审查 → 明确应用后退出教学。结构规模和文字为模拟结果，不代表真实模型质量。
- 方向和结构仍沿用实际回复的下一步按钮。进入正文视图与选中具体场景分开说明；缺少本场人物时点亮现有缺项区域，打开选择后点亮真实表单，保存后指向实际 Agent 入口。
- 发现上下文自动准备只局部刷新 Inspector，教学没有重算。该刷新回调现在同时更新首次教学与可选陪跑；正文和输入不重建。
- 生成中显示等待，保留现有“停止本轮”；失败时优先点亮真实失败说明及重试/设置入口，允许转为手写。旧候选因设定变化被标为 superseded 后，解释失效并接到当前要求或手写。
- 教学作品移入回收站后，先高亮回收站，再高亮该作品的恢复按钮；恢复后依次指向返回列表、打开原作品。可显式选择从新作品开始，重新建立基线。不会要求返回已删除作品或把旧正文误作新进度。
- Web Control 发现夜间模式的失败卡与本场人物表单仍为浅色背景，叠加夜间浅色文字无法阅读。相关背景和文字改用现有主题变量，正文/失败说明对比度断言至少 4.5:1。

## 首次起草的工具边界

此前空白场景发送“起草本场”只产生讨论回复，没有可审查正文。新增内部 `propose_scene_draft` 工具，输入 JSON schema 为 `text`（1–60000 字符）、`reason`（1–1000 字符），身份绑定当前 scene 对话，仅供 `scene.draft.generate`。真实 Provider 的现有讨论规则和稳定系统前缀保留，再追加直接起草与只讨论时不调用的说明。

工具只准备结果；在现有授权结果事务中创建一份 `scene_script` Proposal，base 为 null。正式 Revision 仍由原有明确应用/采纳操作建立。提交前重查空白正文、待审候选、规则和已确认材料、人物名、场景契约及原固定输入来源。取消、来源变化、重复起草、已有正文、仅讨论作用域均有回归；工具回执不重传完整候选。

没有新增 HTTP 入口、持久化 schema 迁移、依赖或后台模型调用。工具契约由现有 registry JSON schema 暴露给当前 Agent 回合；未扩展外部 MCP 允许列表。已有正文继续走 `propose_scene_text_edit`，未改正式采纳边界。用户流程说明已写入 `services/halocue/writing/docs/authoring-workspace.md`。
