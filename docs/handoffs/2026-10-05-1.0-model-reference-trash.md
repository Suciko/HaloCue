Repository: HaloCue 1.0, branch `codex/1.0-model-reference-20261005`, based on
`5a1d2772` / draft PR #63. Issues [#64](https://github.com/Suciko/HaloCue/issues/64)

## Confirmed causes and changes

- Native datalist filters the seven returned models against the already-filled
  model name. An explicit popup now lists all fetched models, has its own search,
  supports keyboard selection, keeps typed model names, and clears candidates on
  endpoint changes, empty responses and refresh failures. Same-endpoint reopening
  retains the fetched list. Existing stale-response and secret-binding guards stay.
- The catalog contained 102 complete files; default API limit 18 and misleading
  UI copy caused the reported count. Additive `total_cards`, `matched_cards` and
  `has_more` fields distinguish catalog size from a slice. Browsing requests up
  to 200 and progressive UI disclosure makes every card reachable.
- Writing search previously queried scenario text, curated cards and AA visual
  metadata together. The maintainer explicitly excludes background, expression
  and appearance indices from writing. The UI now has only character references
  and original excerpts. The historical `search_bundled_character_metadata` tool
  name stays compatible but its implementation reads curated reference cards;
  it never queries outfits/faces. Resource APIs and AA research remain available
  to the asset/production surfaces. No research files or game media are removed.
- Common character aliases and 基沃托斯/奇普托斯/Kivotos search original text
  without translating or altering returned evidence. Real shipped corpus query
  基沃托斯 was verified in the internal browser, returning 奇普托斯 dialogue.
- Work deletion is recoverable: a named dialog moves the work to trash, hiding
  it from ordinary selection; the project page exposes restore. Status/version
  changes are transactional; stale versions and active queued/running Agent
  tasks are rejected. Content, revisions and conversations remain intact.
  Deleted work HTTP routes are blocked; restore restores access. Current/last
  deletion resets navigation and the active work. No schema migration is needed.
