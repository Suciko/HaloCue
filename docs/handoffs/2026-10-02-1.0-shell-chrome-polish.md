- Scope: accepted maintainer request to prioritize the current 1.0 web shell UI before further feature acceptance. - Source: maintainer reported SVG/label spacing, crowded top-bar information/actions, and asked for layout that can accommodate future Electron maximize/close controls.

## Implemented

- Consistent vertical rail layout in every desktop workspace: 20px SVG, zero icon margin, one 6px icon/label gap, 14px label line-height. Remove the writing-only extra bottom margin that compounded the flex gap.
- Keep the title/home action and actual work navigation. Remove the unused STUDIO suffix and duplicate top help/model-status entries from the primary view; settings/help remain on the rail and mobile navigation. Keep manuscript save and dirty/error status, with quieter status styling.
- Production top bar keeps current task, task materials and one More menu. New production and task overview move into the menu alongside background tasks/refresh; existing proxy targets and availability logic remain. Duplicate AA breadcrumb/divider are hidden on this surface.
- More menu uses theme tokens, flat menu rows and supports outside-pointer dismissal, Escape with focus return, arrow navigation and Home/End. Abort the document listener on reinstall/exit to avoid accumulating handlers across workspace switches.
- Bump shell stylesheet/embed script cache versions.
- Opt-in desktop layout uses `html[data-window-chrome="overlay"]`, a default 140px right reservation, optional `--hc-window-controls-width` override, and drag/no-drag regions. A future trusted host must supply actual native controls and opt in; browsers keep normal layout. No Electron dependency, installer, fake window buttons, native-window API or preload bridge was added. Actual minimize/maximize/close/drag behavior is unverified until packaged-host acceptance.
