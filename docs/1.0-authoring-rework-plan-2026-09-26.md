## 1. 重构目标

让作者能够先积累世界观与人物，逐步形成长篇大纲，再以整章为单位创作、审查和整理剧情变化。所有主要页面应直接呈现要读写的内容。

这次反馈修正了先前方案里的三个方向：不再把一句故事想法作为创建前提；资料成为左侧固定可达的主要工作区；场景审查与记忆整理从作者的逐场必经操作，转为后台协作过程，整章提供统一结果。

旧计划和交付报告保留为历史记录，不把其中的“已交付”理解为本轮体验已经合格。本文不扩展到 1.1 视频编辑器重做。

## 3. 内容归属与导航

### 3.1 可以先有世界，再有作品

建议建立三个清楚的范围：

| 范围 | 放什么 | 如何使用 |
|---|---|---|
| 世界观底稿 | 总体世界说明、人物原型、地点、组织、规则、参考文件 | 可独立保存，不需要先有故事名、第一章或一句梗概 |
| 作品 | 当前作品大纲、人物版本、私设、正文、剧情记录 | 选择底稿后建立本作品可编辑副本，并保留来源版本 |
| 章节 | 本章细纲、连续正文、审查结果、本章变化 | 作者主要创作和确认单位；场景保留为内部组织与定位单位 |

底稿更新先提示差异，由作者选择是否引入作品，不能直接改变正在写的故事。首版采用“复用时复制并记录来源”的简单策略；暂不建设跨作品实时同步体系。

世界底稿支持一份自由文本总说明，人物/地点/规则可以逐步提取为结构化卡片。不要要求作者先把所有内容拆成表单。BA 起始底稿、本作私设和原作证据继续区分，但不要求每张卡都走教学流程。

### 3.2 起步页

首次进入显示作品与底稿入口，不自动弹出新建作品。提供三个并列动作：创建作品、整理世界观、导入已有内容。

新建作品只需可随时改的名称，也可自动使用“未命名作品”；想法、长短篇、世界来源均可暂时不填。创建后落在可直接选择“大纲 / 正文 / 人物 / 世界观”的工作区。短篇可以直接开写；长篇可以先建总纲和卷章，不自动要求完成第一场。

“还没想好”时，作者可写零散便条、从人物或世界设定开始，也可主动让助手一次询问一个具体问题。渐进讨论是可选辅助，不是进入工作台的门槛。

### 3.3 左侧固定入口

建议同一左侧导航包含：作品、创作、资料、AA 制作、素材。资料组可展开人物、世界观、剧情记录、导入文件；在创作页也保持资料入口可见。

- 顶部显示当前作品；资料区明确当前范围是“某世界底稿”还是“某作品”，不暗中切换作用域。
- 创作内部保留构思、大纲、正文、定稿；移除左侧重复的“细纲 / 正文 / 发布”流程切换。
- 关系图作为资料的查看方式；待审建议作为数量和侧面板入口，不占一个常驻空白主页面。
- 素材继续管理图片、音效、立绘等媒体，与文字设定资料区分。

## 4. 工作区改造

### 4.1 构思：对话可展开，作品成果一直找得到

主区上方用紧凑标题和讨论范围；已有作品打开新对话时显示“继续讨论这部作品”，不重复新手欢迎页。输入框与对话使用同一居中阅读宽度，展开收起侧栏时不变成通栏巨框。

底稿、总纲、已采纳决定有固定入口；聊天中的大纲可以“整理到大纲”，预览后落到对应总纲/卷/章。聊天记录不承担正式大纲的存储和展示职责。

撤掉常驻“当前下一步”大面板。需要处理的事项显示为短提示与数量，展开后才显示清单；没有待审内容时不保留空助手面板。

### 4.2 大纲：从目录改为真正的大纲文档

大纲支持三个阅读层级：全作总纲、分卷大纲、章节细纲。总纲可写主题、核心冲突、主要线索和阶段发展；卷/章有各自正文式梗概。场景拆分置于章细纲下，不再占据大纲页全部主区。

已有 `brief`、`story_blueprint`、卷章结构与场景目标需要投影到同一大纲入口；不能丢掉构思阶段已确认的内容。现有方向数据不等于完整的长篇大纲，新字段和版本仍需补齐。

作者可以直接修改、整理顺序、展开阅读整部大纲。助手提出的调整先显示差异，采用后更新相应范围；未采用方案保留为候选。只改大纲不会自动重写已完成正文。

删除推荐场景大卡、冗余边框和相邻双横线。主标题下直接是本层大纲内容，章节目录负责定位，当前编辑区域占视觉中心。

### 4.3 正文：连续读写整章

正文默认整章连续读写，各场景使用同一排版；标题和轻量间距区分场景。旁白和对白通过字重、缩进和角色名区分，不给每行套框、编号和工具栏。编号及段落操作在定位、悬停或选中时出现。

章节工具栏集中保存状态、检查本章、查看修改。选中文字后可请助手改写；需要单场细调时再选择场景，右侧明确显示作用范围。审查、变化建议、历史和引用均在可关闭的面板中，不插在章正文中间。

不要把剧本文字强制变成小说格式：保留角色、旁白、对白等结构，只统一阅读呈现。AA 所需场景和段落 ID 保持稳定。

### 4.4 审查与剧情变化：以章为单位

默认流程为：写完或阶段保存一章 → 检查本章 → 一份问题清单与本章变化 → 作者处理或批量确认。

AI 自动完成场景间承接、人物知情状态、地点时间连续性和设定冲突检查。长章超出可用输入时，内部按段检查后做跨段汇总，作者仍然只操作一章。单场重查作为高级操作保留。

实施必须包含：

- 检查固定一份章节快照：章节顺序、所含正文版本和引用设定版本明确。结果能定位到具体段落。
- 中途编辑后，旧检查标记过期，不把旧结果当作新正文通过。失败或部分完成可重试，结果不能重复写入。
- “本章变化”统一列出新事实、关系变化、伏笔与人物状态；相同变化去重，互相矛盾的内容指出冲突。
- 作者可批量采用无冲突项，也可逐项决定；后台计算过程不用逐场确认，AI 提议仍不自动覆盖正式设定。
- 定稿规则改为识别当前章节检查与章节变化处理结果。已有场景检查历史保留为证据；不简单隐藏旧门槛，更不自动伪造通过状态。
- 一章完成后能继续下一章；仍可写草稿，不因上一场尚未“沉淀”而反复中断。

### 4.5 资料与卡片

统一采用“分类/列表 + 内容详情”的布局。打开世界观直接看到总说明与已有条目；空库只显示一句说明，以及新建和导入两个动作。BA 底稿选择放在新建/导入流程内，不常驻首屏。

卡片详情第一屏显示名称、类别与核心内容，并可直接编辑。来源、别名、关联、历史放在次级区域；检查有实际问题时才显示。AI 协助以一个入口打开，不再叠加体检框、步骤框和引导框。

复杂编辑使用宽侧面板或独立详情页，避免窄窗多层滚动。关联项用搜索选择器与简短摘要；跳转后能返回刚才编辑的位置和未保存内容。

用户界面使用“保存 / 版本记录 / 引用”，不显示“整个 WorldBible 的新修订”“正式 Revision”等内部术语。

### 4.6 导入：以想得到什么为中心

取消“来源资料与检索”作为创作者必须理解的独立主流程；保留文件原文、引用和检索能力，用于导入、查证和助手读取依据。

统一导入路径：选择文件或粘贴 → 预览原文与识别结果 → 选择用途和归属 → 确认写入。

| 用途 | 目标 |
|---|---|
| 世界设定 | 世界底稿或本作品世界观，可先整篇保存，再选择是否拆卡 |
| 人物资料 | 人物卡候选；显示识别字段和未识别原文 |
| 故事大纲 | 总纲、卷纲或章纲；预览章节层级 |
| 正文 | 新作品或指定章节；预览分章分场，不直接覆盖已有稿 |
| 暂时不分类 | 导入文件，之后继续整理 |

优先贯通当前已有文稿与人物/世界卡导入能力；逐一明确 TXT/Markdown、现有结构化卡、DOCX/PDF 的实际支持边界。只提供文件扩展名选择不算导入完成；扫描 PDF 的 OCR 属于单独能力，不假装已解析。

导入产生重复名称时提供新建、合并预览或跳过，保留来源位置。纯文本预览和原文保存无需模型；AI 提取有明确动作和可恢复失败状态。原作检索放在搜索入口或“从原作查找”内，结果可引用到正在编辑的卡片。

## 5. 模型服务重构与失败诊断

### 5.1 先处理当前可选模型但启用失败

本轮源码发现以下确定性差异，它们是排查线索，尚不是特定接口失败的已证实根因：

| 差异 | 后续处理 |
|---|---|
| 写作连接探测固定使用 `max_tokens=256` 和 15 秒超时，而表单超时默认 120 秒 | 连接探测复用正式调用的协议适配与能力规则，明确连接/响应等待时间，避免推理模型因探测预算过小被误判 |
| OpenAI 兼容探测直接发往 Chat Completions；正式 provider 另有 token 参数选择逻辑 | 核对实际接口支持的协议与参数；测试成功应能代表后续写作请求兼容 |
| 界面输出上限范围为 512–128000，写作后端为 256–256000，制作后端为 512–128000 | 从统一能力描述产生校验，不再让同一表单在两个服务得到不同答案 |
| “保存并立即启用”按用途分别请求写作与制作服务 | 清楚显示每个用途的结果，支持只重试失败用途；避免一处成功被总错误覆盖 |
| `activate` 测试成功后才保存；失败后不能等同于“配置已保存” | 拆分保存配置草稿、测试、启用三个状态；未验证配置可保存，但不替换当前有效连接 |
| 部分失败仅通过弹窗外的 toast 提示 | 字段错误就地展示，服务响应在设置内部保留，提示始终处于当前可见交互层 |

针对用户实际失败，后续记录脱敏的协议、请求路径、模型 ID、HTTP 状态/错误码及失败用途；区分路径错误、鉴权、参数不支持、超时、响应格式和本地保存错误。避免仅凭“模型能列出来”判断生成协议兼容。

### 5.2 表单顺序

服务商 → 协议和服务地址 → API Key → 模型列表/手填模型 → 模型能力 → 用途 → 保存/测试/启用。

自定义接口的协议和地址永久展开。高级采样等设置可以折叠，但连接所必需的信息不折叠。获取列表失败仍支持手填模型 ID；不要因为列表接口不可用就拒绝有效模型。

### 5.3 模型能力与 token 参数

每个“服务商 + 模型”维护上下文容量、最大输入（若单独约束）、最大输出、推理能力、支持的参数及来源/更新时间。已知模型按实际能力预填，不再统一 8192；自定义中转可按其实际限制覆盖。

把“能力最大值”和“本次请求额度”分开：容量字段填真实上限；输出默认采用该接口支持的最大输出能力并允许调整。发送请求时结合已用输入和协议限制计算可用额度，不能把最大上下文同时当作最大输入和最大输出。

预设优先匹配准确服务商和模型版本；接口明确返回的实际限制用于约束预设，人工覆盖保留。列表接口只有模型名时，不能把缺失字段当作已识别，也不能按名称猜一个精确值。未知能力显示待配置，并保留手动输入。

高级项按能力显示：输出预算、上下文使用与裁剪策略、temperature/top_p、推理强度或思考预算、超时；不支持的参数不发送。现有“均衡/创意/严格”主要是写作提示词偏好，不能继续冒充真实模型推理参数。

长篇上下文包含当前章正文/章纲、全作摘要、相关设定与前章状态；超预算先缩减非必要历史或分段处理，不能静默截掉当前正文。向作者展示实际范围和估算，不要求手工管理每个场景的上下文。

参考 Cherry Studio 的模型目录、服务商覆盖及用户覆盖分层；不复制未经验证的具体上限，也不把其开发分支行为当作所有发行版保证：

- [Provider & Model Registry System](https://github.com/CherryHQ/cherry-studio/blob/main/docs/references/provider-model/provider-registry.md)
- [ModelService](https://github.com/CherryHQ/cherry-studio/blob/main/src/main/data/services/ModelService.ts)

### 5.4 统一反馈层

字段校验在字段旁；连接结果在表单内；全局通知需要支持原生 dialog 顶层场景。嵌套确认、下拉选择、错误详情的焦点和层级统一管理。错误保留到作者处理或关闭，不能只显示五秒后消失。

## 6. 视觉方向与验收基准

采用安静的桌面写作工具风格：保留蓝色主操作色，统一白色/浅灰背景与导航；正文深色，辅助说明降一级但保持可读。移除资料页独有的米色底和蓝绿混用的强调框。

建议初版尺寸：正文 17–18px、行高 1.7–1.85；表单正文 14–16px；主内容阅读宽度约 760–920px；左导航约 220–248px，按需右面板约 320–380px。使用现有字体资源，统一 4/8px 间距阶梯，阴影仅用于浮层。具体数值以原型的真实中文密度验证，不为了大标题牺牲内容。

验收不以“按钮都在、测试都绿”为结束：

- 第一屏能看出当前编辑对象、主体内容和一个主要动作；不用先滚过引导才能开始。
- 总纲、章纲、正文、人物、世界观都能在固定位置找到；导航不出现同义重复。
- 侧栏展开/关闭、窗口变窄、125%/150% 缩放时，主体不溢出，关键动作可达。选择一个主要内容滚动区，避免卡片内再套多层滚动。
- 浅色和深色主题使用相同组件与层级；键盘焦点清楚，错误不只依靠颜色。
- 用有内容的长篇样本检查：多卷、多章、多人物、多设定，以及一章包含多个场景。样本规模用于压力检验，不作为预设用户限制。

| 阶段 | 交付 | 验收例子 |

目标：设置中心打开时，作者触发校验或连接失败，能立即看到发生在哪个字段/步骤，并保留修正入口。

统一完成定义：相关验收项均有证据，阻断问题已处理，界面符合已选结构，旧内容和版本关系保持，未验证边界写清楚。修正一个问题后仅重复受影响检查；没有新变化或失败原因时不循环重跑。

### 12.2 成本怎么控制

- 一个任务一次派发，范围以可独立演示的用户结果为单位；不发“重构整个资料库”这种宽泛指令。
- 工作者只加载相关规格和文件；主代理在检查点集中审阅，不持续重复读全部上下文。
- 小错误直接带复现和期望结果退回。同一问题连续两轮没有进展，由主代理重新定位原因或接手，避免无方向返工。
- 先以 T01 做合作试点，记录耗时、可获得的用量、返工次数和主代理复核投入，再决定后续分配。拿不到准确计费就报告操作/用量证据，不声称节省了具体金额。
- 公开 API 单价不能直接换算本地 Codex 订阅消耗；实际节省还取决于上下文、重复调用和返工。模型选择本身不构成质量或成本保证。
