# HaloCue 1.0 高级部署与更新

## 本地服务

集成运行时是单一来源入口，默认只监听本机：

```powershell
$env:PYTHONPATH='services/halocue/integrated/src;services/halocue/writing/src;services/halocue/production/src'
# 默认使用随包规则；仅在自定义规则时设置 HALOCUE_BA_WRITING_SKILL_DIR
python -m halocue_integrated.server --port 8910
```

写作和制作服务由集成网关在内部端口启动；浏览器只接触同源网关。生产环境不应把 HaloCue 服务绑定到 `0.0.0.0`，也不应把 API Key 放进浏览器环境变量。

## 主要 API 边界

- 写作：`/api/v1/works`、`/api/v1/works/{id}/scenes`、`/api/v1/works/{id}/agent-jobs`。
- 发布：`/api/v1/works/{id}/releases`，冻结后形成不可变 ScriptRelease。
- 制作：`/production/api/v1/production-runs`、`.../review`、`.../compile`、`.../install`。
- 健康：`/api/v1/health`、`/production/api/v1/health`。

旧版兼容启动器还提供本地迁移向导接口：`GET /api/migration/status`，以及
`POST /api/migration/backup`、`POST /api/migration/import`、
`POST /api/migration/skip`。这些接口只处理 `%LOCALAPPDATA%\\HaloCue` 中的已知配置/数据库文件，
不会覆盖已有 1.0 文件。

写操作必须携带期望版本或幂等键；版本冲突返回 409。制作端只接收冻结的 ScriptRelease，不回写写作正文。

## 反馈同步

反馈先写本地 `writing.db`，再按启动时配置同步到独立服务：

```powershell
$env:HALOCUE_FEEDBACK_REMOTE_URL='https://your-server.example/api/halocue/feedback'
$env:HALOCUE_FEEDBACK_REMOTE_TOKEN='<Bearer 密码>'
```

远端不可用时记录 `remote_status=pending`，不会丢失本地反馈。Token 只由 Python 服务读取，不发送给浏览器。

## 更新清单

默认清单地址：

```text
https://github.com/Suciko/HaloCue/releases/latest/download/update-manifest.json
```

清单必须是 `halocue-update/1`，包含产品、stable/beta 渠道、Windows x64、SemVer、最小支持版本、ZIP URL/大小/SHA-256、Ed25519 签名、Key ID 和更新说明 URL。CI 只在测试、公开边界扫描和包 smoke 全部通过后上传清单与 ZIP。

`tools/build_update_manifest.py` 从 ZIP 计算大小和 SHA-256，并使用
`HALOCUE_UPDATE_SIGNING_KEY` 签名；仓库和公开包都不保存私钥。便携包同时包含
`HaloCueUpdater.exe`，负责主进程退出后的目录替换和启动失败恢复。

签名私钥只放在 GitHub Actions Secret 或离线发布机；客户端只内置公钥。清单和 ZIP 均使用 HTTPS，ZIP 解压拒绝绝对路径、`..` 和符号链接。

首次正式发布前，维护者必须把稳定公钥写入 `halocue_meta.py` 的
`UPDATE_PUBLIC_KEYS`（或在测试环境通过 `HALOCUE_UPDATE_PUBLIC_KEYS` 覆盖）。
公钥为空时客户端会安全地把更新状态标为不可用，不会降级为未签名下载。
