# 合作者审查流程与清单

适用：2026-09-26 源码验收快照。目标是回答“首次使用是否清楚、改动是否可控、结果是否可复现”，不是继续堆功能。启动请先读根目录 `START_REVIEW.md`。

## 0. 约定和回传（5 分钟）

- 用独立目录和虚构数据；先不配置真实模型、AA 或外部反馈通道。
- 记录包文件名、`REVIEW_MANIFEST.json` 的基线提交、Windows／Python／浏览器版本、显示缩放、窗口宽度。
- 第一遍不要读操作答案，先用 5 分钟自己找“新建作品、修改人物卡、修改世界观卡、查看任务、帮助”。记下入口找了多久、哪一句文案误导了你；随后按清单复验。
- 每项记录：**通过 / 失败 / 阻塞 / 未测**，以及证据和问题编号。没有配置真实模型或 AA 的项目记“阻塞”，不能算通过。
- 建议 60–90 分钟完成基础流程；真实模型与 AA 另开专项，不挤进这个时间预期。

## 2. 资料卡编辑与智能协作（15–20 分钟）

| 编号 | 操作 | 通过标准 | 结果／证据 |
|---|---|---|---|
| B01 | 在样例中找“白露”的人物卡，修改知情边界并保存，刷新再打开 | 找得到编辑入口；保存状态清楚；只改目标卡，修改保留 | |
| B02 | 找“档案室”世界观卡，改定义；试取消编辑 | 明白人物卡与世界卡区别；取消不冒充保存；刷新无取消内容 | |
| B03 | 人物卡留未保存草稿，带草稿去讨论；返回编辑 | 助手看到目标卡与允许字段；草稿非正式资料；返回不丢草稿 | |
| B04 | 选择“说话方式”等有限字段，请助手讨论 | 讨论与正式保存分离；不自动改名称、来源、确认状态、其他字段 | |
| B05 | 如生成了候选，展开字段差异、部分采纳，再刷新 | 能看改前改后；只有明确选中的允许字段变成正式资料；拒绝的不变 | |

模拟助手不保证为任意说法生成可采纳候选。B05/B06 没有实际候选时应记“阻塞（模拟候选不足）”，不要拿普通聊天回复代替 Proposal 验收。真实模型要另验字段忠实度、拒绝／超时／重试和成本告知，且使用自备密钥。

## 3. 已保存设定的修改影响（10–15 分钟）

请在改动样例前先看一次初始状态；若 B01 改了数据，状态可合理变化。重置需要停止服务后保留旧目录，再启动新数据，不能破坏他人的现场。

| 编号 | 操作 | 通过标准 | 结果／证据 |
|---|---|---|---|
| C01 | 白露／档案室卡 → 修改影响预览 | 能定位“夜访档案室”，列出已保存资料变化；只是查看，不改正文或发起模型调用 | |
| C02 | 比较样例三个场景 | 初始“夜访档案室”需复查；仅标题提到档案室但实际未选用的场景不被误判关联；“尚未检查的便条”是未检查 | |
| C03 | 从列表打开场景 → 资料变更检查 → 重新检查本场 | 打开正确场景；需明确操作才复查；完成后更新基准；正文保持原样 | |
| C04 | 卡片或正文留未保存改动后尝试跳转／复查 | 不把未保存草稿当正式资料；提示先处理草稿，不静默丢失 | |

“未变化”只表示与上次有效检查输入相比没有本报告范围的变化；**不等于语义无矛盾、文稿可发布或模型审查通过**。证据文件、时间线、全部事实等不在本次字段比较覆盖内。

## 6. 结论与问题分级

- **P0**：真实数据丢失、密钥泄露、越权外发、破坏他人文件。立即停止该流程，保留现场；禁止公开上传敏感附件。
- **P1**：干净环境无法启动、核心保存／恢复失败、正常操作不可继续、候选写入错误对象。阻止宣布可发布。
- **P2**：有绕行的功能缺陷、状态误导、明显易用性障碍。记录是否影响本次验收结论。
- **P3**：局部文案、间距、非阻断视觉问题、可选建议。不要和失败混写。

回传结论选一项：
- [ ] 可继续内测：基础路径可用，关键未测项已明确；不是正式发布批准。
- [ ] 有条件通过：列出需要修复的问题编号和必须补测的专项。
- [ ] 不通过：列出阻断问题及最短复现。

请同时写：最困惑的三个入口／一个应简化的流程／一个真正有帮助的智能功能。每项尽量给观察和操作证据，而不是只写“感觉不好用”。
