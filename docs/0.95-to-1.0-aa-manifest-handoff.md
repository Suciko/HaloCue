# 0.95 -> 1.0 AA 人物目录迁移记录

## 本轮解决的问题

0.95 的发布种子曾把开发机 `source='custom'` 的人物注册元数据带入公开包；同时，运行时人物列表主要依赖打包数据库，未把用户当前 AA `data/overrides/manifest.json` 作为“本机实际可用人物”的事实源。这会造成两个用户可见问题：别人的电脑能看到开发者私有人物名称，以及数据库名称与用户 AA 的繁中/简中译名或人物标识不同步。

## 0.95 已实施改动

1. `build_desktop_release.py` 在生成公开种子时查找全部 `character.source='custom'` 身份，并从主库、只读 overlay、所有带 `ident` 的关联表及 `aa_resources.json.characters` 中移除。`asset_install`、`asset_library_profile` 和 `name_alias` 仍按原发布边界清空。
2. 新增 `aa_manifest_catalog.py`，只读加载当前用户 `data/overrides/manifest.json`。不修改 manifest，不重命名人物目录，不改 `Identifier` 或 `SpinePortraitPath`。
3. manifest 中重复 `Identifier` 按最后一条作为有效绑定，这与当前 AA 文件及数据库中四组重复资源的实际结果一致。
4. 身份对齐优先级固定为：精确 `Identifier` -> 唯一骨骼资源 basename（例如 `CH0285_spr`）-> 不匹配时作为本机 manifest 新人物保留。名称本身不作为身份主键。
5. 普通繁简字形通过 OpenCC `t2s` 生成检索键；非字形的地区译名来自 `ba-writing/knowledge/characters` 人物卡中的 `name + aliases`。发布时只携带自动生成的精简 `character_aliases.json`，不携带人物写作卡正文，也不依赖开发机目录。
6. 运行时严格拆分三层：规范人物身份（例如生盐诺亚）、地区译名（诺亚/乃爱）和真实装束资源（普通 `노아`/睡衣 `诺亚（睡衣）`）。普通译名搜索会列出该人物全部可用装束，自动映射优先普通资源；只有剧本明确写出装束 Identifier 时才选择对应装束。
7. 人物搜索、自动演员匹配和每次生成的资源快照都接入上述人物组。骨骼匹配到既有数据库人物时，会把已有 face/语义能力复制到用户真实的 manifest Identifier；完全未知人物可选择和编译，但不会凭空生成不存在的表情白名单。
8. 最终演员映射的 `name` 使用简中常用短名，因此 AA 成片对白框显示“诺亚”而非“乃爱”；资源 `id`、骨骼路径和用户 manifest 原文均保持不变。译名规范化只作用于 HaloCue 生成结果，不回写用户的全局 AA 配置。
9. `HaloCue.spec` 和冻结程序自检同时收集、检查 OpenCC 配置/字典与 `character_aliases.json`，保证打包后的 EXE 与源码运行使用相同的检索和显示名行为。
10. 运行时记录明确区分 `manifest_bound` 与 `user_custom`：前者只说明当前 AA 已安装，后者只在资源无法对齐已知 Identifier/唯一骨骼键，或本地来源明确为 `custom/current_story_custom` 时为真。用户只改 `Name/Nickname` 不会把官方人物误判成自定义；真正新增的人物保留在本机自定义分组，绝不进入公共发布种子。
11. `asset_catalog.sync_manifest_custom_characters()` 会把 `user_custom=true` 且骨骼文件有效的 manifest 人物同步到用户可写数据库。记录使用 `catalog_source=aa_manifest_custom`、`manifest_only=true` 和独立的 `.halocue-manifest-library` scope；它只引用用户当前 AA 资源，不复制资源、不创建章节副本、不修改 manifest。
12. 素材库对 `manifest_only` 人物隐藏“复制到当前剧情”和副本管理，只开放现有表情标注工作台。AI 结果继续写入用户库的 `face_visual_label/face_evidence`；公开种子构建会清空 `asset_install`，因此本机资源身份和标注不会进入发布包。manifest 删除资源或资源后来能与正式数据库对齐时，仅删除本机映射行，不删除独立保存的表情标注。

## 1.0 同步要求

1. 复用 `AAManifestCharacter` 的字段边界：`identifier` 是 AA 绑定键，`display_name` 是用户当前显示名，`spine_key` 是资源核对键；另保留 `canonical_name`、地区 aliases 和 `preferred_name`，不得再把显示名、人物身份与装束 Identifier 合并成一个字段。
2. 1.0 的 `resource_catalog.characters.aliases_json` 应导入 manifest 对齐产生的别名；不要只导入旧 `name_alias`。导入必须保持来源为本机目录，不能回写 0.95 数据库，也不能进入公开种子。
3. 1.0 搜索仍应使用“规范化名称匹配”，但资源选择和成片编译必须回到原始 manifest `Identifier`。简中常用名只写入生成项目的演员显示名，禁止覆盖 AA 路径字段或用户全局 manifest。
4. 1.0 若需要“修正 AA 配置”，只能提供显式、可预览、可回滚的迁移工具，同时成对重命名 manifest 与真实文件目录；默认运行不得改用户 AA 文件。
5. 1.0 发布构建继续执行 `source='custom'` 跨表清理，并增加包内数据库、资源索引和绝对路径扫描。运行时从用户 manifest 读取的记录不得写回发布资源目录。
6. 1.0 人物列表可直接使用 `manifest_bound/user_custom` 分组；不要以“出现在 manifest”或“名称与数据库不同”作为自定义判据。
7. 1.0 素材库应保留 `manifest_only` 的行为边界：这是当前 AA 已安装的本机资源，不是历史章节副本。允许在用户库中 AI 打标，但禁止默认上传、进入公共种子或显示跨章节复制操作。

## 回归测试清单

- 搜索 `诺亚` 或 `乃爱` 同时列出普通 `노아` 和 `诺亚（睡衣）`。
- 自动识别 `乃爱` 默认选择普通 `노아`；明确输入 `诺亚（睡衣）` 才选择睡衣 Identifier。
- 两种资源在成片对白框中的显示名均为 `诺亚`，读取前后用户 manifest 字节完全不变。
- `愛麗絲 / 爱丽丝` 能搜索到官方普通人物，不能只返回冬装。
- manifest Identifier 与数据库不同但骨骼 basename 相同，沿用数据库 face 能力并输出 manifest Identifier。
- manifest 新人物在数据库不存在时仍可选，但 face 列表为空。
- 用户修改显示名后，仍可按 Identifier 或骨骼键识别，且 `user_custom=false`。
- 真正无法对齐的 manifest 新人物标记 `user_custom=true`，不污染公共数据库。
- 未知且骨骼文件有效的 manifest 人物进入素材库，初始 `labeled_count=0`，可启动现有 AI 表情标注；结果只写用户本地数据库。
- manifest 移除未知人物后，本机素材映射自动清理；历史表情标注不被连带删除。
- 读取前后 manifest 字节完全不变。
- 公开发布种子的主库、overlay 和 `aa_resources.json` 都不存在开发机 `source='custom'` 人物。
