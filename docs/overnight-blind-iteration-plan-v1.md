# 0.9x 十小时盲测迭代方案

## 目标

从新的共享轮次 `V4` 开始，验证“积极导演扫描”提示词是否让 AI 更好地理解：

`上文刺激 -> 承受者 -> 可见反应 -> 表演承载 -> 镜头时机 -> 下一节点继承`

本轮不是追求字段数量，而是检查有因果价值的表演是否被看见，并确认三个不同场景都没有明显退化。

## 固定运行身份

- 模型：`gpt-5.6-sol`
- 模式：`balanced`
- 三个场景同一轮使用同一个版本号：`V4`、`V5`、`V6`……
- 每个场景独立目录、`source_id`、checkpoint fingerprint 和审计文件
- fingerprint 必须包含：运行模式、模型身份、source_id、当前运行时文件 SHA256
- 新提示词已经改变，禁止复用 `terra-shared-v3` 的 checkpoint、请求或响应
- 不设置字符预算，不覆盖模型最大输出 token

建议根目录：

`output/sol-shared-v4-proactive-blind-balanced/`

子目录固定为：

- `main-p03/`
- `seia/`
- `main-3-1-7/`

## 每轮顺序

一轮必须完整处理三个场景，但只运行一个模型请求进程。不要使用并行 worker 抢占网络、缓存或响应文件。

1. `main-p03`：生成 G1，保存原始响应；生成 G2，编译 AAP。
2. `seia`：生成 G1，保存原始响应；生成 G2，编译 AAP。
3. `main-3-1-7`：生成 G1，保存原始响应；生成 G2，编译 AAP。
4. 三段都完成后，再统一做官方事后对照和轮次判断。

每个 Agent chunk 必须保留：

`原始 AI JSON -> compact 展开 -> validate -> 后端策略 -> 最终 AAP trace -> .model-audit.json`

模型请求只能看到盲测台词、演员表、当前状态、资源白名单和本轮提示词。以下内容不得进入任何生成请求：

- 官方命令流、官方解析、人工标注；
- 旧 AAP、旧模型响应、上一轮完整演出结果；
- 官方事后差异报告中的具体节点答案。

官方资料和差异报告只能在 AAP 编译完成后用于评估和归纳提示词问题。

## 积极导演检查

G1 和 G2 都必须主动扫描六类机会：

1. 注意对象改变；
2. 预期被打破或新信息落地；
3. 回答前的犹豫、迟疑或压住情绪；
4. 可见身体意图；
5. 关系压力或距离改变；
6. 结果落地后的情绪余波。

有因果价值时默认让变化可读，优先在对白节点选择最自然的 `face / emo / act / fx / camera / sound`。
只有反应或结果必须在下一句前被单独看见时，才拆无对白 beat。普通信息交换没有阶段变化时可以保持。

演出推断可以积极揭示潜台词，但剧情事实必须严格。不得凭空添加物件操作、入场、退场、事件结果、关系事实或时间流逝。

## 失败处理

- 网络失败：只重试失败的 request；保留所有 `attempt-N.raw.json` 和原始响应，不覆盖。
- G1/G2 协议失败：保存失败原始响应，重新生成同一 request 的新 attempt；不要重跑已经成功的独立场景。
- AI 原始 JSON 已经正确、compact 或 validate 丢失：修协议/校验，标记为后端修复，不称为模型提升。
- AI 原始 JSON 缺少因果或表演判断：只修改提示词/规划器，下一共享轮次重新生成，标记为 AI 新生成。
- G2 repair 只替换 AI 明确返回的字段；省略字段保持旧值，明确空值才清除。不要用 repair 整行覆盖旧镜头、站位、reveal 或连续性。
- 不因为内部质量分上升就保留版本。所有旧版本和失败版本继续封存。

## 每轮质量闸门

先过硬约束，再看演出质量：

- 编译成功；
- 单镜最多三名有立绘角色；
- 有对白节点没有额外 Wait；
- 资源、角色、装束合法；
- `move/reveal/enter/exit` 的跨节点状态连续；
- `camera / positions / reveal / enter / exit / face / emo / act / reactions` 没有无理由丢失；
- model-audit 能解释每个字段的落地或丢弃原因。

通过硬闸门后，逐段与官方对照四个维度：

1. 内容因果：谁受刺激、谁承受结果、反应是否接得上上文；
2. 表演因果：face 阶段是否变化，emo/act 是否在需要时出现，是否有有效无对白反应；
3. 镜头因果：关系组、单人反打、峰值特写、硬切和回切是否服务当前拍点；
4. 连续性：站位、入退场、背景、特写释放和跨 chunk 状态是否自然。

不要把 `emo`、`act` 或静默节点数量最大化作为目标；只判断是否在正确的因果位置出现了正确的承载。

## 轮次保留规则

- 三段都无明显退化，且至少一段出现可解释的官方差异缩小：允许保留下一轮提示词候选。
- 一段改善、另一段退化：保留该轮完整产物，但不把改动合入下一轮；先定位是否主线/圣亚过拟合。
- 三段都只是编译字段变多、内容因果没有改善：撤回该提示词候选，检查是否变成了合规驱动。
- 任一段出现真实字段丢失、人物瞬移、错误入退场或对白 Wait：优先修后端/协议，不继续增加审美规则。
- 连续两轮三段均无明显退化且官方差异稳定缩小：停止继续改提示词，生成最终人工审查包。

## 十小时节奏

不要用“每十分钟改一次提示词”的盲目循环。每轮只允许修改一个问题簇：

- 第一轮：验证积极导演扫描是否解除 `emo=0 / act=0` 和情绪阶段停滞；
- 第二轮：若需要，只修听者反应、静默拍和操作反馈；
- 第三轮：若需要，只修站位交换、关系镜头和硬切连续性；
- 后续轮次：只处理三段共同出现的退化，不针对单一场景做专属规则。

每轮结束写入：

- `ROUND-MANIFEST.json`
- `RUN-STATUS.json`
- 三个场景的 `*.model-audit.json`
- 三个场景的官方事后差异报告
- 当前轮次的决策记录：保留、拒绝或待人工复核

十小时结束时，无论是否达到停止条件，都必须保留最后一个完整可编译轮次，并输出：

- 最佳共享版本号；
- 每段 AAP 路径；
- 每段 model-audit 路径；
- 每段相对上一轮和官方的差异；
- 失败 request 及全部 attempt；
- 仍需人工审查的问题；
- 明确说明哪些变化来自 AI 新生成、哪些只是后端修复。

## 可直接交给挂机 Agent 的执行指令

你负责 0.9x AA 演出后端的十小时连续盲测迭代。使用 `gpt-5.6-sol`、`balanced`，从共享轮次 `V4` 开始。三段 `main-p03`、`seia`、`main-3-1-7` 每轮必须使用同一个版本号，但按串行顺序执行，不要并行。新提示词已改变，不能复用旧 checkpoint。每轮先生成三段，再做官方事后对照；模型请求绝不能读取官方答案、旧 AAP、人工标注、官方解析或旧模型结果。失败只重试失败 request，保留所有 attempt。原始 AI JSON、compact、validate、策略应用、AAP trace 和 model-audit 必须全部保存。每轮发现问题后只修改一个共同问题簇，下一轮重新生成三段；不要因为单独改善圣娅而合并规则。没有真实 AAP、审计和差异报告不要声称完成；十小时结束时保留最佳完整轮次并生成汇总报告。
